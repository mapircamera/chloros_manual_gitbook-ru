# Настройки проекта

Боковая панель «Настройки проекта» <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line">

в Chloros позволяет настроить все аспекты обработки изображений, обнаружения калибровочных мишеней, расчёта мультиспектральных индексов и параметров экспорта для вашего проекта. Эти настройки сохраняются вместе с проектом и могут быть сохранены в виде шаблонов для повторного использования в других проектах.

2. Нажмите на вкладку **«Настройки проекта»** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line">

3. На панели настроек отобразятся все доступные параметры конфигурации, сгруппированные по категориям

## Отображение

### Разрешение миниатюр изображений

* **Тип**: выпадающий список
* **Варианты**: `Default (512 px)`, `1024 px`, `2048 px`, `Full resolution`
* **По умолчанию**: По умолчанию (512 пикселей)
* **Описание**: Разрешение (по самой длинной стороне, в пикселях), с которым отображаются миниатюры в сетке изображений. Более высокие значения обеспечивают более четкое изображение при увеличении, но загружаются медленнее и занимают больше памяти. Полное разрешение соответствует исходному размеру изображения.
* **Примечание**: Только для отображения — это никогда не влияет на обработку или экспортируемые файлы.

## Обнаружение мишеней

Эти настройки определяют, как Chloros обнаруживает и обрабатывает калибровочные мишени на ваших изображениях. Обе настройки активны только при включенной функции **Калибровка отражательной способности / баланс белого** (в противном случае они затенены, так как обнаружение мишеней полностью пропускается).

### Минимальная площадь калибровочной области (px)

* **Тип**: Число
* **Диапазон**: от 0 до 10 000 пикселей
* **По умолчанию**: 25 пикселей
* **Описание**: Устанавливает минимальную площадь (в пикселях), необходимую для того, чтобы обнаруженная область считалась действительным образцом калибровочной мишени. Меньшие значения позволяют обнаруживать более мелкие мишени, но могут увеличить количество ложных срабатываний. Более крупные значения требуют более крупных и чётких областей мишеней для обнаружения.
* **Когда настраивать**:
  * Увеличьте значение, если возникают ложные срабатывания на мелких артефактах изображения
  * Уменьшите значение, если калибровочные мишени на изображениях выглядят слишком маленькими и не обнаруживаются

### Минимальная степень кластеризации мишеней (0–100)

* **Тип**: Число
* **Диапазон**: от 0 до 100
* **По умолчанию**: 60
* **Описание**: Регулирует порог кластеризации для группировки областей схожего цвета при обнаружении калибровочных целей. Более высокие значения требуют объединения в одну группу большего количества схожих цветов, что приводит к более консервативному обнаружению целей. Более низкие значения допускают большее разнообразие цветов внутри группы целей.
* **Когда следует настраивать**:
  * Увеличьте значение, если калибровочные мишени разбиваются на несколько отдельных объектов обнаружения
  * Уменьшите значение, если калибровочные мишени с цветовыми вариациями не обнаруживаются полностью

## Обработка

Эти настройки определяют, как программа Chloros обрабатывает и калибрует ваши изображения.

### Коррекция виньетирования

* **Тип**: Флажок
* **По умолчанию**: Включено (отмечено)
* **Описание**: Применяет коррекцию виньетирования для компенсации затемнения по краям изображений, вызванного характеристиками объектива. Виньетирование — распространённое оптическое явление, при котором углы и края изображения выглядят темнее, чем центр, из-за характеристик объектива.
* **Побочный эффект**: этот переключатель также определяет, какой *некалиброванный резервный продукт* будет записан в результате прогона (см. ниже).

### Калибровка отражательной способности / баланс белого

* **Тип**: Флажок
* **По умолчанию**: Включено (отмечено)
* **Описание**: Включает калибровку отражательной способности — на основе обнаруженных в кадре калибровочных мишеней и/или данных о нисходящем излучении, полученных с помощью светового датчика системы сбора данных (DAQ), в зависимости от камеры и доступных данных. Это нормализует значения отражательной способности во всём наборе данных и обеспечивает стабильность измерений независимо от условий освещения.
* **При отключении**: Обнаружение мишеней полностью пропускается, и**ни одна камера не может сгенерировать продукт отражательной способности** — как в режиме Survey3, основанном на мишенях, так и в режиме LATTICE, основанном на данных DAQ. Зависимые настройки (*Экспорт отражательной способности*, *Минимальный интервал повторной калибровки* и пороги обнаружения мишеней) становятся неактивными.

### Резервные продукты при отсутствии калибровки: «Экспорт отклика датчика» / «Экспорт с коррекцией виньетирования»

* **Тип**: два флажка
* **Значения по умолчанию**: оба включены (отмечены)
* **Описание**: если кадр не может быть откалиброван по коэффициенту отражения (не найден калибровочный объект или калибровка по коэффициенту отражения отключена), он записывается в качестве *некалиброванного резервного продукта*. **Для каждой модели камеры** на один прогон приходится ровно один из двух резервных продуктов, выбираемый переключателем *Коррекция виньетирования*:
  * Коррекция виньетирования **включена**→ `Vignette_Corrected_Images/` (регулируется параметром**Экспорт с коррекцией виньетирования**)
  * Коррекция виньетирования **выключена**→ `Sensor_Response_Images/` (регулируется параметром**Экспорт характеристик датчика**)
* Резервный вариант, который не используется, отображается серым цветом. Снятие галочки с используемого варианта полностью предотвращает запись этого файла.

### Результаты экспорта LATTICE

Для проектов, содержащих кадры LATTICE, каждый импортированный кадр LATTICE разветвляется на все включённые **и применимые**результаты за один проход обработки. Распределение контролируется четырьмя флажками (по умолчанию все**включены**):

| Параметр | Папка вывода | Что экспортируется |
| --- | --- | --- |
| **Экспорт с дебайеризацией** | `Debayered_Images/` | Линейное изображение с дебайеризацией: с удаленным темновым смещением из калибровочного набора, затем с демозаикой с учетом краев, без коррекции линейности, плоского поля или разложения — тот же файл, который сохраняется при съемке на уровне с дебайеризацией. Сохраняется в исходной ориентации датчика (записанной в XMP). Применимо к RGB- и мультиспектральным камерам. |
| **Экспорт предварительного просмотра** | `Preview_Images/` | Предварительный просмотр на экране. RGB = баланс белого (источник освещения DAQ, если доступен, в противном случае — «серый мир») + гамма; мультиспектральный = растяжение в ложных цветах. |
| **Экспорт яркости** | `Radiance_Images/` | Спектральная яркость в формате Float32, единица измерения W/m²/sr/nm. Только для мультиспектральных (M3C/M3M) изображений — не применимо к исходным файлам RGB. Всегда записывается в формате 32-битного TIFF независимо от настройки *Формат калиброванного изображения*. |
| **Экспорт коэффициента отражения**| `Reflectance_Calibrated_Images/` | Коэффициент отражения в формате Uint16, масштабированный так, что**32768 = коэффициент отражения 1,0** (помечается как XMP `Chloros:PixelScale`). Только для мультиспектральных данных, записывается, когда соответствующая запись о нисходящем излучении `.daq` (или прошедшая контроль качества цель внутри кадра) охватывает кадр. |

* Основные камеры RGB-режима выдают данные после дебайеризации + предварительный просмотр; значения яркости/отражательной способности для них пропускаются как неприменимые.
* Глубина цвета данных после дебайеризации/предварительного просмотра зависит от настройки *Формат калиброванного изображения*; яркость всегда представляет собой float32.
* Эти четыре переключателя не влияют на обработку данных Survey3.
* Продукты яркости и отражательной способности мультиспектральных камер M3C также могут записывать **маску ограничения** в папку `clamp_masks/`, расположенную рядом с папками продуктов, фиксируя места, где при разложении полос отрицательное значение было ограничено до нуля. См. [Форматы выходных изображений](../output-image-formats.md#clamp-masks).

Те же четыре переключателя существуют в режиме без интерфейса как `chloros-cli process --debayered / --preview / --radiance / --reflectance`. Они заменили старый флаг CLI `--radiometric-output`, который больше не существует.

{% hint style="warning" %}
**Отключение всех применимых продуктов приводит к сбою выполнения.** Начиная с версии 1.2.0, цикл обработки, для которого были запрошены продукты, но который не записал ни одного изображения, сообщает об ошибке, и интерфейс CLI завершается с ненулевым кодом, вместо того чтобы тихо сообщить об успешном завершении. В журнале указывается название продукта, который не удалось записать, и причина. Намеренный запуск, предназначенный только для метаданных (запросов не было) по-прежнему считается успешным.
{% endhint %}

### Источник отражательной способности (настройка проекта, задаётся через CLI)

Проект также хранит информацию о том, какой **эталон отражательной способности** использует продукт LATTICE по отражательной способности. На панели настроек нет специального элемента управления; значение хранится в конфигурации проекта как `Processing → "Target reflectance source"` и задаётся с помощью `chloros-cli process --reflectance-source {auto,target,daq}` (в SDK для параметра `configure()` нет соответствующего ключевого слова):

* **`auto`** (по умолчанию): мишень калибровки в кадре, прошедшая контроль качества (QA), становится абсолютным эталоном; при отсутствии мишени или неудачном прохождении QA используется по умолчанию коэффициент разделения нисходящего излучения DAQ (ρ = πL/E). Мишень, прошедшая контроль качества с флагом (опущенная панель или неисправная полоса), не выбирается автоматически: цепочки «мишень», «мишень+DAQ» и «только DAQ» пробуются в порядке их измеренных оценок на выделенных панелях.
* **`target`**: строгое отражение, определяемое мишенью — без замены данными сбора данных (DAQ).
* **`daq`**: отражение, определяемое данными сбора данных (DAQ); мишени в кадре не используются в качестве эталона.

Сопоставление сохраненного значения производится без учета регистра, и несколько вариантов написания принимаются в качестве синонимов: `target`, `target_image`, `empirical` и `empirical_line` — все означают **цель**; `daq`, `dls`, `light_sensor` и `sensor` — все означают**daq**. Все остальное — включая отсутствующий ключ — преобразуется в**auto**.

Сканирование **измеренных** целей по единицам производится по серийному номеру/QR-коду целевой единицы, например `<serial>.csv`, в трёх местах: в каталоге, указанном с помощью `--target-reflectance-dir` (сохраняется как `Processing → "Target reflectance dir"`), в собственной папке проекта `target_reflectance/`, и по пути, указанному в переменной среды `CHLOROS_TARGET_REFLECTANCE_DIR`. Если для данной единицы измерения не существует измеренного скана, вместо него используется номинальная опубликованная кривая для целевой модели.

### Метод дебайеризации

* **Тип**: Выбор из раскрывающегося списка
* **Параметры**:
  * Стандартный (быстрый, среднее качество)
  * С учётом текстуры (медленный, наивысшее качество) \[Chloros+]
* **По умолчанию**: Стандартный (быстрый, среднее качество)
* **Описание**: Выбор алгоритма демозаики, используемого для преобразования необработанных данных датчика с матрицей Байера в полноцветные изображения. Метод «Стандартный (быстрый, среднее качество)» обеспечивает оптимальный баланс между скоростью обработки и качеством изображения. Метод «С учётом текстуры (медленный, высочайшее качество)» \[Chloros+] использует высококачественный алгоритм демозаики с учетом контуров в сочетании с моделью шумоподавления на основе ИИ/машинного обучения, которая устраняет практически весь шум, возникающий при демозаике. Для работы модели с учетом текстур требуется память графического процессора (VRAM). Мы рекомендуем использовать её, если у вас доступно более 4 ГБ VRAM, для более быстрой обработки.
* **Если строка вообще представляет собой выпадающий список**: выпадающий список с двумя вариантами появляется только тогда, когда**оба** условия выполняются — вы вошли в систему с действующей подпиской на Chloros+, **и** проект не содержит снимков LATTICE. В противном случае строка отображается в виде простого текста `Standard (Fast, Medium Quality)` без возможности выбора.
* **Примечание по LATTICE**: Модели Texture Aware, обученной на данных LATTICE, не существует, и конвейер принудительно применяет стандартную демозаику к кадрам LATTICE независимо от сохраненного значения. Если вы добавляете папку LATTICE в проект, в котором уже был выбран режим Texture Aware, Chloros перезаписывает настройку обратно на «Стандартный», а не оставляет устаревшее значение в `project.json`.

### Минимальный интервал повторной калибровки

* **Тип**: Число
* **Диапазон**: от 0 до 3 600 секунд
* **По умолчанию**: 0 секунд
* **Описание**: Устанавливает минимальный временной интервал (в секундах) между использованием калибровочных мишеней. При значении 0 Chloros будет использовать каждую обнаруженную калибровочную мишень. При установке более высокого значения Chloros будет использовать только те калибровочные мишени, между которыми прошло не менее указанного количества секунд, что сокращает время обработки наборов данных с частым захватом калибровочных мишеней.
* **Когда следует настраивать**:
  * Установите значение 0 для максимальной точности калибровки при изменяющихся условиях освещения
  * Увеличьте значение (например, до 60–300 секунд) для ускорения обработки, если освещение стабильно и имеются частые изображения калибровочных мишеней

### Смещение часового пояса датчика освещенности

* **Тип**: Число
* **Диапазон**: от -12 до +12 часов
* **По умолчанию**: 0 часов
* **Описание**: Указывает смещение часового пояса (в часах от UTC) для временных меток данных датчика освещенности, используемое при сопоставлении журналов датчика освещенности со временем съемки изображений. Более новые записи `.daq` содержат собственную информацию о часовом поясе, поэтому этот параметр в основном необходим для старых журналов, записанных в местном времени.

### Применить поправки PPK

* **Тип**: Флажок
* **По умолчанию**: Отключено (не установлен)
* **Описание**: Включает использование поправки Post-Processed Kinematic (PPK) из регистраторов данных MAPIR, оснащённых GPS (GNSS). При включении Chloros будет использовать любые файлы журналов .daq, содержащие данные о выдержке, в каталоге вашего проекта и применять точные поправки геолокации к вашим изображениям.
* **Требование**: в каталоге проекта должен присутствовать файл журнала .daq с записями о значках экспозиции
* **Когда включать**: рекомендуется всегда включать поправку PPK, если в файле журнала .daq имеются записи обратной связи по экспозиции.

### Контакт экспозиции 1

* **Тип**: Выбор из раскрывающегося списка
* **Видимость**: Видно только, когда включена опция «Применить PPK-коррекции» И имеются данные об экспозиции для контакта 1
* **Параметры**:
  * Названия моделей камер, обнаруженных в проекте
  * «Не использовать» — игнорировать этот контакт экспозиции
* **По умолчанию**: Выбирается автоматически на основе конфигурации проекта
* **Описание**: Назначает конкретную камеру контакту экспозиции 1 для синхронизации времени по методу PPK. Контакт экспозиции регистрирует точное время срабатывания затвора камеры, что имеет решающее значение для точной геолокации по методу PPK.
* **Поведение при автоматическом выборе**:
  * Одна камера + один контакт: камера выбирается автоматически
  * Одна камера + два контакта: контакт 1 автоматически назначается камере
  * Несколько камер: требуется ручной выбор

### Контакт экспозиции 2

* **Тип**: Выбор из раскрывающегося списка
* **Видимость**: Виден только при включенной опции «Применить поправки PPK» И при наличии данных экспозиции для контакта 2
* **Параметры**:
  * Названия моделей камер, обнаруженных в проекте
  * «Не использовать» — игнорировать этот контакт экспозиции
* **По умолчанию**: Выбирается автоматически на основе конфигурации проекта
* **Описание**: Назначает конкретную камеру контакту экспозиции 2 для синхронизации времени по PPK при использовании конфигурации с двумя камерами.
* **Поведение автовыбора**:
  * Одна камера + один контакт: для контакта 2 автоматически устанавливается значение «Не использовать»
  * Одна камера + два контакта: для контакта 2 автоматически устанавливается значение «Не использовать»
  * Несколько камер: требуется ручной выбор
* **Примечание**: Одна и та же камера не может быть одновременно назначена как на контакт 1, так и на контакт 2.

В каждой строке указаны файл, модель датчика и коррекция диффузорного колпачка, фактически применяемая к данному файлу. Над строками находится единый элемент управления, действующий для всего проекта:

* **Параметры**: `Auto` плюс профили поправки на диффузорный колпачок, действительные для типов датчиков, присутствующих в проекте
* **По умолчанию**: Авто

## Выравнивание массива

Этот раздел появляется **только** в том случае, если хотя бы одно изображение в проекте содержит преобразование выравнивания между модулями, которое массивы LATTICE проставляют во время съемки (теги XMP `Chloros:Alignment*`). Здесь показано, сколько изображений содержат теги выравнивания, какая камера является эталонной (метка `REF`), а также приведена таблица количества изображений по камерам.

<!-- SCREENSHOT-NEEDED: Project Settings "Array Alignment" section for an imported LATTICE array capture set, showing the tagged-image count, the per-camera rows with the REF badge, and the three controls (Apply array alignment, Crop to common overlap, Resampling). -->

### Применить выравнивание массива

* **Тип**: Флажок
* **По умолчанию**: Включено (отмечено)
* **Сохраняется как**: `Processing → "Array alignment"`
* **Описание**: Деформирует каждый обработанный продукт (без байера / предварительный просмотр / яркость / отражательная способность / индекс) в общую эталонную геометрию массива с использованием трансформации, зафиксированной при съемке. Отключено = экспорт в исходной геометрии для каждого датчика.

### Обрезать до общего перекрытия

* **Тип**: Флажок (активен только при включенной опции *Применить выравнивание массива*)
* **По умолчанию**: Включено (отмечено)
* **Сохраняется как**: `Processing → "Array alignment crop"`
* **Описание**: Обрезает выровненные экспортируемые данные до области, общей для всех модулей камеры, так что каждая полоса имеет одинаковую площадь. При отключении сохраняется полная область датчика (за пределами исходного изображения — чёрная заливка).

### Передискретизация

* **Тип**: Выпадающий список (активен только при включенной опции *Применить выравнивание массива*)
* **Варианты**: `Bilinear (smooth, default)`, `Nearest (preserve exact values)`, `Cubic (sharpest)`
* **По умолчанию**: Билинейная
* **Сохраняется как**: `Processing → "Array alignment interpolation"`
* **Описание**: Интерполяция, используемая при деформации выравнивания. «Ближайший» сохраняет точные значения источника (без смешивания пикселей) для строгого радиометрического анализа; «Билинейный» лучше всего подходит для картографирования и визуального использования.

Те же три параметра существуют в виде кодов без префикса: `chloros-cli process --array-alignment`, `--array-alignment-crop` и `--array-alignment-interp {bilinear,nearest,cubic}`.

## Индексы

Эти настройки позволяют настраивать мультиспектральные индексы для анализа и визуализации.

### Добавить индекс

* **Тип**: Специальная панель настройки индексов
* **Описание**: Открывает интерактивную панель, на которой можно выбрать и настроить мультиспектральные индексы растительности (NDVI, NDRE, EVI и т. д.) для расчёта при обработке изображений. Можно добавить несколько индексов, каждый со своими настройками визуализации.
* **Доступные индексы**: выпадающий список графического интерфейса содержит**27** предопределенных формул мультиспектральных индексов (полный список, включая названия, которые также поддерживаются опцией CLI/SDK `--indices`).
* **Возможности**:
  * Выбор из предустановленных формул индексов
  * Перетаскивание каналов фильтров вашей камеры в слоты полос формулы
  * Настройка цветовых градиентов визуализации (LUT — таблицы преобразования)
  * Устанавливайте пороговые значения и режимы обрезания
  * Создавайте собственные формулы индексов
* **Примечание**: Индексы не рассчитываются для однополосных монохромных камер LATTICE M3M — многополосные индексы не определены для одной полосы. Это не касается моделей Survey3 и LATTICE M3C.

<!-- SCREENSHOT-NEEDED: Project Settings > Index section with one index added and expanded: the filter dropdown, the formula dropdown open showing preset names, the coloured channel circles above the rendered formula, and the "+ Add LUT" button below it. -->



Каждый добавленный индекс отображает свою формулу в виде математического выражения с цветным кружком для каждого слота полосы: красный = Red, зеленый = Green, синий = Blue, оранжевый = Orange, голубой = Cyan, фиолетовый = NIR, пурпурный = RE. Перетащите кружок из строки над формулой на слот, чтобы привязать его; дважды щелкните привязанный слот, чтобы очистить его. Индекс вычисляется только тогда, когда каждый слот, используемый в формуле, имеет канал.

### Пользовательские формулы (функция Chloros+)

* **Тип**: Массив определений пользовательских формул
* **Доступность**: Требуется вход в систему с действующей подпиской на Chloros+.
* **Описание**: Позволяет создавать и сохранять пользовательские формулы мультиспектральных индексов с использованием математических операций над полосами. Пользовательские формулы сохраняются вместе с настройками вашего проекта и могут использоваться так же, как и встроенные индексы.
* **Как создать**:
  1. На панели настроек индекса откройте калькулятор пользовательских формул
  2. Напишите формулу, используя **символы полос и слотов**, а не названия полос
  3. Сохраните формулу под описательным именем — после этого она появится внизу раскрывающегося списка формул, и вы сможете перетаскивать кружки каналов вашей камеры в соответствующие слоты точно так же, как и в случае со встроенными предустановками
* **Синтаксис формулы**:
  * Слоты полос: `x`, `y`, `z`, `a`, `b`, `c` — шесть позиций, которые можно сопоставить с реальными каналами путем перетаскивания
  * Операторы: `+`, `-`, `*`, `/`, `^` и `()` для группировки
  * Функции: `sqrt()`, `log()`, `ln()`, `abs()`, `sign()`, `log1p()`, `log2()`
* **Почему символы, а не названия групп**: формула, записанная как `(y-x)/(y+x)`, работает на любой камере, поскольку сопоставление методом «перетаскивания» определяет, является ли `y` NIR-диапазоном 850 нм фильтра RGN или NIR-диапазоном 808 нм фильтра OCN. встроенные пресеты хранятся таким же образом — см. [Формулы мультиспектральных индексов](multispectral-index-formulas.md) для точного обозначения всех 27 пресетов.
* **Где они работают**: пользовательские формулы сохраняются вместе с настройками проекта и могут использоваться как в [песочнице индексов/LUT](../image-viewer-gui/index-lut-sandbox.md), так и при обработке. Они**не** поддерживаются списком имен CLI/SDK `--indices`, который расширяет только 22 встроенных названия пресетов.

## Экспорт

Эти настройки определяют формат и качество экспортируемых обработанных изображений.

### Формат откалиброванного изображения

* **Тип**: Выбор из раскрывающегося списка
* **Варианты**:
  * **TIFF (16-бит)** — несжатый 16-битный формат TIFF


  * **TIFF (8-bit)** — несжатый 8-битный формат TIFF


  * **TIFF (32-bit, Percent)** — 32-битный TIFF с плавающей запятой, в котором значения отражательной способности указаны в процентах
  * **PNG (8-bit)** — сжатый 8-битный формат PNG


  * **JPG (8-бит)** — сжатый 8-битный формат JPEG


* **По умолчанию**: TIFF (16-бит); в проекте, состоящем исключительно из 8-битных изображений, отображается TIFF (8-бит) и доступны только 8-битные форматы
* **Описание**: Выбирает формат файла для сохранения обработанных и откалиброванных изображений. Экспортированные файлы помещаются в подпапки, соответствующие каждому формату, внутри папки каждой камеры (`tiff16`, `tiff32`, `png8`, `jpg8`), при этом на каждый продукт приходится одна папка `<Product>_Images/`. Экспортированные файлы сохраняют исходное имя файла — продукт идентифицируется по папке, а не по суффиксу имени файла.
* **Рекомендации по форматам**:
  * **Формат TIFF (16-битный)**: Рекомендуется для научного анализа и профессиональных рабочих процессов. Сохраняет максимальное качество данных без артефактов сжатия. Лучше всего подходит для мультиспектрального анализа и дальнейшей обработки в программном обеспечении ГИС.
  * **Формат TIFF (32-битный, в процентах)**: Лучше всего подходит для рабочих процессов, требующих значений отражательной способности в процентах (0–100%). Обеспечивает максимальную точность радиометрических измерений.
  * **Формат PNG (8-бит)**: Подходит для просмотра в Интернете и общей визуализации. Меньший размер файлов благодаря сжатию без потерь, но с уменьшенным динамическим диапазоном.
  * **JPG (8-битный)**: Наименьший размер файлов, подходит только для предварительного просмотра и отображения в Интернете. Использует сжатие с потерями, которое не подходит для научного анализа.
* **Примечание**: Данные о яркости LATTICE всегда экспортируются в формате 32-битного TIFF с плавающей запятой, независимо от данного параметра.

## Сохранение настроек

Проект Chloros представляет собой **папку**. Все настройки проекта сохраняются в папке `project.json`, расположенной внутри него; информация о подключённом оборудовании сохраняется вместе с ними в файлах `cameras.json` и `sensors.json`, поэтому при повторном открытии проекта также восстанавливается подключение к камерам и датчикам освещённости. При повторном открытии проекта все настройки восстанавливаются в том виде, в каком вы их оставили. Сохраненные проекты также можно управлять в режиме без интерфейса с помощью файла `chloros-cli project` или файла `open_project` из набора SDK.

### Иерархия настроек

Настройки применяются в следующем порядке:

1. **Системные настройки по умолчанию** — встроенные настройки по умолчанию, определённые компанией Chloros

2. **Настройки шаблона** — если при создании проекта загружен шаблон
3. **Настройки сохраненного проекта** — настройки, сохраненные вместе с файлом проекта
4. **Ручные настройки** — любые изменения, внесённые вами в течение текущего сеанса

### Настройки и обработка изображений

Настройки обработки считываются при запуске цикла обработки. Изменение настройки не влияет на результаты, уже сохраненные на диске — для применения новых настроек необходимо запустить обработку заново. Некоторые настройки вообще не влияют на обработку:

* Разрешение миниатюр изображений (только для отображения)
* Сохранить шаблон проекта
* Сохранить папку проекта

### Ключи, хранящиеся в `project.json`, не управляемые на панели настроек

Они находятся в том же дереве `Project Settings` и считываются при обработке, но вы не найдёте для них виджета на боковой панели:

| Путь к ключу | Тип | По умолчанию | Устанавливается |
| --- | --- | --- | --- |
| `Processing → LATTICE input level` | `"auto" \| "raw" \| "debayered" \| "processed"` | `"auto"` | `chloros-cli process --input-level`, SDK `input_level=`. Переопределяет способ интерпретации входных TIFF-файлов LATTICE; `auto` определяет на основе тега XMP каждого файла `Chloros:ProcessingLevel` и количества каналов. Игнорируется для снимков Survey3 `.raw`. Намеренно не является настройкой графического интерфейса — значение «auto» подходит для всех обычных случаев. |

| `Processing → Target reflectance config` | словарь с ключом по серийному номеру камеры | `{}` | Регистрация цели в кадре (режим `fixed_block` / `fixed_strip` / `aruco`) |
| `Processing → DAQ-U log path` | строка пути | `""` | SDK `process_folder(daq_log_path=…)`. Указывает на запись `.daq` или папку с такими записями |
| `Target Detection → Minimum calibration target squares` | число | `4` | Устаревшее значение по умолчанию; без управления и без флага CLI |
| `UI → Grid thumbnail size` | число | `160` | Собственный ползунок масштабирования миниатюр сетки изображений |

Два параметра просмотрщика хранятся **на верхнем уровне в `project.json`**, полностью вне `Project Settings`, поскольку они относятся к состоянию отображения, а не к настройкам обработки:

| Путь к ключу | Тип | По умолчанию | Устанавливается |

## Рекомендации

1. **Начните с настроек по умолчанию**: настройки по умолчанию хорошо подходят для большинства систем камер MAPIR и типичных рабочих процессов.
2. **Создавайте шаблоны**: после оптимизации настроек для конкретного рабочего процесса или камеры сохраните их в виде шаблона, чтобы обеспечить единообразие во всех проектах.
3. **Проводите тестирование перед полномасштабной обработкой**: при экспериментах с новыми настройками сначала протестируйте их на небольшом поднаборе изображений, прежде чем обрабатывать весь набор данных.
4. **Документируйте настройки**: Используйте описательные названия шаблонов, указывающие систему камер, тип обработки и предполагаемое использование (например, «Survey3\_RGB\_NDVI\_Agriculture»).
5. **Выбор формата экспорта**: Выбирайте формат экспорта в зависимости от конечного назначения:
   * Научный анализ → TIFF (16-битный или 32-битный)
   * Обработка в ГИС → TIFF (16-битный)
   * Быстрая визуализация → PNG (8-битный)
   * Публикация в Интернете → JPG (8-битный)
