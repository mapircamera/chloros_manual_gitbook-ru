# Конвейер обработки В версии 1.3.0 программы

Chloros используется 4-потоковый конвейер обработки, который работает по принципу поэтапной сборочной линии. Каждый поток отвечает за отдельный этап рабочего процесса, поэтому одновременно несколько изображений могут находиться на разных этапах обработки.

## Архитектура конвейера

```

Images In → [Thread 1: Detection] → [Thread 2: Calibration] → [Thread 3: Processing] → [Thread 4: Export] → Files Out
```

Каждое изображение поочерёдно проходит через все четыре потока. Благодаря многопоточной обработке в Chloros+ несколько изображений одновременно занимают разные потоки — пока поток 3 обрабатывает одно изображение, поток 1 может заниматься обнаружением следующего, поток 2 — калибровкой ещё одного, а поток 4 — записью готового изображения на диск.

Отчеты о ходе обработки генерируются для каждого потока и передаются через Server-Sent Events (бэкенд публикует их на `/api/events`). В окне отображения текущего прогресса в интерфейсе командной строки (CLI) четыре этапа обозначены как **Обнаружение, Анализ, Обработка, Экспорт**.

***

## Сведения о потоках

### Поток 1: Обнаружение

**Назначение**: Загрузка изображений и обнаружение калибровочных мишеней.

* Считывает файлы изображений с диска — пары Survey3 `.raw`+`.jpg`, снимки LATTICE `.tif`/`.tiff` и `.dng`
* Извлекает метаданные EXIF (GPS, модель камеры, временные метки, экспозиция)
* Обнаруживает калибровочные мишени: геометрические фигуры с метками ArUco для снимков LATTICE и классический панельный детектор для фотографий калибровочных мишеней Survey3
* Результаты: данные изображения + метаданные + результаты обнаружения мишеней

В основном это поток, ограниченный операциями ввода-вывода и загрузкой ЦП.

### Поток 2: Калибровка

**Назначение**: Вычисление параметров калибровки на основе обнаруженных мишеней.

* Вычисляет коэффициенты калибровки отражательной способности по изображениям мишеней
* Вычисляет параметры коррекции виньетирования
* Определяет калибровочные кривые для каждого диапазона
* Результаты: параметры калибровки для каждого изображения

Вычислительный поток, ограниченный ресурсами ЦП. При запуске Survey3 или смешанном запуске поток 3 ожидает его завершения, если включена калибровка отражательной способности, чтобы коэффициенты были готовы до начала обработки любого изображения. При запуске только LATTICE поток 3 работает во время обнаружения: каждый кадр запускается, как только его опорная мишень окончательно определена. Кадр принимает ближайшую по времени цель с любой стороны, поэтому он ожидает, пока не будут отсканированы все кадры камеры, более близкие по времени, чем текущая ближайшая цель. Результаты остаются теми же, только получаются раньше.

### Поток 3: Обработка (GPU)

**Назначение**: применение коррекций и расчёт индексов растительности.**Это наиболее вычислительно-интенсивный поток.*** **Дебайеризация**: преобразование данных RAW в формате Байера в многоканальные изображения
  * Стандартный (быстрый, среднее качество) — по умолчанию, `--debayer standard`
  * С учётом текстур (медленный, высочайшее качество) — только для Chloros+, `--debayer texture-aware`, использует модель шумоподавления на основе ИИ/машинного обучения
  * Снимки LATTICE mono (M3M) являются однополосными: для них этапы демозаики и баланса белого пропускаются (с однострочным сообщением в журнале), в то время как любые изображения M3C/Байера в том же цикле по-прежнему проходят эти этапы
* **Коррекция виньетирования**: применяет коррекцию виньетирования объектива ко всему изображению
* **Калибровка по отражательной способности**: применяет калибровочные коэффициенты для преобразования в значения отражательной способности
* **Расчёт индексов**: вычисляет растительные индексы (NDVI, NDRE, GNDVI и т. д.)
* Результаты: обработанные данные изображения, готовые к экспорту

Этот поток в наибольшей степени выигрывает от ускорения на GPU, и именно его настраивает [Динамическая адаптация вычислений](dynamic-compute-adaptation.md).

### Поток 4: Экспорт

**Назначение**: запись обработанных изображений на диск.

* Записывает выходные файлы в выбранном формате — `TIFF (16-bit)`, `TIFF (8-bit)`, `TIFF (32-bit, Percent)`, `PNG (8-bit)`, `JPG (8-bit)`
* Встраивает метаданные в выходные файлы (GPS, временные метки, параметры обработки) — включая теги обработки `Chloros:*`, которые начиная с версии 1.3.0 записываются в любом режиме обработки, как для Survey3, так и для LATTICE
* Организует выходные данные в папке проекта в формате `<camera>/<format>/<Product>_Images/` — например, `LATT-M3M-L41-F550/tiff16/Reflectance_Calibrated_Images/`. **Экспортированные файлы сохраняют имя исходного файла; папка идентифицирует продукт.**
* Для снимков LATTICE один исходный кадр может разбиваться на несколько продуктов (Debayered, Preview, Radiance, Reflectance, Index), каждый из которых помещается в отдельную папку продукта. Индексные продукты вычисляются на основе продукта отражательной способности, сгенерированного в ходе обработки (если такового нет, то на основе другого продукта, сгенерированного в ходе обработки, например, продукта яркости). Продукты яркости и отражательной способности мультиспектральных камер M3C также могут получать маску ограничения по пикселям в `<format>/clamp_masks/` (см. [Форматы выходных изображений](../output-image-formats.md#clamp-masks))
* Результаты: окончательные файлы на диске

В основном это поток, ограниченный операциями ввода-вывода — использование SSD-накопителя заметно улучшает его производительность.

## «Под капотом»: исполнители

В рамках потока 3 работа с каждым изображением параллелизуется следующим образом:

* **Стратегии использования GPU**(`GPU_SINGLE`, `GPU_PARALLEL`) используют пул**рабочих процессов**, каждый из которых представляет собой отдельный процесс ОС со своим собственным контекстом CUDA. Chloros запускает каждый рабочий процесс, повторно запуская собственную установленную бэкенд-программу — а не через `multiprocessing` Python, запуск рабочих процессов которого не работает внутри упакованного приложения
* **`CPU_PARALLEL`** использует пул потоков (функция Python `ThreadPoolExecutor`) — NumPy и OpenCV освобождают GIL, поэтому потоков достаточно
* Устройства Jetson с общим объёмом ОЗУ 8 ГБ или менее полностью обходят исполнителя и выполняют обработку внутри процесса, последовательно
* Функция Texture Aware на графическом процессоре с объёмом видеопамяти менее 7 ГБ также работает последовательно — модель шумоподавления не может поместиться более одного раза

Chloros не использует никаких сторонних фреймворков для распределённых вычислений (таких как Ray). См. [Динамическая адаптация вычислений](dynamic-compute-adaptation.md) для ознакомления с тем, как выбираются стратегия и количество рабочих процессов.

## Последовательная обработка vs. конвейерная обработка

### Свободный режим (последовательный)

В бесплатной версии Chloros изображения обрабатываются **по одному**, последовательно проходя все четыре этапа:

```

Image 1: [Detect] → [Calibrate] → [Process] → [Export]
                                                         Image 2: [Detect] → [Calibrate] → [Process] → [Export]
```

В графическом интерфейсе в бесплатном режиме отображается упрощённая индикатор выполнения; его последовательные этапы отображаются как **Обнаружение целей**, а затем**Обработка**.

### Режим Chloros+ (конвейерная обработка)

При наличии лицензии Chloros+ все четыре потока работают **одновременно** с разными изображениями:

```

Thread 1: [Image 1] [Image 2] [Image 3] [Image 4] ...
Thread 2:           [Image 1] [Image 2] [Image 3] ...
Thread 3:                     [Image 1] [Image 2] ...
Thread 4:                               [Image 1] ...
```

Индикатор выполнения в графическом интерфейсе пользователя (GUI) отображает четыре этапа; наведите курсор на него, чтобы увидеть ход выполнения по каждому потоку. В командной строке (CLI) те же четыре этапа отображаются в режиме реального времени как **Обнаружение, Анализ, Обработка, Экспорт**.

{% hint style="info" %}
**Одно обозначение, два названия.** CLI называет этап 3 _Обработка_. Лента прогресса бэкенда в премиум-режиме — та, которую отображает индикатор прогресса в графическом интерфейсе — обозначает тот же этап как _Калибровка_. Это один и тот же поток, выполняющий одну и ту же работу (поток 3: дебайеризация, коррекции, индексы).
{% endhint %}

{% hint style="success" %}
**Конвейерная обработка с помощью Chloros+** может быть в 3–5 раз быстрее, чем последовательная обработка, в зависимости от вашего оборудования и размера набора данных. Наибольшее ускорение наблюдается на системах с быстрыми графическими процессорами и SSD-накопителями.
{% endhint %}

## Ход экспорта в потоке 4

Поток экспорта имеет собственное отслеживание хода выполнения, которое можно опрашивать отдельно:**Командная строка (CLI):**

```bash
chloros-cli export-status
```

**SDK:**

```python
status = chloros.get_status()
print(f"Export: {status['export']['percent']}% - Phase: {status['export']['phase']}")
```

Обработка завершается, когда поток 4 достигает 100%.

{% hint style="info" %}
**Запуск, в ходе которого не записываются образы, считается неудачным.**В случае успеха `chloros-cli process` сообщает, сколько образов было записано (`Image products written: N`). Если продукты были запрошены, но**ни один**не был записан — только `project.json` и `calibration_data.json` — CLI выводит `Processing finished but wrote no image products.` и**завершает работу с ненулевым кодом**, указав название папки проекта и обычные причины (входная папка не была распознана как захват — проверьте структуру и `--input-level` — либо все запрошенные продукты были неприменимы к этим камерам). Скрипты могут полагаться на код завершения.
{% endhint %}

## Связь с динамической адаптацией вычислений

[Динамическая адаптация вычислений](dynamic-compute-adaptation.md) в первую очередь влияет на **поток 3 (обработка)**:

* **`GPU_PARALLEL`**: Поток 3 одновременно обрабатывает несколько изображений на GPU с использованием конвейера `fused_gpu`
* **`GPU_SINGLE`**: Поток 3 сериализует доступ к графическому процессору с помощью семафора, в то время как рабочие процессы перекрывают операции ввода-вывода, используя конвейер `fused_gpu` или конвейер `tiled_gpu`, оптимизированный для эффективного использования памяти
* **`CPU_PARALLEL`**: Поток 3 использует обработку на ЦП с многопоточным параллелизмом

Объём памяти GPU, выделённой для потока 3, также увеличивается по мере завершения работы потоков 1 и 2 — см. [Динамическое выделение памяти GPU](dynamic-compute-adaptation.md#dynamic-gpu-memory-allocation).
