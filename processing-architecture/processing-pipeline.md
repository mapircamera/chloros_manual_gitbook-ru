# Конвейер обработки

ChlorosВерсия 1.2.0 использует 4-поточный конвейер обработки, который работает по принципу поэтапной сборочной линии. Каждый поток отвечает за отдельный этап рабочего процесса, поэтому одновременно на разных этапах могут находиться несколько изображений.

## Архитектура конвейера

```

Images In → [Thread 1: Detection] → [Thread 2: Calibration] → [Thread 3: Processing] → [Thread 4: Export] → Files Out
```

Каждое изображение последовательно проходит через все четыре потока. Благодаря многопоточной обработке в Chloros+ несколько изображений одновременно обрабатываются в разных потоках — пока поток 3 обрабатывает одно изображение, поток 1 может заниматься распознаванием следующего, поток 2 — калибровкой ещё одного, а поток 4 — записью готового изображения на диск.

Отчеты о ходе обработки формируются для каждого потока и передаются через Server-Sent Events (бэкенд публикует их на канале `/api/events`). В окне отображения текущего хода обработки в «CLI» четыре этапа обозначены как **Обнаружение, Анализ, Обработка, Экспорт**.***

## Сведения о потоках

### Поток 1: Обнаружение

**Назначение**: Загрузка изображений и обнаружение калибровочных мишеней.

* Считывает файлы изображений с диска — пары Survey3 `.raw`+`.jpg`, снимки LATTICE `.tif`/`.tiff`, а также `.dng`
* Извлекает метаданные EXIF (GPS, модель камеры, временные метки, экспозиция)
* Обнаруживает калибровочные мишени: геометрические фигуры с маркировкой ArUco для снимков LATTICE и классический панельный детектор для фотографий с калибровочными мишенями Survey3
* Результаты: данные изображения + метаданные + результаты обнаружения мишеней

В основном это поток, ограниченный операциями ввода-вывода и загрузкой ЦП.

### Поток 2: Калибровка

**Цель**: вычисление параметров калибровки на основе обнаруженных мишеней.

* Вычисляет коэффициенты калибровки отражательной способности по изображениям мишеней
* Вычисляет параметры коррекции виньетирования
* Определяет калибровочные кривые для каждого диапазона
* Результаты: параметры калибровки для каждого изображения

Вычислительный поток, ограниченный ресурсами ЦП. Поток 3 ожидает его завершения, когда включена калибровка отражательной способности, чтобы коэффициенты были готовы до начала обработки любого изображения.

### Поток 3: Обработка (GPU)

**Назначение**: Применение коррекций и расчёт индексов растительности.**Это наиболее вычислительно-интенсивный поток.*** **Дебайеризация**: преобразование RAW-данных Байера в многоканальные изображения
  * Стандартный (быстрый, среднее качество) — по умолчанию, `--debayer standard`
  * С учётом текстуры (медленный, высочайшее качество) — только для Chloros+, `--debayer texture-aware`, использует модель шумоподавления на основе ИИ/машинного обучения
  * Снимки LATTICE mono (M3M) являются однополосными: для них этапы демозаики и баланса белого пропускаются (с однострочным сообщением в журнале), в то время как любые изображения M3C/Bayer в том же цикле обработки по-прежнему проходят эти этапы
* **Коррекция виньетирования**: применяет коррекцию виньетирования объектива по всему изображению
* **Калибровка отражательной способности**: применяет калибровочные коэффициенты для преобразования в значения отражательной способности
* **Расчет индексов**: вычисляет растительные индексы (NDVI, NDRE, GNDVI, …)
* Результаты: обработанные данные изображения, готовые к экспорту

Этот поток в наибольшей степени выигрывает от ускорения на GPU, и именно его настраивает [Динамическая адаптация вычислений](dynamic-compute-adaptation.md).

### Поток 4: Экспорт

**Назначение**: запись обработанных изображений на диск.

* Запись выходных файлов в выбранном формате — `TIFF (16-bit)`, `TIFF (32-bit, Percent)`, `PNG (8-bit)`, `JPG (8-bit)`
* Встраивает метаданные в выходные файлы (GPS, временные метки, параметры обработки)
* Организует выходные файлы в папке проекта в виде `<camera>/<format>/<Product>_Images/` — например, `LATT-M3M-L41-F550/tiff16/Reflectance_Calibrated_Images/`. **Экспортированные файлы сохраняют имя исходного файла; папка идентифицирует продукт.**
* Для снимков LATTICE один исходный кадр может разбиваться на несколько продуктов (Debayered, Preview, Radiance, Reflectance, Index), каждый из которых находится в своей папке
* Результаты: окончательные файлы на диске

В основном это поток, ограниченный операциями ввода-вывода — использование SSD-накопителя заметно улучшает его производительность.

## «Под капотом»: исполнители

В рамках потока 3 обработка каждого изображения параллелизуется с помощью стандартного `concurrent.futures` из библиотеки «Python»:

* **Стратегии использования GPU**(`GPU_SINGLE`, `GPU_PARALLEL`) используют метод `ProcessPoolExecutor` с методом**spawn** — каждый рабочий процесс представляет собой отдельный процесс со своим собственным контекстом CUDA (`fork` унаследовал бы инициализированное состояние CUDA родительского процесса и повредил бы дочерние процессы)
* **`CPU_PARALLEL`** использует `ThreadPoolExecutor` — NumPy и OpenCV освобождают GIL, поэтому достаточно потоков
* Устройства Jetson с общим объемом ОЗУ 8 ГБ или менее полностью обходят исполнитель и обрабатывают данные внутри процесса последовательно
* Техника Texture Aware на GPU с объемом VRAM менее 7 ГБ также работает последовательно — модель шумоподавления не может поместиться более одного раза

Chlorosне использует никаких сторонних фреймворков для распределенной обработки (таких как Ray). См. [Динамическая адаптация вычислений](dynamic-compute-adaptation.md), чтобы узнать, как выбираются стратегия и количество рабочих процессов.

## Последовательная обработка vs. конвейерная обработка

### Свободный режим (последовательный)

В бесплатной версии Chloros изображения обрабатываются **по одному**, последовательно проходя все четыре этапа:

```

Image 1: [Detect] → [Calibrate] → [Process] → [Export]
                                                         Image 2: [Detect] → [Calibrate] → [Process] → [Export]
```

В графическом интерфейсе в бесплатном режиме отображается упрощённая полоса прогресса; её последовательные этапы обозначаются как **Обнаружение целей**, а затем**Обработка**.

### Режим «Chloros» (конвейерный)

При наличии лицензии «Chloros» все четыре потока работают **одновременно** с разными изображениями:

```

Thread 1: [Image 1] [Image 2] [Image 3] [Image 4] ...
Thread 2:           [Image 1] [Image 2] [Image 3] ...
Thread 3:                     [Image 1] [Image 2] ...
Thread 4:                               [Image 1] ...
```

Индикатор выполнения в графическом интерфейсе показывает четыре этапа; наведите курсор, чтобы увидеть прогресс по каждому потоку. В консоли CLI эти же четыре этапа отображаются в режиме реального времени как **«Обнаружение», «Анализ», «Обработка», «Экспорт»**.

{% hint style="info" %}
**Одна метка, два названия.** В «CLI» третий этап называется _Processing_. В ленте прогресса бэкенда в премиум-режиме — той самой, которую отображает индикатор прогресса в графическом интерфейсе — этот же этап обозначен как _Calibrating_. Это один и тот же поток, выполняющий одну и ту же работу (поток 3: дебайеризация, коррекции, индексы).
{% endhint %}

{% hint style="success" %}
**Потоковая обработка с помощью Chloros+** может быть в 3–5 раз быстрее последовательной обработки, в зависимости от вашего оборудования и размера набора данных. Наибольшее ускорение наблюдается на системах с быстрыми графическими процессорами и SSD-накопителями.
{% endhint %}

## Ход экспорта в потоке 4

Поток экспорта имеет собственное отслеживание хода выполнения, которое можно опрашивать отдельно:**CLI:**

```bash
chloros-cli export-status
```

**SDK:**

```python
status = chloros.get_status()
print(f"Export: {status['export']['percent']}% - Phase: {status['export']['phase']}")
```

Обработка завершается, когда поток 4 достигает 100%.

{% hint style="info" %}
**Запуск, в ходе которого не было записано ни одного изображения, считается неудачным.**В случае успеха `chloros-cli process` сообщает, сколько изображений было записано (`Image products written: N`). Если продукты были запрошены, но**ни один**из них не был записан — только `project.json` и `calibration_data.json` — то «CLI» выводит `Processing finished but wrote no image products.` и**завершает работу с ненулевым кодом**, указав название папки проекта и обычные причины (входная папка не была распознана как захват — проверьте структуру и `--input-level` — или все запрошенные продукты были неприменимы к этим камерам). Скрипты могут полагаться на код завершения.
{% endhint %}

## Связь с динамической адаптацией вычислений

[Динамическая адаптация вычислений](dynamic-compute-adaptation.md) в первую очередь влияет на **поток 3 (обработка)**:

* **`GPU_PARALLEL`**: Поток 3 одновременно обрабатывает несколько изображений на графическом процессоре с использованием конвейера `fused_gpu`
* **`GPU_SINGLE`**: Поток 3 сериализует доступ к графическому процессору с помощью семафора, в то время как рабочие процессы перекрывают операции ввода-вывода, используя конвейер `fused_gpu` или конвейер `tiled_gpu`, оптимизированный для эффективного использования памяти
* **`CPU_PARALLEL`**: Поток 3 использует обработку на CPU с многопоточным параллелизмом

Объём памяти GPU, выделённой для потока 3, также увеличивается по мере завершения работы потоков 1 и 2 — см. [Динамическое выделение памяти GPU](dynamic-compute-adaptation.md#dynamic-gpu-memory-allocation).
