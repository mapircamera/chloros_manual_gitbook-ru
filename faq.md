# Часто задаваемые вопросы

<details>

<summary>Можно ли обрабатывать изображения с камер, не относящихся к бренду MAPIR, с помощью Chloros?</summary>

Нет, Chloros поддерживает обработку только изображений с камер MAPIR — семейств Survey3 и LATTICE. Для получения дополнительной информации ознакомьтесь со списком [поддерживаемых моделей камер](supported-cameras.md). Мы предлагаем обработку изображений с других камер в облачной платформе MAPIR Cloud; полный список см. [здесь](https://mapir.gitbook.io/mapir-cloud/supported-cameras).

</details>

<details>

<summary>Поддерживает ли Chloros камеры LATTICE?</summary>

Да. Chloros версии 1.2.0 полностью поддерживает модули камер LATTICE M3C и M3M: **управление в режиме реального времени**— обнаружение, подключение, предварительный просмотр и захват изображения на вкладке «Камеры» графического интерфейса пользователя, `chloros-cli lattice` или в Python SDK, включая синхронизированные мультикамерные массивы с синхронизацией времени по PTP — а также**полную радиометрическую обработку** полученных изображений (исходные данные → дебайеризация → яркость → отражательная способность → индекс). См. [Поддерживаемые камеры](supported-cameras.md) и [руководство LATTICE](lattice/README.md).

</details>

<details>

<summary>Можно ли откалибровать изображения по коэффициенту отражения без калибровочной мишени?</summary>

**Survey3:** Нет. Без изображения калибровочной мишени, снятого в то же время, когда снимались изображения без мишени, вы не сможете соотнести значения пикселей изображения с известным процентом отражательной способности. Если вы также не включите данные из датчика освещенности MAPIR, спектр окружающего света не будет измерен, и результаты измерения коэффициента отражения будут неточными.**LATTICE:** Да. Отражательная способность может быть соотнесена с интенсивностью излучения, направленного вниз, измеренной датчиком освещенности DAQ вместо панели (ρ = π·L/E). Если в кадре *присутствует* мишень, прошедшая контроль качества (QA), она по умолчанию становится абсолютным эталоном (`--reflectance-source auto`). Единственное исключение: «Коэффициент отражения F988 калибруется с использованием панели отражения в кадре: диапазон лежит за пределами калиброванного диапазона датчика освещенности DAQ, поэтому Chloros применяет ваши последние данные с панели и сохраняет их между наблюдениями панели». См. [Калибровочные мишени](calibration-targets.md).

</details>

<details>

<summary>Нужен ли мне световой датчик DAQ?</summary>

Нет, если речь идет о яркости: экспортируемые LATTICE данные по яркости основаны на заводской радиометрической калибровке каждой камеры и не требуют ни датчика DAQ, ни мишени. Для **коэффициента отражения**вам нужен эталон для окружающего освещения — либо измерение нисходящего излучения датчиком освещенности DAQ, либо калибровочная мишень в кадре. Датчик DAQ позволяет получать откалиброванные значения отражательной способности**без размещения каких-либо панелей в кадре**. Записанные файлы `.daq` автоматически сопоставляются с вашими изображениями по временной метке. См. [Калибровочные мишени](calibration-targets.md) и [Справочник по CLI](reference/cli-reference.md).

</details>

<details>

<summary>Можно ли использовать Chloros с ИИ-помощником (Claude, ChatGPT и т. д.)?</summary>

Да — это руководство и файлы CLI/SDK созданы именно для этого:

* Полный указатель руководства доступен по адресу `https://mapir.gitbook.io/chloros/llms.txt`, чтобы ИИ-помощники могли найти каждую страницу.
* Исходный код Markdown каждой страницы доступен на странице с названием, написанным строчными буквами, в формате URL с добавлением `.md` (например, `https://mapir.gitbook.io/chloros/reference/cli-reference.md`).
* [Справочник по CLI](reference/cli-reference.md) и [справочник по SDK](reference/sdk-reference.md) написаны для использования LLM: точные флаги, значения по умолчанию, семантика выхода и команды, которые можно скопировать и вставить.

См. раздел [AI-помощники](ai-assistants.md), чтобы узнать, как настроить вашего помощника на работу с Chloros.

</details>

<details>

<summary>Куда сохраняются мои обработанные выходные файлы?</summary>

Результаты обработки сохраняются в папке проекта, сгруппированные по камерам, а затем по форматам файлов:

```
<project>/<camera-folder>/<format-folder>/<Product>_Images/
```

* **папка-камеры** — `LATT-<sensor>-<lens>-F<filter>` для LATTICE, `<model>_<filter>` (например, `Survey3N_RGN`) для Survey3
* **папка-формата** — `tiff16`, `tiff8`, `png8`, `jpg8` или `tiff32`
* **папки продуктов** — `Reflectance_Calibrated_Images/`, `Debayered_Images/`, `Preview_Images/`, `Radiance_Images/` (всегда находятся в папке `tiff32`), `<INDEX>_Index_Images/`**Экспортированные файлы сохраняют имя исходного файла — папка идентифицирует продукт, а не суффикс имени файла.**При использовании CLI папка проекта создаётся рядом с входной папкой, если не указан параметр `-o`. Обратите внимание, что выполнение `chloros-cli process`, при котором запрашивались продукты, но ни один из них не был записан, выводит сообщение `Processing finished but wrote no image products.` и**завершается с ненулевым кодом**, что позволяет скриптам обнаружить эту ситуацию. См. [Форматы выходных изображений](output-image-formats.md) и [Справочник по CLI](reference/cli-reference.md).

</details>

<details>

<summary>Можно ли редактировать изображения перед обработкой в Chloros?</summary>

Нет. Chloros предполагает, что входные данные не были изменены. Не изменяйте имена файлов.

</details>

<details>

<summary>Можно ли настроить камеры MAPIR и Survey3 на автоматическую экспозицию и обрабатывать изображения в Chloros?</summary>

Нет. Наборы изображений Survey3 должны иметь фиксированную/заблокированную экспозицию, поэтому нельзя использовать автоматическую выдержку или автоматическое ISO. Все изображения, снятые камерой одной и той же модели, должны иметь одинаковую выдержку и ISO (экспозицию).

Камеры LATTICE не имеют этого ограничения: Chloros регулирует их экспозицию в режиме реального времени (Smart AE), и при каждой съемке фиксируются фактически использованные значения экспозиции и коэффициента усиления, которые учитываются в радиометрическом конвейере.

</details>

<details>

<summary>Может ли Chloros обрабатывать или анализировать ортомозаичные изображения?</summary>

Нет. Поддерживаются только отдельные изображения с камеры MAPIR, а не сшитые изображения, такие как ортомозаичная карта.

</details>

<details>

<summary>Как ускорить этап обнаружения целей в Chloros?</summary>

В таблице файлового браузера предварительный выбор целевых изображений в правой колонке укажет Chloros искать калибровочные цели только на этих изображениях, что значительно ускорит обработку.

</details>

<details>

<summary>Доступен ли Chloros для Linux?</summary>

Да! Chloros 1.2.0 поддерживает Linux amd64 (x86_64) и arm64 (NVIDIA Jetson JetPack 6) через пакеты `.deb`. CLI и Python SDK полностью поддерживаются на Linux, включая управление камерой LATTICE в режиме реального времени и датчиками DAQ. Для Linux нет графического интерфейса пользователя — всё взаимодействие осуществляется через [CLI](CLI.md) или [Python SDK](api-python-sdk.md). Подробности см. в [Linux Обзоре](linux/linux-overview.md).

</details>

<details>

<summary>Можно ли запустить Chloros на NVIDIA Jetson?</summary>

Да! Chloros поддерживает платформы NVIDIA Jetson, включая Jetson Nano, Orin Nano, Orin NX и AGX Orin под управлением JetPack 6. Chloros автоматически определяет модель вашего Jetson и оптимизирует стратегию обработки. См. [Руководство по NVIDIA Jetson](linux/nvidia-jetson-guide.md) для получения инструкций по настройке и развертыванию.

</details>

<details>

<summary>Оптимизируется ли Chloros автоматически под моё оборудование?</summary>

Да! Chloros включает функцию [динамической адаптации вычислений](processing-architecture/dynamic-compute-adaptation.md), которая автоматически определяет ваш ЦП, графический процессор, объем оперативной памяти и (на Jetson) датчики температуры. Затем он выбирает оптимальную стратегию обработки — от `GPU_PARALLEL` на системах с большим объемом памяти до `GPU_SINGLE` на устройствах с ограниченными ресурсами и до `CPU_PARALLEL` на системах без графического процессора NVIDIA. Ручная настройка не требуется.

</details>

<details>

<summary>Что такое 4-потоковый конвейер обработки?</summary>

Chloros использует 4-потоковую конвейерную архитектуру для пользователей Chloros+: Поток 1 (Обнаружение) загружает изображения и обнаруживает калибровочные мишени, поток 2 (Калибровка) вычисляет калибровку коэффициента отражения, поток 3 (Обработка) выполняет ускоренное на графическом процессоре дебейерирование и вычисление индекса, а поток 4 (Экспорт) записывает выходные файлы. Для обеспечения максимальной пропускной способности несколько изображений могут одновременно обрабатываться в разных потоках. Подробности см. в разделе [Конвейер обработки](processing-architecture/processing-pipeline.md).

</details>

<details>

<summary>Как запустить диагностику установки Chloros?</summary>

Используйте команду `selftest` для запуска 7-этапного теста работоспособности: проверка версии, доступности портов, запуска бэкэнда, подключения к API (`/api/test`), системной информации (`/api/system-info` — GPU/CUDA/PyTorch), наличие модели шумоподавителя и готовность CUDA + шумоподавителя:

```bash
chloros-cli selftest
```

Это особенно полезно на системах Linux/Jetson для проверки настроек GPU и CUDA.

</details>
