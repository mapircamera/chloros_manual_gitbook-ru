# Часто задаваемые вопросы

<details>

<summary>Можно ли обрабатывать в программе Chloros изображения с камер, не относящихся к бренду MAPIR?</summary>

Нет, Chloros поддерживает обработку только изображений с камер MAPIR — серий Survey3 и LATTICE. Для получения дополнительной информации ознакомьтесь со списком [поддерживаемых моделей камер](supported-cameras.md). Мы предлагаем обработку изображений с других камер в облачном сервисе MAPIR Cloud; полный список см. [здесь](https://mapir.gitbook.io/mapir-cloud/supported-cameras).

</details>

<details>

<summary>Поддерживает ли Chloros камеры LATTICE?</summary>

Да. Chloros 1.3.0 поддерживает камерные модули LATTICE M3C и M3M на всех этапах: **управление в режиме реального времени**— обнаружение, подключение, предварительный просмотр и съемка через вкладку «Камеры» графического интерфейса пользователя (`chloros-cli lattice`) или SDK-Python, включая синхронизированные массивы из нескольких камер с синхронизацией времени по протоколу PTP — а также**полную радиометрическую обработку** снимков (исходные данные → дебайеризация → яркость → отражательная способность → индекс). См. [Поддерживаемые камеры](supported-cameras.md) и [руководство по LATTICE](lattice/README.md).

</details>

<details>

<summary>Можно ли откалибровать изображения по коэффициенту отражения без калибровочной мишени?</summary>

**Survey3:** Нет. Без изображения калибровочной мишени, снятого примерно в то же время, что и изображения без мишени, вы не сможете соотнести значения пикселей изображения с известным процентом отражательной способности. Если вы также не включите данные журнала датчика освещённости MAPIR, спектр окружающего света не будет измерен, и результаты измерения коэффициента отражения будут неточными.

**LATTICE:** Да. Отражательная способность может быть привязана к интенсивности нисходящего излучения, измеренной датчиком освещенности DAQ, а не к панели (ρ = π·L/E). Если в кадре *присутствует* цель, прошедшая контроль качества (QA), она по умолчанию становится абсолютным эталоном (`--reflectance-source auto`), за исключением случаев, когда она проходит контроль с флагом — тогда цель и цепочки DAQ соревнуются по измеренному баллу. Единственное исключение: «Коэффициент отражения F988 калибруется с использованием панели отражения в кадре: диапазон лежит за пределами калиброванного диапазона датчика освещённости DAQ, поэтому Chloros применяет ваши последние данные с панели и сохраняет их между наблюдениями панели». См. [Мишени для калибровки](calibration-targets.md).

</details>

<details>

<summary>Нужен ли мне световой датчик DAQ?</summary>

Нет, если речь идет о яркости: экспортируемые данные яркости LATTICE основаны на заводской радиометрической калибровке каждой камеры и не требуют ни датчика DAQ, ни мишени. Для **отражательной способности**вам нужен эталон для окружающего освещения — либо измерение нисходящего излучения датчиком освещенности DAQ, либо калибровочная мишень в кадре. Датчик DAQ позволяет получать откалиброванные значения отражательной способности**без размещения каких-либо панелей в кадре**. Записанные файлы `.daq` автоматически сопоставляются с вашими изображениями по временной метке. См. [Калибровочные мишени](calibration-targets.md) и [Справочник по CLI](reference/cli-reference.md).

</details>

<summary>Можно ли использовать Chloros с ИИ-помощником (Claude, ChatGPT и т. д.)?</summary>

* [Справочник по CLI](reference/cli-reference.md) и [Справочник по SDK](reference/sdk-reference.md) написаны с учётом потребностей больших языковых моделей (LLM): точные флаги, значения по умолчанию, семантика завершения работы и команды, готовые к копированию и вставке.

См. раздел [AI-помощники](ai-assistants.md), чтобы узнать, как настроить своего помощника на работу с Chloros.

</details>

<details>

<summary>Куда попадают мои обработанные выходные файлы?</summary>

Результаты обработки сохраняются в папке проекта, сгруппированные по камерам, а затем по форматам файлов:

```
<project>/<camera-folder>/<format-folder>/<Product>_Images/
```

* **папка-камеры** — `LATT-<sensor>-<lens>-F<filter>` для LATTICE, `<model>_<filter>` (например, `Survey3N_RGN`) для Survey3
* **папка-формата** — `tiff16`, `tiff8`, `png8`, `jpg8` или `tiff32`
* **папки продуктов** — `Reflectance_Calibrated_Images/`, `Debayered_Images/`, `Preview_Images/`, `Radiance_Images/` (всегда находятся в папке `tiff32`), `<INDEX>_Index_Images/`
* **`clamp_masks/`** — только для мультиспектральных данных LATTICE: маски на уровне пикселей находятся рядом с папками с продуктами, см. ниже**Экспортированные файлы сохраняют имя исходного файла — папка идентифицирует продукт, а не суффикс имени файла.**При использовании CLI папка проекта создаётся в папке проектов по умолчанию (`Documents/MAPIR/Chloros Projects`, если вы её не изменили), если вы не передадите `-o`; относительное значение `-o` интерпретируется относительно папки, из которой запускается команда. Обратите внимание, что при выполнении команды `chloros-cli process`, которая запрашивала продукты, но не записала ни одного, выводится сообщение `Processing finished but wrote no image products.` и**программа завершается с ненулевым кодом**, что позволяет скриптам обнаружить эту ситуацию. См. [Форматы выходных изображений](output-image-formats.md) и [Справочник по CLI](reference/cli-reference.md).

</details>

<details>

<summary>Что представляют собой папки clamp_masks и файлы *_clampmask.tif?</summary>

Новое в версии 1.3.0. Продукты яркости и отражательной способности, полученные с помощью мультиспектральной камеры LATTICE M3C, проходят размикширование по полосам 3×3, и в тех случаях, когда в какой-либо полосе получается отрицательное значение, Chloros обрезает это значение до нуля. Продукт, содержащий хотя бы один обрезанный пиксель, получает однополосную маску `uint8`, которая отмечает, какие пиксели и полосы были обрезаны (бит 0 = канал R продукта, бит 1 = G, бит 2 = B). Маски сохраняются в папке `clamp_masks/` **рядом** с папками продуктов — например, `tiff16/clamp_masks/Reflectance_Calibrated_Images/<name>_clampmask.tif` — а тег XMP продукта `Chloros:UnmixClampMask` указывает название его маски (или содержит надпись `none`).

Они не являются изображениями сцены: собственный импорт Chloros их пропускает, и, поскольку они никогда не находятся внутри папки продукта, вы можете передать папку продукта в Pix4D или Metashape без изменений. См. [Маски зажимов](output-image-formats.md#clamp-masks).

</details>

<details>

<summary>Почему Chloros выдает сообщение «Папка проекта слишком глубокая для этого компьютера»?</summary>

Это касается только Windows. В Windows по умолчанию отключена поддержка длинных путей, и длина любого пути к файлу не может превышать 260 символов. Продукты Chloros находятся примерно на 130 символов ниже папки проекта, поэтому Chloros отклоняет слишком глубокую папку проекта перед обработкой — вместо того, чтобы запускаться и ничего не записывать, как это могло происходить до версии 1.3.0. В сообщении указывается самая длинная допустимая папка проекта.

Исправить это можно одним из следующих способов:

* Используйте папку проекта с меньшим именем (**Рабочий каталог** в настройках проекта или `-o` / `chloros-cli set-project-folder` для командной строки (CLI)).
* Включите поддержку длинных путей в Windows и перезапустите Chloros. Это обеспечивает параметр **«Включить длинные пути Windows»** в установщике Chloros (отмечен по умолчанию); запустите установщик заново, если вы сняли эту отметку.

См. раздел [Запуск обработки](processing-images-gui/starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer).

</details>

Нет. Chloros предполагает, что входные данные не были изменены. Не изменяйте имена файлов.

<details>

<summary>Можно ли настроить камеры MAPIRSurvey3 на автоматическую экспозицию и обрабатывать изображения в Chloros?</summary>

Нет. Наборы изображений Survey3 должны иметь фиксированную/заблокированную экспозицию, поэтому нельзя использовать автоматическую выдержку или автоматическое ISO. Все изображения, снятые камерой одной и той же модели, должны иметь одинаковую выдержку и ISO (экспозицию).

Камеры LATTICE не имеют этого ограничения: Chloros управляет их экспозицией в режиме реального времени (Smart AE), и при каждой съемке фиксируются фактически использованные значения экспозиции и коэффициента усиления, которые учитываются в радиометрическом конвейере.

</details>

<details>

<summary>Может ли Chloros обрабатывать или анализировать ортомозаичные изображения?</summary>

Нет. Поддерживаются только отдельные изображения с камерMAPIR, а не сшитые изображения, такие как ортомозаичная карта.

</details>

<summary>Доступен ли Chloros для Linux?</summary>

Да! Chloros 1.3.0 поддерживает Linux amd64 (x86_64) и arm64 (NVIDIA Jetson JetPack 6) через пакеты `.deb`. CLI и Python SDK полностью поддерживаются в Linux, включая управление камерой LATTICE и датчиками сбора данных (DAQ) в режиме реального времени. Графического интерфейса пользователя (GUI) для Linux нет — все взаимодействие осуществляется через [CLI](CLI.md) или [Python SDK](api-python-sdk.md). Подробности см. в [Обзоре Linux](linux/linux-overview.md).

</details>

<details>

<summary>Можно ли запустить Chloros на NVIDIA Jetson?</summary>

Да! Chloros поддерживает **семейство** NVIDIA Jetson Orin — Orin Nano, Orin NX и AGX Orin — под управлением JetPack 6. Более старые модели (Jetson Nano, TX2, Xavier NX) не могут работать с JetPack 6 и не поддерживаются текущим пакетом. Chloros автоматически определяет модель вашего Jetson и оптимизирует стратегию обработки. Пакет для Jetson использует CUDA-версию PyTorch из JetPack 6, поэтому обработка выполняется на графическом процессоре (GPU) Jetson. Инструкции по настройке и развертыванию см. в [Руководстве по NVIDIA Jetson](linux/nvidia-jetson-guide.md).

</details>

<details>

<summary>Chloros автоматически оптимизируется под моё оборудование?</summary>

Да! Chloros включает функцию [динамической адаптации вычислений](processing-architecture/dynamic-compute-adaptation.md), которая автоматически определяет ваш ЦП, графический процессор, объем оперативной памяти и (на Jetson) датчики температуры. Затем она выбирает оптимальную стратегию обработки — от `GPU_PARALLEL` для графических процессоров с большим объёмом памяти до `GPU_SINGLE` для графических процессоров меньшего размера и до `CPU_PARALLEL` для систем без графического процессора с поддержкой CUDA, который может использовать PyTorch. Ручная настройка не требуется.

</details>

<details>

<summary>Что такое 4-потоковый конвейер обработки?</summary>

Chloros использует 4-поточную конвейерную архитектуру для пользователей Chloros+: Поток 1 (Обнаружение) загружает изображения и обнаруживает калибровочные мишени, поток 2 (Калибровка) вычисляет калибровку коэффициентов отражения, поток 3 (Обработка) выполняет ускоренное на GPU дебайерирование и вычисление индекса, а поток 4 (Экспорт) записывает выходные файлы. Для обеспечения максимальной пропускной способности несколько изображений могут одновременно обрабатываться в разных потоках. Подробности см. в разделе [Конвейер обработки](processing-architecture/processing-pipeline.md).

</details>

<details>

<summary>Как запустить диагностику установки Chloros?</summary>

Используйте команду `selftest` для запуска 7-этапного теста работоспособности: проверка версии, доступности портов, запуска бэкенда, подключения к API (`/api/test`), системной информации (`/api/system-info` — GPU/CUDA/PyTorch), наличие модели шумоподавления и готовность CUDA + шумоподавления:

```bash
chloros-cli selftest
```

Это особенно полезно в системах Linux для проверки настройки GPU и CUDA. На Jetson код ошибки `CUDA: False` обычно означает отсутствие библиотек CUDA и cuDNN для JetPack 6: установите их с помощью команды `sudo apt install nvidia-jetpack`.

</details>
