# Мониторинг обработки

После запуска обработки Chloros предоставляет несколько способов отслеживать ход выполнения, выявлять проблемы и понимать, что происходит с вашим набором данных. На этой странице объясняется, как отслеживать ход обработки и интерпретировать информацию, предоставляемую Chloros.

## Обзор индикатора хода обработки

Индикатор хода обработки в верхнем заголовке отображает статус обработки в режиме реального времени и процент выполнения. Данные о ходе обработки передаются в реальном времени с серверной стороны через Server-Sent Events (SSE), поэтому индикатор отражает то, что на самом деле происходит в конвейере обработки.

### Индикатор хода обработки в бесплатном режиме

Для пользователей без лицензии Chloros+:

**Отображение прогресса в 2 этапа:**

1.**Обнаружение мишеней** — поиск калибровочных мишеней на изображениях
2. **Обработка** — применение корректировок и экспорт**Индикатор прогресса отображает:**

* Общий процент выполнения (0–100 %)
* Название текущего этапа
* Простую горизонтальную полосу

### Индикатор выполнения Chloros+

Для пользователей с лицензией Chloros+:

**4-этапное отображение хода выполнения:**

1.**Обнаружение** — поиск калибровочных мишеней
2. **Анализ** — изучение изображений и подготовка конвейера обработки
3. **Калибровка** — применение корректировок виньетирования и отражательной способности
4. **Экспорт** — сохранение обработанных файлов**Интерактивные функции:*** **Наведите курсор** на индикатор выполнения, чтобы увидеть развернутую панель с 4 этапами
* **Щелкните** по индикатору выполнения, чтобы зафиксировать развернутую панель
* **Щелкните ещё раз**, чтобы отменить фиксацию и включить автоматическое скрытие при уходе курсора
* На каждом этапе отображается индивидуальный прогресс (0–100 %)

{% hint style="info" %}
**CLI четность**: во время выполнения `chloros-cli process` те же четыре потока отображают состояния «Обнаружение», «Анализ», «Обработка» и «Экспорт», а `chloros-cli export-status` показывает текущий ход экспорта потока 4 с другого терминала. См. [Справочник по CLI](../reference/cli-reference.md).
{% endhint %}

## Описание каждого этапа обработки

{% hint style="info" %}
**Архитектура конвейера**: эти 4 этапа графического интерфейса пользователя соответствуют [4-потоковому конвейеру обработки](../processing-architecture/processing-pipeline.md). В системах с ускорением на GPU поток 3 («Калибровка») использует преимущества [динамической адаптации вычислений](../processing-architecture/dynamic-compute-adaptation.md), которая оптимизирует обработку под ваше конкретное оборудование.
{% endhint %}

### Этап 1: Обнаружение (обнаружение целей)

**Что происходит:**

* Chloros сканирует изображения, отмеченные флажком «Цель» (все изображения, если ни одно не отмечено)
* Алгоритмы компьютерного зрения идентифицируют калибровочные панели
* Из каждой панели извлекаются значения коэффициента отражения
* Регистрируются временные метки целей для правильного планирования калибровки

**Продолжительность:**

* С отмеченными целями: 10–60 секунд
* Без отмеченных целей: 5–30+ минут (просканируются все изображения)

**Индикатор выполнения:**

* Обнаружение: 0% → 100%
* Количество отсканированных изображений (учитываются только те изображения, которые действительно сканируются)
* Количество найденных целей

**На что следует обратить внимание:**

* Процесс должен завершиться быстро, если цели отмечены правильно
* Если процесс занимает слишком много времени, возможно, цели не помечены
* Проверьте журнал отладки на наличие сообщений «Цель найдена»

### Этап 2: Анализ

**Что происходит:**

* Чтение метаданных EXIF изображений (временные метки, настройки экспозиции)
* Определение стратегии калибровки на основе временных меток целей и доступных данных DAQ по нисходящему потоку
* Организация очереди обработки изображений
* Подготовка рабочих процессов для параллельной обработки (только Chloros+)

**Продолжительность:** 5–30 секунд**Индикатор прогресса:**

* Анализ: 0% → 100%
* Быстрый этап, обычно завершается быстро

**На что следует обратить внимание:**

* Прогресс должен идти плавно, без пауз
* Предупреждения об отсутствующих метаданных будут появляться в журнале отладки

### Этап 3: Калибровка

**Что происходит:*** **Дебейеринг**: преобразование RAW-матрицы Байера в 3 канала (пропускается для монохромных модулей LATTICE, с соответствующим примечанием)
* **Коррекция виньетирования**: устранение затемнения по краям объектива
* **Калибровка отражательной способности**: нормализация по заданным значениям и/или по данным DAQ
* **Расчёт индексов**: вычисление мультиспектральных индексов
* Обработка каждого изображения по полному конвейеру

**Продолжительность:** большая часть общего времени обработки (60–80 %)**Индикатор прогресса:**

* Калибровка: 0% → 100%
* Текущее обрабатываемое изображение
* Обработанные изображения / Общее количество изображений

**Поведение при обработке:*** **Свободный режим**: последовательная обработка по одному изображению за раз
* **Режим Chloros+**: запускает пул рабочих процессов с адаптацией к аппаратному обеспечению — 1–4 параллельных рабочих процесса на системах с GPU (в зависимости от объёма VRAM), по одному рабочему процессу на каждое физическое ядро (за вычетом одного) на системах, оснащённых только CPU. См. [Динамическая адаптация вычислений](../processing-architecture/dynamic-compute-adaptation.md)
* **Ускорение на GPU**: значительно ускоряет этот этап**На что следует обратить внимание:**

* Стабильное продвижение по количеству изображений
* Проверьте журнал отладки на наличие сообщений о завершении обработки каждого изображения
* Предупреждения о проблемах с качеством изображения или калибровкой

### Этап 4: Экспорт

**Что происходит:**

* Запись обработанных изображений на диск в выбранном формате по мере их завершения
* **LATTICE**: каждый кадр распределяется по всем включённым продуктам (без байеризации / предварительный просмотр / яркость / отражательная способность)
* Экспорт мультиспектральных индексных изображений с цветами LUT
* Создание дерева выходных файлов `<project>/<camera>/<format>/<Product>_Images/` — экспортированные файлы сохраняют имя исходного файла; папка обозначает продукт

**Продолжительность:** 10–20 % от общего времени обработки**Индикатор прогресса:**

* Экспорт: 0 % → 100 %
* Запись файлов
* Формат экспорта и место назначения

**На что следует обратить внимание:**

* Предупреждения о нехватке места на диске
* Ошибки записи файлов
* Завершение всех настроенных выводов

## Вкладка «Журнал отладки»

Журнал отладки содержит подробную информацию о ходе обработки и любых возникших проблемах. Сообщения о запуске бэкэнда также отображаются в консоли журнала, поэтому журнал отражает всю картину событий, даже если вы откроете его позже.

### Доступ к журналу отладки

1. Нажмите значок **Журнал отладки**<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

на левой боковой панели
2. Откроется панель журнала, на которой отображаются сообщения об обработке в режиме реального времени
3. Панель автоматически прокручивается для отображения последних сообщений

<!-- SCREENSHOT-NEEDED: Debug Log tab open at the end of a completed run, showing real backend log lines including the [RUN-SUMMARY] lines (images / camera groups / targets / calibrated / files written) -->

### Понимание сообщений журнала

Строки журнала с кодом Chloros имеют префикс в виде тегов в скобках, обозначающих подсистему — например, `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`. Самым важным для знания является **сводка запуска**, выводимая в конце каждого запуска (включая остановленные запуски):

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

Дополнительные строки с подсказками `[RUN-SUMMARY]` следуют всякий раз, когда что-то требует пояснения — например, в случае запуска, не давшего результатов, или камеры, запрошенный продукт которой был пропущен как неприменимый. Строки `[EXPORT-CHECK]` объясняют пропуски по отдельным камерам (например, почему для камеры RGB не был получен продукт яркости).

Общие уровни серьезности сообщений (приведенные ниже примеры носят иллюстративный характер и не являются дословными):

#### Информационные сообщения (белые/серые)

Обычные обновления о ходе обработки: начало обработки, обнаружены цели (с указанием количества панелей), ход калибровки по каждому изображению, файлы экспортированы, обработка завершена.

#### Предупреждающие сообщения (желтые)

Некритические проблемы, не приводящие к остановке обработки — например, отсутствие данных GPS в кадре, большой разрыв во временных метках между изображениями целей или низкая контрастность калибровочной панели.

**Действие:** Просмотрите предупреждения после завершения обработки, но не прерывайте её

#### Сообщения об ошибках (Red)

Критические проблемы, которые могут привести к сбою обработки — например, диск заполнен, повреждённый файл изображения или отсутствие обнаруженных целей при запросе калибровки отражательной способности.

**Действие:** Остановите обработку, устраните ошибку, перезапустите

### Типичные ситуации в журнале

| Ситуация                             | Значение                                       | Необходимые действия                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| Цель обнаружена в \[имя файла]        | Цель калибровки найдена успешно         | Нет — нормально                                         |
| Строки прогресса по каждому изображению              | Обновление текущего прогресса                       | Нет — нормально                                         |
| Цели не найдены                      | Не обнаружено калибровочных целей               | Пометить изображения целей или отключить калибровку по отражательной способности |
| Недостаточно места на диске               | Недостаточно места для хранения выходных данных                 | Освободить место на диске                                    |
| Пропуск повреждённого файла               | Файл изображения повреждён                         | Перекопировать файл с SD-карты                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | Запись без необработанного кадра не может быть обработана | Повторите съёмку с необработанным кадром или используйте CLI `--input-level`  |
| `[RUN-SUMMARY] ... 0 file(s) written` | В результате выполнения не было создано изображений — зарегистрировано как сбой с подсказками | Прочитайте строки с подсказками; проверьте, что было пропущено и почему |

### Копирование данных журнала

Чтобы скопировать журнал для устранения неполадок или обращения в службу поддержки:

1. Откройте панель «Журнал отладки»
2. Нажмите кнопку **«Копировать журнал»** (или щелкните правой кнопкой мыши → «Выделить всё»)
3. Вставьте в текстовый файл или в электронное письмо
4. При необходимости отправьте в службу поддержки MAPIR

## Мониторинг системных ресурсов

### Использование ЦП

**Свободный режим:**

* 1 ядро ЦП на уровне ~100 %
* Остальные ядра находятся в режиме ожидания или доступны
* Система продолжает реагировать на запросы

**Параллельный режим Chloros+:**

* Несколько ядер с высокой загрузкой — количество зависит от стратегии, выбранной в [Динамической адаптации вычислений](../processing-architecture/dynamic-compute-adaptation.md)
* Система может работать с меньшей отзывчивостью

**Для мониторинга:**

* Windows Диспетчер задач (Ctrl+Shift+Esc)
* Вкладка «Производительность» → раздел «Процессор»
* Найдите процессы «Chloros» или «chloros-backend»

### Использование памяти (RAM)

**Типичное использование:**

* Небольшие проекты (&lt; 100 изображений): 2–4 ГБ
* Средние проекты (100–500 изображений): 4–8 ГБ
* Крупные проекты (500+ изображений): 8–16 ГБ
* Параллельный режим Chloros+ потребляет больше ОЗУ

**Если не хватает памяти:**

* Обрабатывайте меньшие партии
* Закройте другие приложения
* Увеличьте объём ОЗУ, если регулярно обрабатываете большие наборы данных

### Использование графического процессора (Chloros+ с CUDA)

Когда включено ускорение на графическом процессоре:

* Графический процессор NVIDIA демонстрирует высокую загрузку (60–90 %)
* Увеличивается использование видеопамяти (требуется 4 ГБ и более; 7 ГБ и более для одновременного дебайеринга с учетом текстур)
* Этап калибровки проходит значительно быстрее

**Для мониторинга:**

* Значок NVIDIA в системном трее
* Диспетчер задач → Производительность → Графический процессор
* GPU-Z или аналогичный инструмент мониторинга

### Ввод-вывод с диска

**Чего следует ожидать:**

* Высокая интенсивность чтения с диска на этапе анализа
* Высокая интенсивность записи на диск на этапе экспорта
* SSD работает значительно быстрее, чем HDD

**Совет по повышению производительности:**

* По возможности используйте SSD для папки проекта
* Избегайте использования сетевых дисков для больших наборов данных
* Убедитесь, что диск не заполнен почти до предела (это влияет на скорость записи)

## Обнаружение проблем во время обработки

### Предупреждающие признаки

**Процесс останавливается (без изменений в течение 5 и более минут):**

* Проверьте журнал отладки на наличие ошибок
* Проверьте наличие свободного места на диске
* Проверьте в «Диспетчере задач», запущен ли процесс Chloros

**Часто появляются сообщения об ошибках:**

* Остановите обработку и проанализируйте ошибки
* Распространённые причины: нехватка места на диске, повреждённые файлы, проблемы с памятью
* См. раздел «Устранение неполадок» ниже

**Система перестает отвечать:**

* Параллельный режим Chloros+ потребляет слишком много ресурсов
* Рассмотрите возможность уменьшения количества одновременно выполняемых задач или модернизации оборудования
* Свободный режим менее ресурсоемкий

### Когда следует остановить обработку

Остановите обработку, если вы видите:

* ❌ Ошибки «Диск заполнен» или «Не удаётся записать файл»
* ❌ Повторяющиеся ошибки повреждения файлов изображений
* ❌ Система полностью зависла (не отвечает)
* ❌ Вы обнаружили, что были заданы неверные настройки
* ❌ Импортированы неверные образы

**Как остановить:**

1. Нажмите**кнопку «Стоп»** (заменяет кнопку «Старт») — достаточно одного раза
2. На полосе прогресса будет отображаться надпись «Остановка...», пока завершается обработка текущего изображения, после чего цикл завершится в остановленном состоянии
3. Уже экспортированные продукты останутся на диске; в журнале будет записан подробный отчет `[RUN-SUMMARY]` о том, что было выполнено
4. Устраните проблемы и перезапустите — цикл начнётся с самого начала

## Устранение неполадок во время обработки

### Обработка происходит очень медленно

**Возможные причины:**

* Непомеченные целевые изображения (происходит сканирование всех изображений)
* Использование жесткого диска (HDD) вместо твердотельного диска (SSD)
* Недостаток системных ресурсов
* Настроен слишком много индексов
* Доступ к сетевому диску

**Решения:**

1. Если процесс только начался и находится на этапе обнаружения: остановите его, пометьте целевые изображения и перезапустите
2. На будущее: используйте SSD, сократите количество индексов, модернизируйте оборудование
3. Рассмотрите возможность использования CLI для пакетной обработки больших наборов данных

### Предупреждения о «нехватке места на диске»

**Решения:**

1. Немедленно освободите место на диске
2. Переместите проект на диск с большим объёмом свободного места
3. Уменьшите количество индексов для экспорта
4. Отключите экспорт продуктов LATTICE, которые вам не нужны (Настройки проекта → Обработка)
5. Используйте формат JPG вместо TIFF (файлы меньшего размера)

### Частые сообщения «Повреждённый файл»

**Решения:**

1. Снова скопируйте изображения с SD-карты, чтобы убедиться в их целостности
2. Проверьте SD-карту на наличие ошибок
3. Удалите поврежденные файлы из проекта
4. Продолжите обработку оставшихся изображений

### Перегрев системы / снижение производительности

**Решения:**

1. Обеспечьте достаточную вентиляцию
2. Очистите вентиляционные отверстия компьютера от пыли
3. Уменьшите нагрузку при обработке (используйте режим «Free» вместо Chloros+)
4. Выполняйте обработку в более прохладные часы суток

***

## Уведомление о завершении обработки

По завершении обработки:

* Индикатор выполнения достигает 100 %
* В журнале отладки появляются строки `[RUN-SUMMARY]` с итоговыми подсчётами
* Кнопка «Пуск» снова становится активной
* Все выходные файлы находятся в дереве выходных файлов проекта для каждой камеры: `<project>/<camera>/<format>/<Product>_Images/`

## Следующие шаги

После завершения обработки:

1. **Проверьте результаты** — см. раздел [Завершение обработки](finishing-the-processing.md)
2. **Проверьте папку с результатами** — убедитесь, что все файлы экспортированы правильно
3. **Просмотрите журнал отладки** — проверьте, нет ли предупреждений или ошибок
4. **Просмотрите обработанные изображения** — используйте просмотрщик изображений или внешнее программное обеспечение

Информацию о просмотре и использовании обработанных результатов см. в разделе [Завершение обработки](finishing-the-processing.md).
