# Мониторинг обработки

После запуска обработки Chloros предоставляет несколько способов отслеживать ход работы, выявлять проблемы и понимать, что происходит с вашим набором данных. На этой странице объясняется, как отслеживать ход обработки и интерпретировать информацию, предоставляемую Chloros.

## Обзор индикатора выполнения

Индикатор выполнения в верхнем заголовке отображает статус обработки в режиме реального времени и процент выполнения. Данные о ходе обработки передаются в режиме реального времени из бэкэнда через Server-Sent Events (SSE), поэтому индикатор отражает то, что на самом деле делает конвейер обработки.

### Индикатор выполнения в бесплатном режиме

Для пользователей без лицензии Chloros+:

**2-этапное отображение хода выполнения:**

1.**Обнаружение целей** — поиск калибровочных целей на изображениях
2. **Обработка** — применение корректировок и экспорт**Индикатор выполнения показывает:**

* Общий процент выполнения (0–100 %)
* Название текущего этапа
* Простая визуализация в виде горизонтальной полосы

### Индикатор выполнения Chloros+

Для пользователей с лицензией Chloros+:

**4-этапное отображение выполнения:**

1.**Обнаружение** — поиск калибровочных мишеней
2. **Анализ** — изучение изображений и подготовка конвейера
3. **Калибровка** — применение коррекции виньетирования и отражательной способности
4. **Экспорт** — сохранение обработанных файлов

**Интерактивные функции:**

* **Наведите курсор** на индикатор выполнения, чтобы увидеть развернутую панель с 4 этапами
* **Щелкните** по индикатору выполнения, чтобы зафиксировать развернутую панель
* **Щелкните ещё раз**, чтобы разблокировать панель; она автоматически скроется при уходе курсора
* Каждый этап отображает индивидуальный прогресс (0–100 %)

{% hint style="info" %}
**Соответствие CLI**: во время выполнения `chloros-cli process` те же четыре потока отображаются как «Обнаружение», «Анализ», «Обработка» и «Экспорт», а `chloros-cli export-status` показывает в реальном времени ход экспорта потока 4 с другого терминала. См. [Справочник по CLI](../reference/cli-reference.md).
{% endhint %}

## Описание каждого этапа обработки

{% hint style="info" %}
**Архитектура конвейера**: эти 4 этапа графического интерфейса пользователя соответствуют [4-потоковому конвейеру обработки](../processing-architecture/processing-pipeline.md). В системах с ускорением на GPU поток 3 (калибровка) использует преимущества [динамической адаптации вычислений](../processing-architecture/dynamic-compute-adaptation.md), которая оптимизирует обработку под ваше конкретное оборудование.
{% endhint %}

### Этап 1: Обнаружение (обнаружение целей)

**Что происходит:**

* Chloros сканирует изображения, отмеченные флажком «Цель» (все изображения, если ни одно не отмечено)
* Алгоритмы компьютерного зрения идентифицируют калибровочные панели
* Из каждой панели извлекаются значения коэффициента отражения
* Регистрируются временные метки целей для правильного планирования калибровки

**Продолжительность:**

* С отмеченными целями: 10–60 секунд
* Без отмеченных целей: 5–30+ минут (просканируются все изображения)

**Индикатор прогресса:**

* Обнаружение: 0 % → 100 %
* Количество отсканированных изображений (учитываются только те изображения, которые действительно сканируются)
* Количество найденных целей

**На что следует обратить внимание:**

* Процесс должен завершиться быстро, если цели правильно помечены
* Если процесс занимает слишком много времени, цели, возможно, не помечены
* Проверьте журнал отладки на наличие сообщений «Цель найдена»

### Этап 2: Анализ

**Что происходит:**

* Чтение метаданных EXIF изображений (метки времени, настройки экспозиции)
* Определение стратегии калибровки на основе меток времени целей и доступных данных DAQ о нисходящем излучении
* Организация очереди обработки изображений
* Подготовка рабочих процессов для параллельной обработки (только для Chloros+)

**Продолжительность:** 5–30 секунд**Индикатор прогресса:**

* Анализ: 0 % → 100 %
* Быстрый этап, обычно завершается быстро

**На что следует обратить внимание:**

* Процесс должен проходить плавно, без пауз
* Предупреждения об отсутствующих метаданных будут появляться в журнале отладки

### Этап 3: Калибровка

**Что происходит:**

* **Дебейеринг**: преобразование RAW-матрицы Байера в 3 канала (пропускается для монохромных модулей LATTICE с соответствующим примечанием)
* **Коррекция виньетирования**: устранение затемнения по краям объектива
* **Калибровка отражательной способности**: нормализация по заданным значениям и/или по данным DAQ
* **Расчет индексов**: вычисление мультиспектральных индексов
* Обработка каждого изображения по полному конвейеру

**Продолжительность:** Большая часть общего времени обработки (60–80 %)**Индикатор прогресса:**

* Калибровка: 0 % → 100 %
* Текущее изображение обрабатывается
* Обработанные изображения / Общее количество изображений

**Режимы обработки:**

* **Свободный режим**: последовательная обработка по одному изображению за раз
* **Режим Chloros+**: запуск пула рабочих процессов с адаптацией к аппаратному обеспечению — 1–4 параллельных рабочих процесса на системах с GPU (в зависимости от объёма VRAM), по одному рабочему процессу на каждое физическое ядро (за вычетом одного) на системах, оснащённых только CPU. См. [Динамическая адаптация вычислений](../processing-architecture/dynamic-compute-adaptation.md)
* **Ускорение на GPU**: значительно ускоряет этот этап**На что следует обратить внимание:**

* Стабильное увеличение количества обработанных изображений
* Проверьте журнал отладки на наличие сообщений о завершении обработки каждого изображения
* Предупреждения о проблемах с качеством изображений или калибровкой

### Этап 4: Экспорт

**Что происходит:**

* Запись обработанных изображений на диск в выбранном формате по мере их завершения
* **LATTICE**: каждый кадр распределяется по всем включённым продуктам (без байеризации / предварительный просмотр / яркость / отражательная способность)
* Экспорт мультиспектральных индексных изображений с цветами LUT
* Создание дерева выходных файлов `<project>/<camera>/<format>/<Product>_Images/` — экспортированные файлы сохраняют имя исходного файла; папка обозначает продукт

**Продолжительность:** 10–20 % от общего времени обработки**Индикатор прогресса:**

* Экспорт: 0 % → 100 %
* Запись файлов
* Формат экспорта и место назначения

**На что следует обратить внимание:**

* Предупреждения о нехватке места на диске
* Ошибки записи файлов
* Завершение всех настроенных выводов

## Вкладка «Журнал отладки»

Журнал отладки содержит подробную информацию о ходе обработки и любых возникших проблемах. Сообщения о запуске бэкэнда также отображаются в консоли журнала, поэтому журнал отражает всю картину, даже если вы откроете его позже.

### Доступ к журналу отладки

1. Нажмите на значок **Журнал отладки** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

на левой боковой панели
2. Откроется панель журнала, отображающая сообщения об обработке в режиме реального времени
3. Панель автоматически прокручивается, чтобы отобразить последние сообщения

### Понимание сообщений журнала Строки журнала

Chloros начинаются с тегов в скобках, обозначающих подсистему — например, `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`. Наиболее важным для понимания является **сводка запуска**, выводимая в конце каждого запуска (включая остановленные запуски):

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

Дополнительные строки с подсказками `[RUN-SUMMARY]` появляются всякий раз, когда что-то требует пояснения — например, в случае запуска, не давшего результатов, или камера, запрашиваемый продукт которой был пропущен как неприменимый. Строки `[EXPORT-CHECK]` объясняют пропуски по каждой камере (например, почему для камеры RGB не был получен продукт яркости).

Общие уровни серьезности сообщений (приведенные ниже примеры носят иллюстративный характер, а не являются дословными):

#### Информационные сообщения (белый/серый)

Обычные обновления о ходе обработки: начало обработки, обнаружение целей (с указанием количества панелей), ход калибровки по каждому изображению, экспорт файлов, завершение обработки.

#### Предупреждающие сообщения (желтый)

Некритические проблемы, не приводящие к остановке обработки — например, отсутствие данных GPS в кадре, большой разрыв во временных метках между изображениями целей или низкая контрастность калибровочной панели.

**Действие:** Просмотрите предупреждения после завершения обработки, но не прерывайте её

#### Сообщения об ошибках (цвет Red)

Критические проблемы, которые могут привести к сбою обработки — например, диск заполнен, повреждённый файл изображения или отсутствие обнаруженных целей при запросе калибровки коэффициента отражения.

**Действие:** Остановите обработку, устраните ошибку, запустите обработку заново

### Типичные ситуации в журнале

| Ситуация                             | Значение                                       | Необходимые действия                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| Объект обнаружен в \[имя файла]        | Объект калибровки найден успешно         | Нет — нормально                                         |
| Строки прогресса для каждого изображения              | Обновление текущего прогресса                       | Нет — нормально                                         |
| Цели не найдены                      | Не обнаружено калибровочных целей               | Пометить изображения целей или отключить калибровку по отражательной способности |
| Недостаточно места на диске               | Недостаточно места для сохранения результатов                 | Освободить место на диске                                    |
| Пропуск повреждённого файла               | Файл изображения повреждён                         | Перекопируйте файл с SD-карты                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | Невозможно обработать съёмку без необработанного кадра | Повторите съёмку с необработанным кадром, или воспользуйтесь CLI `--input-level`  |
| `[RUN-SUMMARY] ... 0 file(s) written` | В результате выполнения не было создано никаких изображений — сообщение об ошибке с подсказками | Прочитайте строки с подсказками; проверьте, что было пропущено и почему |
| `[PROCESS] refused: The project folder is too deep for this computer…` | В Windows отключены длинные пути, а папка проекта находится слишком глубоко, что превышает ограничение в 260 символов для пути; ничего не было обработано | Используйте папку проекта с меньшим именем (в сообщении указан максимально допустимый длинный путь), либо включите поддержку длинных путей в Windows и перезапустите Chloros — см. [Запуск обработки](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer) |
| `[unmix-clamp-mask] …` | Не удалось записать маску ограничения для продукта LATTICE; сам продукт исправен и выдает сообщение `Chloros:UnmixClampMask=unavailable` | Проверьте свободное место на диске и права доступа к папке, затем повторите обработку, если маска вам нужна |

### Копирование данных журнала

Чтобы скопировать журнал для устранения неполадок или обращения в службу поддержки:

1. Откройте панель «Журнал отладки»
2. Нажмите кнопку **«Копировать»**(скопирует журнал в буфер обмена) или**«Скачать»**, чтобы сохранить его в виде текстового файла
3. Вставьте в текстовый файл или отправьте по электронной почте
4. При необходимости отправьте в службу поддержки MAPIR



### Сообщение об ошибке с вкладки «Журнал отладки»

Новое в версии 1.3.0: значок ошибки (**Сообщить об ошибке**) в верхней части вкладки «Журнал отладки» позволяет отправить отчет напрямую в MAPIR.

1. Нажмите значок ошибки в верхней части вкладки «Журнал отладки»
2. Опишите проблему: что вы делали, чего ожидали и что произошло на самом деле (обязательно)
3. При желании установите флажок **Добавить несколько изображений (до 10)**и выберите изображения из открытого проекта или воспользуйтесь кнопкой**Обзор...** для выбора любого другого файла изображения
4. Нажмите **Отправить**

Отчет включает ваше описание, все прикрепленные изображения, журналы Chloros и сведения о системе (версия Chloros, ОС, графический процессор и настройки проекта). Для отправки отчета необходимо войти в систему Chloros (вкладка «Пользователь»). Во время отправки можно закрыть окно; по завершении в журнал записывается ссылка, например `Bug report sent. Reference: BR-…` — укажите её при обращении в MAPIR. Если отчёт не удаётся загрузить (например, из-за отсутствия подключения к Интернету), Chloros сохраняет его на вашем компьютере и показывает путь к файлу, чтобы вы могли отправить его по электронной почте на адрес support@mapir.camera.

## Мониторинг системных ресурсов

### Использование ЦП

**Свободный режим:**

* 1 ядро процессора загружено на ~100 %
* Остальные ядра находятся в режиме простоя или доступны
* Система продолжает нормально реагировать

**Параллельный режим Chloros+:**

* Несколько ядер с высокой загрузкой — количество зависит от стратегии, выбранной в [Динамической адаптации вычислений](../processing-architecture/dynamic-compute-adaptation.md)
* Система может работать с меньшей отзывчивостью

**Для мониторинга:**

* Диспетчер задач Windows (Ctrl+Shift+Esc)
* Вкладка «Производительность» → раздел «ЦП»
* Найдите процессы «Chloros» или «chloros-backend»

### Использование памяти (RAM)

**Типичное использование:**

* Небольшие проекты (< 100 изображений): 2–4 ГБ
* Средние проекты (100–500 изображений): 4–8 ГБ
* Крупные проекты (500+ изображений): 8–16 ГБ
* Параллельный режим «Chloros+» потребляет больше ОЗУ

**Если памяти недостаточно:**

* Обрабатывайте меньшие партии
* Закройте другие приложения
* Увеличьте объём ОЗУ, если регулярно обрабатываете большие наборы данных

### Использование графического процессора (GPU) (Chloros+ с CUDA)

Когда включено ускорение на GPU:

* Графический процессор NVIDIA демонстрирует высокую загрузку (60–90 %)
* Увеличивается использование VRAM (требуется 4 ГБ и более VRAM; 7 ГБ и более для одновременного дебайеринга с учетом текстур)
* Этап калибровки проходит значительно быстрее

**Для мониторинга:**

* Значок NVIDIA в системном трее
* Диспетчер задач → Производительность → Графический процессор
* GPU-Z или аналогичный инструмент мониторинга

### Ввод-вывод с диска

**Чего следует ожидать:**

* Высокая интенсивность чтения с диска на этапе анализа
* Высокая интенсивность записи на диск на этапе экспорта
* SSD работает значительно быстрее, чем HDD

**Совет по повышению производительности:**

* По возможности используйте SSD для папки проекта
* Избегайте сетевых дисков для больших наборов данных
* Убедитесь, что диск не заполнен почти до предела (это влияет на скорость записи)

## Обнаружение проблем во время обработки

### Предупреждающие признаки

**Процесс останавливается (без изменений в течение 5+ минут):**

* Проверьте журнал отладки на наличие ошибок
* Убедитесь, что на диске достаточно свободного места
* Проверьте в диспетчере задач, работает ли Chloros **Часто появляются сообщения об ошибках:**

* Остановите обработку и проанализируйте ошибки
* Распространённые причины: нехватка места на диске, повреждённые файлы, проблемы с памятью
* См. раздел «Устранение неполадок» ниже

**Система перестает отвечать:**

* Параллельный режим Chloros+ потребляет слишком много ресурсов
* Рассмотрите возможность уменьшения количества одновременно выполняемых задач или модернизации оборудования
* Бесплатный режим менее ресурсоемкий

### Когда следует остановить обработку

Остановите обработку, если вы видите:

* ❌ Ошибки «Диск заполнен» или «Не удаётся записать файл»
* ❌ Повторяющиеся ошибки повреждения файлов образов
* ❌ Система полностью зависла (не отвечает)
* ❌ Вы обнаружили, что были заданы неверные настройки
* ❌ Импортированы неверные образы

**Как остановить:**

1. Нажмите**кнопку «Остановить»** (заменяет кнопку «Пуск») — достаточно одного нажатия
2. На индикаторе будет отображаться надпись «Остановка...», пока завершается обработка текущего образа, после чего процесс завершится в остановленном состоянии
3. Уже экспортированные продукты остаются на диске; в журнале выводится подробный отчет `[RUN-SUMMARY]` о том, что было завершено
4. Устраните проблемы и перезапустите — обработка начнётся с самого начала

## Устранение неполадок во время обработки

### Обработка проходит очень медленно

**Возможные причины:**

* Неотмеченные целевые изображения (происходит сканирование всех изображений)
* Использование HDD вместо SSD
* Недостаток системных ресурсов
* Настроен слишком много индексов
* Доступ к сетевому диску

**Решения:**

1. Если процесс только начался и находится на этапе обнаружения: остановите его, отметьте целевые изображения, перезапустите
2. На будущее: используйте SSD, уменьшите количество индексов, модернизируйте оборудование
3. Рассмотрите возможность использования командной строки (CLI) для пакетной обработки больших наборов данных

### Предупреждения о «месте на диске»

**Решения:**

1. Немедленно освободите место на диске
2. Переместите проект на диск с большим объёмом свободного места
3. Уменьшите количество индексов для экспорта
4. Отключите экспорт ненужных продуктов LATTICE (Настройки проекта → Обработка)
5. Используйте формат JPG вместо TIFF (файлы меньшего размера)

### Частые сообщения о «повреждённых файлах»

**Решения:**

1. Снова скопируйте изображения с SD-карты, чтобы убедиться в их целостности
2. Проверьте SD-карту на наличие ошибок
3. Удалите повреждённые файлы из проекта
4. Продолжите обработку оставшихся изображений

### Перегрев системы / ограничение производительности

**Решения:**

1. Обеспечьте достаточную вентиляцию
2. Очистите вентиляционные отверстия компьютера от пыли
3. Уменьшите нагрузку при обработке (используйте режим «Free» вместо «Chloros+»)
4. Выполняйте обработку в более прохладное время суток

***

## Уведомление о завершении обработки

По завершении обработки:

* Индикатор выполнения достигает 100%
* В журнале отладки появляются строки `[RUN-SUMMARY]` с итоговыми показателями
* Кнопка «Пуск» снова становится активной
* Все выходные файлы находятся в дереве выходных файлов проекта для каждой камеры: `<project>/<camera>/<format>/<Product>_Images/`
