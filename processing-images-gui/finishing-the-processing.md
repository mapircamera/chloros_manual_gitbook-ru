# Завершение обработки

Как только Chloros завершит обработку, пришло время проанализировать результаты, проверить качество выходных данных и подготовить обработанные изображения для использования в вашем рабочем процессе. На этой странице приведены инструкции по выполнению заключительных шагов и дальнейших действий.

## Индикация завершения обработки

По успешному завершении обработки вы увидите несколько индикаторов:

* ✅ **Индикатор выполнения**: достигает 100% завершения
* ✅ **Журнал отладки**: отображает последние строки `[RUN-SUMMARY]` с подсчётом (изображений, групп камер, целей, откалиброванных изображений, записанных файлов)
* ✅ **Кнопка «Старт»**: снова становится активной (готова к следующему запуску обработки)
* ✅ **Выходные файлы**: все обработанные изображения сохранены в папке выходных данных проекта (ниже)

{% hint style="warning" %}
**Запуск, в ходе которого не было записано ни одного изображения, считается неудачным.** Если вы запросили изображения, а в ходе запуска не было записано ни одного, Chloros сообщает об этом как о сбое — `[RUN-SUMMARY]` в имени журнала указывает на вероятную причину (ничего не импортировано, цель не обнаружена или все запрошенные продукты были пропущены как неприменимые). Эквивалент CLI завершается с ненулевым кодом. Намеренный запуск, ориентированный исключительно на метаданные (все экспортные продукты отключены, индексы отсутствуют), по-прежнему считается успешным. См. [справочник по CLI](../reference/cli-reference.md#a-run-that-writes-no-images-fails).
{% endhint %}

4. Найдите свой проект по названию.

### Структура выходных файлов

Файлы сохраняются **в папке проекта, сгруппированные по камерам, а затем по форматам файлов**:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **Папка камеры**: `LATT-<sensor>-<lens>-F<filter>` для LATTICE (соответствует EXIF-данным снимка `Model`), `<model>_<filter>` для Survey3 (например, `Survey3N_RGN`). Две камеры, использующие один и тот же датчик и фильтр, но имеющие разные объективы, хранятся в отдельных деревах — у них различаются виньетирование, поле зрения и искажения.
* **Формат папки**: соответствует вашим настройкам формата экспорта — `tiff16`, `tiff8`, `png8`, `jpg8`, или `tiff32` для TIFF (32-битная, в процентах). Данные Radiance всегда имеют тип float32 и всегда помещаются в папку `tiff32`.
* **Папки с результатами**:
  * `Reflectance_Calibrated_Images/` — откалиброванное коэффициенты отражения
  * `Debayered_Images/` — линейное дебайерирование (LATTICE)
  * `Preview_Images/` — предварительный просмотр на экране (LATTICE)
  * `Radiance_Images/` — спектральное излучение типа float32, Вт/м²/ср/нм (мультиспектральный режим LATTICE)
  * `Vignette_Corrected_Images/` **или** `Sensor_Response_Images/` — некалиброванный резервный вариант для кадров без эталона отражательной способности; в каждом прогоне присутствует ровно один из этих двух вариантов, выбираемый настройкой коррекции Vignette
  * `<INDEX>_Index_Images/` — одна папка на каждый выбранный индекс (например, `NDVI_Index_Images`)

{% hint style="info" %}
**Каждый экспортированный продукт сохраняет имя исходного файла.**Экспорт радиансной интенсивности из `capture_..._raw.tif` по-прежнему называется `capture_..._raw.tif` — просто он находится в папке `tiff32/Radiance_Images/`.**Продукт идентифицируется по папке, а не по имени файла**, поэтому поиск по `*radiance*.tif` ничего не даст; вместо этого ищите по папке.
{% endhint %}

## Чтение значений отражательной способности пикселей (GIS / Pix4D / скрипты)

Отражательная способность хранится в виде целочисленного значения DN, и **значение DN, соответствующее ρ = 1,0, зависит от исходной камеры**:

| Исходная камера          | ρ = 1,0 соответствует | Как определить                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768** (запас до ρ 2,0) | В файле проставлен тег XMP `Chloros:PixelScale=32768` |
| Survey3         | **65535** (обрезано при ρ 1,0)     | Тегов XMP `Chloros:*` нет — это отсутствие и есть сигнал |

**Считайте тег `Chloros:PixelScale` и разделите на это значение**, а не принимайте за данность универсальное значение 65535 — деление коэффициента отражения LATTICE на 65535 незаметно уменьшает каждое значение вдвое. Один крайний случай по замыслу не имеет масштаба: захват с 8-битного источника, записанный как 8-битный выходной файл, обрезается, а не перемасштабируется, и намеренно не получает тег масштаба — для получения полной картины переэкспортируйте в 16-битный или 32-битный формат вместо деления. См. [Форматы выходных изображений](../output-image-formats.md) для получения полной информации.***

## Метаданные, переносимые при экспорте

Каждый продукт сохраняет **GPS-блок**исходного снимка и его**под-IFD EXIF**, поэтому при
экспорте передаются `FocalLength`, `FNumber`, `ExposureTime`, `ISO`, `DateTimeOriginal` и
`CameraSerialNumber`, а также данные геореференции.

{% hint style="warning" %}
**Если ортомозаика получается в нереальном масштабе, сначала проверьте `FocalLength`.**
Pix4D рассчитывает расстояние между точками на местности на основе фокусного расстояния и высоты над землёй. Без этого тега программа
использует крайне неверный масштаб — во время одного из замерённых полётов с 49 снимками апельсиновая роща размером 411 м × 160 м
апельсиновую рощу воссоздали как участок размером 47,8 км × 13 км, в результате чего получилась ортофотопланшага разрешением 455 мегапикселей, состоящая в основном из
пустого пространства. Медленная разбивка на фрагменты и неожиданно огромный размер файла являются симптомами этой проблемы, а не отдельными
проблемами.

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

Не *все* теги копируются. Структурные теги IFD0 намеренно не копируются (их копирование
приводит к повреждению выходных данных LATTICE), а теги `ExifImageWidth` / `ExifImageHeight` исключаются,
поскольку они описывают исходный снимок — в противном случае экспорт с изменёнными размерами
указал бы размеры, противоречащие размерам его собственного растра.

## Распространённые проблемы с выводом данных и их решения

### Проблема: отсутствуют выходные файлы

**Возможные причины:**

* Продукт не подходит для данной камеры (например, яркость/отражательная способность для камер RGB — об этом говорится в журнале)
* Отсутствовала необходимая эталонная информация (например, коэффициент отражения без цели и без нисходящего излучения `.daq`)
* Флажок экспорта продукта был отключен в настройках проекта
* Во время экспорта закончилось место на диске

**Решения:**

1. Проверьте подсказки `[RUN-SUMMARY]` и строки `[EXPORT-CHECK]` в журнале отладки — они объясняют пропуски по каждой камере
2. Проверьте флажки экспорта продукта в [Настройках проекта](adjusting-project-settings.md)
3. Убедитесь, что на диске было достаточно места
4. Повторите обработку после устранения причины

### Проблема: Тёмные или светлые края (виньетирование по-прежнему заметно)

**Возможные причины:**

* Коррекция виньетирования отключена
* Камера/объектив отсутствуют в базе данных профилей Chloros
* Чрезмерное виньетирование, выходящее за пределы возможностей коррекции

**Решения:**

1. Убедитесь, что коррекция виньетирования включена в настройках проекта
2. Проверьте, правильно ли определена модель камеры
3. Если виньетирование сохраняется, обратитесь в службу поддержки MAPIR

### Проблема: Неверные цвета или значения

**Возможные причины:**

* Не обнаружены калибровочные мишени
* Выбрана неверная модель калибровочной мишени
* Калибровка по коэффициенту отражения отключена
* Низкое качество изображений мишеней

**Решения:**

1. Убедитесь, что калибровка по отражательной способности включена
2. Проверьте сообщения «Цель найдена» в журнале отладки
3. Проверьте качество изображений мишеней
4. Повторите обработку с отмеченными правильными мишенями

### Проблема: Значения NDVI кажутся неверными

**Ожидаемые диапазоны значений NDVI:*** **Вода, камни, почва**: от -0,1 до 0,2
* **Редкая/нездоровая растительность**: от 0,2 до 0,4
* **Умеренная растительность**: от 0,4 до 0,6
* **Здоровая, густая растительность**: от 0,6 до 0,9**Если значения выходят за пределы этих диапазонов:**

1. Убедитесь, что была применена калибровка коэффициента отражения
2. Убедитесь, что был включён журнал датчика освещённости
3. Проверьте, были ли обнаружены калибровочные мишени
4. Убедитесь, что была определена правильная модель камеры
5. Проверьте время и условия съемки целевых изображений
6. Если вы самостоятельно вычисляете индексы на основе файлов отражательной способности, убедитесь, что вы произвели деление на значение `Chloros:PixelScale` из файла (см. выше)

## Использование обработанных изображений

### Для фотограмметрии / создания ортомозаики

**Рекомендуемый рабочий процесс:**

1.**Импортируйте откалиброванные изображения отражательной способности** в программное обеспечение для фотограмметрии:
   * Pix4Dmapper
   * Agisoft Metashape
   * DroneDeploy
   * WebODM
2. **Сохраняйте метаданные EXIF**: убедитесь, что данные GPS сохранены для геотагирования
3. **Калиброванные рабочие процессы**: используйте отражательные изображения для обеспечения научной точности — отражательные данные LATTICE содержат теги калибровки XMP, которые считывает Pix4D
4. **Обработка индексных мозаик**: создайте ортомозаики NDVI из отдельных индексных снимков
5. **Экспорт геореференцированных снимков GeoTIFF**: для использования в ГИС-приложениях

### Для ГИС-анализа

**Рекомендуемый рабочий процесс:**

1.**Загрузите в QGIS, ArcGIS или аналогичную программу**

2.**Используйте 16-битные TIFF** отраженные изображения для многополосного анализа (разделить на значение `Chloros:PixelScale` в файле)
3. **Использовать индексные изображения** (NDVI, NDRE) в качестве готовых к использованию слоёв растительности
4. **Растровый калькулятор**: объединяйте полосы для пользовательского анализа
5. **Экспорт**: создавайте карты классификации, карты обнаружения изменений, карты состояния растительности

### Для прямого анализа / составления отчетов

**Рекомендуемый рабочий процесс:**

1.**Используйте индексные изображения с цветами LUT** для визуальных отчетов
2. **Извлечение статистических данных**: среднее значение NDVI по полю/участку
3. **Временные ряды**: сравнение индексов по нескольким сеансам
4. **Создание отчетов**: включение карт, статистических данных и визуализаций***

## Устранение неполадок при постобработке

### Повторная обработка с другими настройками

Если результаты не удовлетворительны:

1. Сохраните исходные изображения (ни в коем случае не удаляйте их)
2. Откройте тот же проект в Chloros
3. Настройте параметры на панели «Настройки проекта»
4. Выполните обработку заново — результаты будут сохранены в тех же папках продуктов, поэтому файлы с теми же именами из предыдущего запуска будут заменены

### Обработка поднабора изображений

Чтобы повторно обработать только определённые изображения:

1. Создайте новый проект
2. Импортируйте только те изображения, которые требуют повторной обработки
3. Используйте тот же шаблон настроек
4. Обработайте меньший набор данных
