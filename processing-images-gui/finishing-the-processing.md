# Завершение обработки

Как только программа Chloros завершит обработку, пришло время проанализировать результаты, проверить качество выходных данных и подготовить обработанные изображения для использования в вашем рабочем процессе. На этой странице вы найдёте инструкции по выполнению заключительных шагов и дальнейших действий.

## Индикаторы завершения обработки

После успешного завершения обработки вы увидите несколько индикаторов:

* ✅ **Индикатор выполнения**: достигает 100% завершения
* ✅ **Журнал отладки**: отображает последние строки `[RUN-SUMMARY]` с подсчётом (изображений, групп камер, целей, откалиброванных изображений, записанных файлов)
* ✅ **Кнопка «Пуск»**: снова становится активной (готова к следующему запуску обработки)
* ✅ **Выходные файлы**: все обработанные изображения сохранены в папке выходных данных проекта (ниже)

{% hint style="warning" %}
**Цикл, в ходе которого не было записано ни одного изображения, считается неудачным.** Если вы запросили продукты в виде изображений, а в ходе цикла не было записано ни одного, Chloros сообщает об этом как о сбое — `[RUN-SUMMARY]` в названии журнала указывает на вероятную причину (ничего не импортировано, цель не обнаружена или все запрошенные продукты были пропущены как неприменимые). Эквивалент в CLI завершается с ненулевым кодом. Намеренный запуск, предназначенный только для метаданных (все экспортные продукты отключены, индексы отсутствуют), по-прежнему считается успешным. См. [Справочник по CLI](../reference/cli-reference.md#a-run-that-writes-no-images-fails).
{% endhint %}

### Дерево выходных файлов

Результаты обработки сохраняются **в папке проекта, сгруппированные по камерам, а затем по форматам файлов**:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **Папка камеры**: `LATT-<sensor>-<lens>-F<filter>` для LATTICE (соответствует EXIF-данным снимка `Model`), `<model>_<filter>` для Survey3 (например, `Survey3N_RGN`). Две камеры, использующие один и тот же датчик и фильтр, но имеющие разные объективы, хранятся в отдельных деревьях — у них различаются виньетирование, поле зрения и искажения.
* **Формат папки**: соответствует вашим настройкам формата экспорта — `tiff16`, `tiff8`, `png8`, `jpg8`, или `tiff32` для TIFF (32-бит, в процентах). Яркость всегда имеет тип float32 и всегда сохраняется в файле `tiff32`.
* **Папки с результатами**:
  * `Reflectance_Calibrated_Images/` — откалиброванное отражение
  * `Debayered_Images/` — линейное дебайерирование (LATTICE): удалено тёмное смещение и выполнено демозаицирование, без плоского поля или размикширования, в исходной ориентации датчика
  * `Preview_Images/` — предварительный просмотр на экране (LATTICE)
  * `Radiance_Images/` — спектральное излучение в формате float32, Вт/м²/ср/нм (мультиспектральный режим LATTICE)
  * `Vignette_Corrected_Images/` **или** `Sensor_Response_Images/` — некалиброванный резервный вариант для кадров без эталона отражательной способности; на каждый цикл съемки приходится ровно один из этих двух вариантов, выбираемый настройкой коррекции виньетирования
  * `<INDEX>_Index_Images/` — одна папка на каждый выбранный индекс (например, `NDVI_Index_Images`)
* **`clamp_masks/`** (новое в версии 1.3.0, только для мультиспектральных камер LATTICE M3C): появляется в папке формата, рядом с папками продуктов, когда при разделении полос отрицательные значения обрезаются до нуля в продукте яркости или отражательной способности. Она содержит одну маску на пиксель для каждого затронутого продукта, например, `tiff16/clamp_masks/Reflectance_Calibrated_Images/<name>_clampmask.tif`. Маски никогда не находятся внутри папки с продуктами, поэтому папку с продуктами можно передавать в программное обеспечение для фотограмметрии без изменений. См. [Маски ограничения](../output-image-formats.md#clamp-masks).

{% hint style="info" %}
**Каждый экспортированный продукт сохраняет имя исходного файла.**Экспорт радианса из `capture_..._raw.tif` по-прежнему называется `capture_..._raw.tif` — он просто находится в папке `tiff32/Radiance_Images/`.**Продукт идентифицируется по папке, а не по имени файла**, поэтому поиск по `*radiance*.tif` ничего не даст; вместо этого ищите по папке.
{% endhint %}

### Сколько должно быть файлов?

Не рассчитывайте по формуле — количество выходных файлов зависит от того, какие продукты были включены и какие из них применяются к каждой камере (например, для камер RGB не генерируются данные о яркости/отражательной способности). Достоверное количество указано в журнале: в последней строке `[RUN-SUMMARY]` точно указано, сколько файлов было записано, а в подсказках объясняется, что именно было пропущено.

## Чтение значений отражательной способности пикселей (ГИС / Pix4D / Скрипты)

Коэффициент отражения хранится в виде целого числа DN, и **значение DN, соответствующее ρ = 1,0, зависит от исходной камеры**:

| Источник          | ρ = 1,0 соответствует | Как определить                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768** (запас до ρ 2,0) | В файле проставлен тег XMP `Chloros:PixelScale=32768` |
| Survey3          | **65535** (обрезано при ρ 1,0)     | Тег `Chloros:PixelScale` отсутствует — это отсутствие и является сигналом (продукты Survey3 содержат другие теги обработки `Chloros:*`) |

**Прочитайте тег `Chloros:PixelScale` и разделите на его значение**, а не принимайте за данность универсальное значение 65535 — деление отражательной способности LATTICE на 65535 незаметно уменьшает каждое значение вдвое. Файл коэффициентов отражения, созданный до версии 1.3.0 и записанный в 8-битном формате, был обрезан, а не перемасштабирован, и не содержит тега масштаба: переэкспортируйте его в 16-битном или 32-битном формате вместо деления. См. [Форматы выходных изображений](../output-image-formats.md) для получения полной информации.

## Метаданные, переносимые в экспортируемые файлы

Каждый продукт сохраняет **блок GPS**исходного снимка и его**под-IFD EXIF**, поэтому при
экспорте передаются `FocalLength`, `FNumber`, `ExposureTime`, `ISO`, `DateTimeOriginal` и
`CameraSerialNumber`, а также геореференцию.

{% hint style="warning" %}
**Если ортомозаика получается в нереальном масштабе, сначала проверьте `FocalLength`.**
Pix4D рассчитывает расстояние между точками на местности на основе фокусного расстояния и высоты над землёй. Без этого тега программа
использует крайне неверный масштаб — в одном из измеренных полётов с 49 снимками апельсиновая роща размером 411 м × 160 м
апельсиновый сад был реконструирован как 47,8 км × 13 км, в результате чего получилась ортофотопланшага размером 455 мегапикселей, состоящая в основном из
пустого пространства. Медленная разбивка на фрагменты и неожиданно огромный размер файла являются симптомами этой проблемы, а не отдельными
проблемами.

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

Не *все* теги копируются. Структурные теги IFD0 намеренно не копируются (их копирование
приводит к повреждению выходных данных LATTICE), а `ExifImageWidth` / `ExifImageHeight` исключаются,
поскольку они описывают исходный снимок — в противном случае экспортированный файл с измененным размером
указывал бы размеры, противоречащие размеру его собственного растра.

Chloros также записывает собственные теги XMP `Chloros:*`, описывающие, что было сделано с каждым продуктом
(например, `Chloros:ProcessingLevel`, `Chloros:CalibrationApplied`,
`Chloros:VignetteCorrected`). Начиная с версии 1.3.0, продукты Survey3 содержат их в каждом режиме обработки
режиме обработки; индексные продукты описывают сам индекс (`Chloros:ProcessingLevel=index`,
формулу и то, был ли он рассчитан на основе коэффициента отражения или яркости), а не повторяют
теги исходных необработанных данных; продукты в папках, имеющих имена длиной более 260 символов, также сохраняют свои метаданные. См. [Форматы выходных изображений](../output-image-formats.md#index-products).

## Распространённые проблемы с выводом данных и их решения

### Проблема: отсутствуют файлы вывода

**Возможные причины:**

* Продукт не применяется к данной камере (например, яркость/отражательная способность для камер RGB — об этом говорится в журнале)
* Отсутствовала необходимая эталонная информация (например, коэффициент отражения без цели и без `.daq` нисходящего излучения)
* Флажок экспорта продукта был отключен в настройках проекта
* Во время экспорта закончилось место на диске

**Решения:**

1. Проверьте подсказки `[RUN-SUMMARY]` и строки `[EXPORT-CHECK]` в журнале отладки — в них объясняются пропуски по каждой камере
2. Проверьте флажки экспорта продукта в [Настройках проекта](adjusting-project-settings.md)
3. Убедитесь, что на диске было достаточно места
4. Повторите обработку после устранения причины

### Проблема: Тёмные или светлые края (виньетирование по-прежнему заметно)

**Возможные причины:**

* Коррекция виньетирования отключена
* Камера/объектив отсутствуют в базе данных профилей Chloros

* Чрезмерное виньетирование, выходящее за пределы возможностей коррекции

**Решения:**

1. Убедитесь, что коррекция виньетирования включена в «Настройках проекта»
2. Проверьте, правильно ли определена модель камеры
3. Если виньетирование сохраняется, обратитесь в службу поддержки MAPIR


### Проблема: Неверные цвета или значения

**Возможные причины:**

* Не обнаружены калибровочные мишени
* Выбрана неверная модель калибровочной мишени
* Калибровка по отражательной способности отключена
* Низкое качество изображений мишеней

**Решения:**

1. Убедитесь, что калибровка по отражательной способности включена
2. Проверьте сообщения «Target found» в журнале отладки.
3. Проверьте качество изображений мишеней.
4. Повторите обработку, отметив правильные мишени.

### Проблема: Значения NDVI кажутся неверными

**Ожидаемые диапазоны значений NDVI:**

* **Вода, камни, почва**: от -0,1 до 0,2
* **Редкая/нездоровая растительность**: от 0,2 до 0,4
* **Умеренная растительность**: от 0,4 до 0,6
* **Здоровая, густая растительность**: от 0,6 до 0,9**Если значения выходят за пределы этих диапазонов:**

1. Убедитесь, что была применена калибровка отражательной способности
2. Убедитесь, что был включён журнал датчика освещённости
3. Проверьте, были ли обнаружены калибровочные мишени
4. Убедитесь, что была определена правильная модель камеры
5. Проанализируйте время и условия съёмки целей
6. Если вы самостоятельно рассчитываете индексы на основе файлов отражательной способности, убедитесь, что вы делили на значение `Chloros:PixelScale` (см. выше)

## Использование обработанных изображений

### Для фотограмметрии / создания ортомозаики

**Рекомендуемый рабочий процесс:**

1.**Импортируйте откалиброванные изображения отражательной способности** в программное обеспечение для фотограмметрии:
   * Pix4Dmapper
   * Agisoft Metashape
   * DroneDeploy
   * WebODM
2. **Сохраните метаданные EXIF**: убедитесь, что данные GPS сохранены для геотагирования
3. **Калиброванные рабочие процессы**: используйте отражательные изображения для обеспечения научной точности — отражательные изображения LATTICE содержат теги калибровки XMP, которые считывает Pix4D
4. **Обработайте индексные мозаики**: создайте ортомозаики NDVI из отдельных индексных изображений
5. **Экспорт геореференцированных файлов GeoTIFF**: для использования в ГИС-приложениях

### Для ГИС-анализа

**Рекомендуемый рабочий процесс:**

1.**Загрузите в QGIS, ArcGIS или аналогичную программу**

2.**Используйте 16-битные TIFF-изображения** отраженного излучения для многополосного анализа (разделите на значение файла `Chloros:PixelScale`)
3. **Используйте индексные изображения** (NDVI, NDRE) в качестве готовых к использованию слоёв растительности
4. **Растровый калькулятор**: объединяйте полосы для пользовательского анализа
5. **Экспорт**: создавайте карты классификации, карты обнаружения изменений, карты состояния растительности

### Для прямого анализа / отчётности

**Рекомендуемый рабочий процесс:**

1.**Используйте индексные изображения с цветами LUT** для визуальных отчётов
2. **Извлечение статистических данных**: среднее значение NDVI по полю/участку
3. **Временные ряды**: сравнение индексов по нескольким сеансам
4. **Создание отчетов**: включение карт, статистических данных и визуализаций***

## Архивирование и резервное копирование

### Рекомендуемая стратегия резервного копирования

**Что следует сохранять:**

* ✅ **Исходные изображения в формате RAW/JPG или исходные снимки LATTICE** — архивируйте на отдельном диске или в облаке; исходные данные являются источником для обработки, и всё остальное можно восстановить на их основе
* ✅ **Файлы датчиков освещённости `.daq` / `.csv`** — необходимы для последующего повторного вычисления коэффициента отражения
* ✅ **Обработанные результаты** — сохраняйте откалиброванные изображения и индексы
* ✅ **Папка проекта** (`project.json` и сопутствующие файлы) — содержит все настройки для повторной обработки в случае необходимости
* ✅ **Журнал отладки** — документирует детали обработки
* ✅ **Изображения калибровочных мишеней** — для проверки и повторной обработки

**Рекомендации по хранению:**

* **Немедленное резервное копирование**: внешний жёсткий диск
* **Долгосрочное архивирование**: облачное хранилище (Google Drive, Dropbox и т. д.)
* **Критически важные данные**: сохраните 2–3 копии в разных местах***

## Следующие циклы обработки

### Повторное использование настроек проекта

Если в будущем предстоит обработка похожих наборов данных:

1. **Сохраните шаблон проекта** (если это ещё не сделано)
2. **Создайте новый проект**, используя сохраненный шаблон
3. **Импортируйте новые изображения**

4.**Обработайте**с использованием идентичных настроек для обеспечения согласованности

### Пакетная обработка нескольких сеансов

Для нескольких сеансов/наборов данных:**Вариант 1: Графический интерфейс — несколько проектов**

* Создайте отдельный проект для каждого сеанса
* Используйте единые настройки шаблона
* Обрабатывайте по одному за раз

**Вариант 2: Chloros CLI (только для Chloros+)**

* Автоматизируйте пакетную обработку
* Обрабатывайте несколько папок с помощью скриптов
* См. [Документацию по CLI](../CLI.md) и [Справочник по CLI](../reference/cli-reference.md)

**Вариант 3: Python SDK (только для Chloros+)**

* Программное управление
* Интеграция с конвейерами анализа
* См. [Документацию по API](../api-python-sdk.md) и [Справочник по SDK](../reference/sdk-reference.md)

## Устранение неполадок при постобработке

### Повторная обработка с другими настройками

Если результаты вас не устраивают:

1. Сохраните исходные изображения (ни в коем случае не удаляйте их)
2. Откройте тот же проект в Chloros
3. Измените настройки на панели «Настройки проекта»
4. Выполните обработку заново — результаты будут сохранены в тех же папках продуктов, поэтому файлы с теми же именами из предыдущего запуска будут заменены

### Обработка поднабора изображений

Чтобы повторно обработать только определённые изображения:

1. Создайте новый проект
2. Импортируйте только те изображения, которые требуют повторной обработки
3. Используйте тот же шаблон настроек
4. Обработайте меньший набор данных
