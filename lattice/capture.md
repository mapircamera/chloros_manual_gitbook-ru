# Настройки и режимы съемки

Процесс съемки на вкладке «Камеры» управляется одной красной кнопкой **«Снять всё»**и одной панелью**«Настройки съемки»**, которая определяет, какой результат даст нажатие этой кнопки: какие камеры будут задействованы, какие типы файлов сохранит каждая камера и будет ли затвор срабатывать однократно, в непрерывном режиме или с определенным интервалом. На этой странице описан весь процесс — настройка, сама съемка, место сохранения файлов на диске и порядок их последующей переработки в откалиброванные продукты. Элементы управления камерами и массивами находятся на странице [Настройки камеры](camera-settings.md).

{% hint style="info" %}
**Для съемки необходимо открыть проект.** Кнопка «Снять всё» и значок настроек съемки (шестеренка) отключены до тех пор, пока не будет открыт проект («Создайте или откройте проект для сохранения снимков»). Каждая съемка сохраняется в папке проекта в `captures/`.
{% endhint %}

## Панель «Настройки захвата»

Откройте её с помощью **значка шестеренки рядом с кнопкой «Захватить всё»**в списке камер на боковой панели или с помощью кнопки**«Открыть настройки захвата…»** внизу любой панели настроек отдельной камеры. В заголовке указано «Настройки захвата» с кнопкой ← «Назад».

Ваши настройки здесь — включённые камеры, флажки для отдельных типов и режим захвата — сохраняются **для каждого проекта** и восстанавливаются при повторном открытии проекта.

### Режимы захвата

Три кнопки режимов в верхней части панели:

| Режим | Описание | Дополнительные настройки (по умолчанию) |
| --- | --- | --- |
| **Одиночный** *(по умолчанию)* | Один захват со всех выбранных камер. | — |
| **Непрерывный**| Последовательные съёмки до наступления условия остановки. | Остановка по**количеству съёмок** (по умолчанию 1) *или* **продолжительности съёмки** (по умолчанию 10 с; единицы: секунды / минуты / часы / дни). |
| **Интервал**(таймлапс) | Серия снимков по таймеру. |**Количество снимков / интервал**(по умолчанию 1) ·**Каждые**N единиц (по умолчанию 5 с) ·**В течение** N единиц (по умолчанию 1 м). |

В режиме «Непрерывный» или «Интервальный» кнопка «Снять всё» во время работы превращается в кнопку **«Остановить (N)»**, подсчитывая снимки по мере их появления.

### Выбор камер и типов экспорта

Справка в этой панели кратко объясняет: выберите, какие камеры и типы экспорта будут использоваться при нажатии «Захватить всё» — по умолчанию всё включено, и настройки сохраняются вместе с этим проектом.

* Кнопки **Выбрать всё / Отменить выбор** одновременно переключают флажки включения для всех камер.
* **Переключатели типов массового экспорта**(два ряда кнопок):**«Все в исходном формате» / «Все с дебейеризацией» / «Все в режиме предварительного просмотра» / «Все в режиме радианса» / «Все в режиме отражения» / «Все в индексном формате»**. Каждый из них имеет трёхсостоятельную подсветку: зелёный ✓ = включено для всех камер, поддерживающих этот тип; янтарный – = включено для некоторых; серый = ни для одной. Переключатель отключён, если ни одна из подключённых камер не поддерживает данный тип. Все они становятся серыми, когда включена функция «Fastest Capture».
* **Строки для каждой камеры**: флажок «Включить», а также раскрываемый (▸/▾) список доступных для этой камеры типов экспорта с отдельными флажками. В строке отображается количество включенных опций, например «4/6».

### Типы экспорта и камеры, поддерживающие их

Существует шесть типов экспорта: **Raw, Debayered, Radiance, Reflectance, Preview, Index**. В строке каждой камеры отображаются только те типы, которые для неё доступны:

| Тип экспорта | Содержание | RGB (FRGB) | Мультиспектральный Байера (FRGN/FOCN/FNGB) | Монохромный (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | Мозаика Байера (монохромный: один канал) напрямую с датчика | ✓ | ✓ | ✓ |
| **Дебайерированный** | Линейная демозаика (монохромный: 1-канальная шкала серого) | ✓ | ✓ | ✓ |
| **Предварительный просмотр** | Полная цепочка обработки изображения (баланс белого + гамма согласно профилю камеры; мультиспектральные данные: растяжение в ложных цветах) | ✓ | ✓ | ✓ |
| **Излучательная мощность** | float32 Вт/м²/sr/нм через полную радиометрическую цепочку | — (не предоставляется) | ✓ | ✓ |
| **Коэффициент отражения** | uint16 ρ (32768 = 1,0) | — (не поддерживается) | ✓ — отображается только при наличии у камеры датчика освещённости DAQ (собственного или унаследованного от массива) | то же, что и для мультиспектрального режима |
| **Индекс** | Визуализация растительного индекса (LUT) | — | ✓ — требует включенного, непустого выражения индекса на камере и не предлагается для элементов комбинированной матрицы (матрица имеет один общий индекс) | — (для индекса требуется ≥2 полос; см. [Монохроматические камеры и индексы растительности](mono-indices.md)) |

Сияние и отражательная способность никогда не доступны для камер RGB — сияние по матрице Байера не имеет смысла для широкополосного фотометрического датчика.

### Быстрая съемка

Переключатель **⚡ Быстрая съемка — только RAW**(оранжевый при включении) переопределяет все настройки экспорта на**только RAW** — плюс бесплатный композитный снимок с объединенным индексом для массивов — чтобы кадр сохранялся как можно быстрее: вычисления яркости/отражательной способности/отображения полностью пропускаются на этапе съемки.

{% hint style="info" %}
**Файл `.daq` по-прежнему сохраняется.** При назначении датчика освещенности функция «Самая быстрая съемка» по-прежнему записывает показания DAQ по нисходящему излучению рядом с необработанными кадрами — так что показатели яркости, отражательной способности и индекса могут быть сгенерированы позже путем повторной обработки (см. [Повторная обработка снимков](#re-processing-captures-into-calibrated-products)). Кроме того, функция «Fastest Capture» не влияет на настройки, выбранные с помощью флажков: при её отключении все настройки восстанавливаются.
{% endhint %}

### Настройки для каждого массива

Каждый подключенный массив имеет собственную групповую карту в панели:

* **Флажок «Включить»** (трехпозиционный для всех элементов) и название массива с указанием режима отображения: «(объединенный | раздельный)».
* Флажок **Выровнять**(по умолчанию**включен**): деформирует экспортируемые элементы в соответствии с профилем выравнивания массива, чтобы экспортированные данные были пиксельно совмещены между камерами. Исходные данные остаются без деформации, но в их метаданных сохраняется трансформация. (Сам профиль рассчитывается в [панели настроек массива](camera-settings.md#alignment-co-registration-combined-only).)
* Строки камер-элементов вложены внутри карты.

Карта массива также содержит два регистратора. Рассматривайте их как **мониторинг и анализ**:

| Регистратор | Уровень | Что записывает |
| --- | --- | --- |
| **● Запись индексного видео / ■ Остановка записи** *(только для комбинированных массивов)* | **Мониторинг** | Композитное изображение комбинированного индекса в реальном времени в формате видео со скоростью 10 кадров в секунду — 8-битное, разрешение предварительного просмотра, встроенная LUT. Требуется открытый проект и потоковое изображение в реальном времени. Отображает кадры и время, прошедшее с начала записи. |
| **⦿ Запись необработанной серии кадров / ■ Остановить серию необработанных кадров** *(любая матрица)* | **Анализ**| Необработанные кадры в формате Байера со скоростью захвата в реальном времени (без обработки) плюс манифест для каждого кадра и показания `.daq`, сохраняемые в формате `captures/bursts/`. После серии снимков появляется кнопка**Создать видео**: она переобрабатывает серию в автономном режиме в откалиброванное видео — с комбинированным индексом и/или показателями яркости/отражательной способности/индекса для каждой камеры — плюс опциональные файлы TIFF. Создание видео с комбинированным индексом запускается автоматически при остановке серии снимков.

## Где сохраняются записи

Записи сохраняются в рамках открытого проекта в папке `<project>/captures/`. Каждый тип экспорта помещается в свою **собственную подпапку**, поэтому в многоуровневой записи типы никогда не смешиваются:

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── *.daq          the downwelling reading matched to the capture
```

* `<ts>` — это временная метка съемки, а `<serial>` — серийный номер камеры. Отдельные снимки называются `capture_<ts>_SN<serial>_<level>`; массивы снимков, полученные по одному синхронизированному триггеру, называются `sync_<ts>_SN<serial>_<level>` и **имеют одну и ту же метку времени для всех камер в группе** (суффикс уровня опускается, если камера сохраняет только один уровень).
* **Одно несоответствие, о котором следует знать:** уровень дисплея хранится в папке с именем `preview/`, тогда как файлы сохраняют `_display` в имени — папка и суффикс различаются только для этого уровня.
* Неизвестные уровни по умолчанию помещаются в папку с их собственным именем; если создание подпапки невозможно, файл записывается в корневой каталог снимков, а не теряется.
* По умолчанию TIFF-файлы снимков сжимаются без потерь (DEFLATE) и содержат полные метаданные калибровки и обработки **внутри XMP-файла** — снимки являются самоописательными, без каких-либо дополнительных файлов, кроме самого файла `.daq`.

Такой же формат файлов `chloros-cli lattice capture` / `array-capture` записывают в свой каталог `-o` — это описано в [Справочнике по CLI, раздел «Как выглядит папка с кадрами»](../reference/cli-reference.md#what-a-captures-folder-looks-like).

## Повторная обработка кадров для получения откалиброванных продуктов

Захваченные необработанные кадры плюс сохраненный файл `.daq` — это всё, что требуется конвейеру обработки; именно поэтому режим «Fastest Capture» безопасен для реальной работы.

* **Графический интерфейс**: добавьте папку с снимками в проект ([Добавление файлов в проект](../processing-images-gui/adding-files-to-a-project.md)) и обработайте как обычно.
* **CLI**: укажите в `process`**корневую папку снимков**:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

`process` обычно импортирует только указанную вами папку, но если в ней нет изображений и есть подпапки, то импорт происходит по иерархии автоматически — таким образом, файлы из корневой папки `.daq` и из подпапок одного уровня импортируются за один раз. Каждый набор данных импортируется как **одно изображение**, к которому другие уровни присоединяются в качестве режимов просмотра, а не как по одному изображению на каждый уровень.

Прямое указание имени подпапки уровня (например, `…/captures/raw/`) также работает, но при этом корневые файлы `.daq` остаются невовлеченными — скопируйте их вместе с ними при повторном получении радиометрического продукта из `raw/`, иначе не будет с чем сопоставить метку времени.

{% hint style="warning" %}
**Обработка всегда начинается с `raw`.**В рамках каждого сбора данных исходным источником для конвейера обработки является необработанный кадр; `debayered`, `radiance`, `reflectance` и `preview` появляются в качестве режимов просмотра, но никогда не возвращаются обратно в конвейер — повторная обработка производного продукта привела бы к повторному применению виньетирования, цветокоррекции и вычислений яркости, уже запечённых в его пикселях, поэтому Chloros отклоняется, а не подвергается двойной обработке. Рендеры `index/` и `composite/` вообще не обрабатываются (они являются выходными данными, а не снимками). Папка с захватами, сохраненная**без** импорта исходных данных, отображается нормально, но `process` пропускает её и сообщает об этом; `--input-level {raw,debayered,processed}` — это специально предусмотренный «запасной выход», который принудительно создаёт точку входа. См. [Справочник по CLI](../reference/cli-reference.md#what-a-captures-folder-looks-like) для ознакомления с точными сообщениями о пропуске.
{% endhint %}

Ещё два важных момента, о которых стоит знать при написании скриптов для повторной обработки:

* Запуск `chloros-cli process`, который запрашивал продукты, но **не записал никаких изображений**, завершается с явной ошибкой и выходит с ненулевым кодом** — вы никогда не получите тихого пустого запуска. Успешные запуски сообщают количество продуктов. (Намеренный запуск, выполнивший только метаданные, всё равно считается успешным.)
* Повторно импортированные обработанные экспортные данные никогда не занимают слот необработанных данных захвата — исходные необработанные данные всегда остаются источником конвейера.

## Эквиваленты CLI

Всё, что описано на этой странице, можно запускать в режиме без интерфейса. Режимы захвата в графическом интерфейсе напрямую сопоставляются с `chloros-cli lattice array-capture`:

| GUI | CLI |
| --- | --- |
| Одиночный | `chloros-cli lattice array-capture` |
| Непрерывный | `array-capture --continuous [--count N] [--duration S]` |
| Интервальный | `array-capture --interval S [--duration S]` |
| Максимально быстрая запись | `array-capture --fastest` |
| Выравнивание флажков | `--aligned / --no-aligned` |
| Флажки типа экспорта | `--processing LEVEL` или `--levels L1,L2,…` (по умолчанию `all`) |
| Запись индексного видео | `chloros-cli lattice array-record` |
| Запись необработанной серии кадров / Создание видео | `chloros-cli lattice array-burst` / `array-build-video` |

Полные таблицы флагов, опция съёмки со стабилизацией Smart-AE (`--smart`) и модель с постоянной скоростью представлены в разделе [CLI Справочник § Режимы съёмки, рекордеры и автономная переработка](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).
