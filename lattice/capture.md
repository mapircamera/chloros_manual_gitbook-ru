# Настройки и режимы съемки

Процесс съемки на вкладке «Камеры» управляется одной красной кнопкой **«Снять всё»**и одной панелью**«Настройки съемки»**, которая определяет, какой результат даст нажатие этой кнопки: какие камеры будут задействованы, какие типы файлов сохраняет каждая камера и будет ли затвор срабатывать однократно, в непрерывном режиме или с определенным интервалом. На этой странице описан весь процесс — настройка, сама съемка, место сохранения файлов на диске и порядок их последующей переработки в откалиброванные продукты. Сами элементы управления камерами и массивами находятся на странице [Настройки камеры](camera-settings.md).

{% hint style="info" %}
**Для съемки необходимо открыть проект.** Кнопка «Захватить всё» и значок настроек захвата в виде шестеренки отключены, пока не будет открыт проект («Создайте или откройте проект для сохранения снимков»). Каждый снимок сохраняется в папке проекта в `captures/`.
{% endhint %}

## Панель «Настройки захвата»

Откройте её с помощью **значка шестеренки рядом с кнопкой «Захватить всё»**в списке камер на боковой панели или с помощью кнопки**«Открыть настройки захвата…»** внизу любой панели настроек отдельной камеры. В заголовке отображается надпись «Настройки захвата» с кнопкой ← «Назад».

Ваши настройки здесь — включённые камеры, флажки для отдельных типов и режим захвата — сохраняются **для каждого проекта** и восстанавливаются при повторном открытии проекта.

### Режимы захвата

Три кнопки режимов в верхней части панели:

| Режим | Описание | Дополнительные настройки (по умолчанию) |
| --- | --- | --- |
| **Одиночная** *(по умолчанию)* | Один снимок со всех выбранных камер. | — |
| **Непрерывная**| Последовательные снимки до наступления условия остановки. | Остановка по**количеству снимков** (по умолчанию 1) *или* **продолжительности съёмки** (по умолчанию 10 с; единицы: секунды / минуты / часы / дни). |
| **Интервал**(таймлапс) | Серия снимков по таймеру. |**Количество снимков / интервал**(по умолчанию 1) ·**Каждые**N единиц (по умолчанию 5 с) ·**В течение** N единиц (по умолчанию 1 м). |

В режимах «Непрерывный» или «Интервал» кнопка «Снять всё» во время работы превращается в кнопку **«Остановить (N)»**, при этом ведётся подсчёт снимков по мере их поступления. Заполнение диска останавливает работу (см. [Процесс «Захват всего»](#the-capture-all-flow)).**Режим «Непрерывный» для массивов работает внутри бэкэнда (новое в версии 1.3.0).** Когда все камеры в списке входят в массив (автономные камеры скрыты или исключены), режим «Непрерывный» больше не отправляет по одному запросу на каждый захват: бэкенд Chloros

самостоятельно запускает цикл захвата, записывая одну синхронизированную группу данных, пока выбирает следующую, а кнопка опрашивает их количество. При наличии автономных камер в списке Chloros

выполняет захват пошагово, как и раньше.

{% hint style="warning" %}
**Быстрая съемка в Windows

: исключите бэкенд Chloros

из сканирования Microsoft Defender.** Сканирование в реальном времени каждого файла, записываемого при высокоскоростной съемке, занимает около 30 % от скорости съемки по результатам тестов MAPIR

(сотни файлов в секунду при небольшой области интереса). Установщик для Windows

предлагает опцию **«Исключить бэкенд Chloros

из сканирования Microsoft Defender (гораздо более быстрая съемка с камеры; рекомендуется)»**, которая по умолчанию отмечена, и снимает это исключение при удалении программы. Если вы сняли флажок, запустите установщик заново с установленным флажком или добавьте исключение процесса Defender для `chloros-backend.exe` (в папке `backend` в папке установки Chloros

). Когда Defender использует одно или более ядер процессора во время непрерывной съемки массива, бэкэнд Chloros

фиксирует это один раз в своём журнале, предлагая те же два способа устранения проблемы.
{% endhint %}

### Выбор камер и типов экспорта

Текст справки в этой панели кратко объясняет: выберите, какие камеры и типы экспорта будут использоваться при «Захвате всего» — по умолчанию включено всё, и настройки сохраняются вместе с этим проектом.

* Кнопки **«Выбрать всё» / «Не выбирать ничего»** одновременно переключают флажки включения для всех камер.
* **Групповые переключатели типов экспорта**(две строки кнопок):**Все в формате Raw / Все с дебайеризацией / Все в формате Preview / Все в формате Radiance / Все в формате Reflectance / Все в формате Index**. Каждый из них имеет три состояния: зелёный ✓ = включено для всех камер, поддерживающих данный тип; жёлтый – = включено для некоторых; серый = ни одна. Переключатель отключен, если ни одна подключённая камера не поддерживает данный тип. Все они становятся серыми, когда включена функция «Fastest Capture».
* **Строки для каждой камеры**: флажок включения, а также раскрываемый (▸/▾) список доступных для данной камеры типов экспорта с отдельными флажками. В строке отображается количество включённых опций, например «4/6».

### Типы экспорта и камеры, поддерживающие их

Существует шесть типов экспорта: **Raw, Debayered, Radiance, Reflectance, Preview, Index**. В строке каждой камеры отображаются только те типы, которые для неё доступны:

| Тип экспорта | Содержание | RGB

(FRGB) | Мультиспектральный Байера (FRGN/FOCN/FNGB) | Монохромный (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | Мозаика Байера (монохромный режим: один канал) напрямую с датчика | ✓ | ✓ | ✓ |
| **Без демозаики** | Линейная демозаика: из исходных данных удаляется смещение темного фона (DSNU) из пакета калибровки, затем выполняется демозаика с учетом краёв — без коррекции линейности, плоского поля или разложения. Сохраняется в формате 3-канального RGB

-файла TIFF

(монохромный: 1-канальный в оттенках серого) | ✓ | ✓ | ✓ |
| **Предварительный просмотр** | Полная цепочка обработки изображения (баланс белого + гамма в соответствии с профилем камеры, а также настройка «Highlights» для RGB

-камеры; мультиспектральный режим: растяжение в ложных цветах) | ✓ | ✓ | ✓ |
| **Яркость** | float32 Вт/м²/ср/нм через полную радиометрическую цепочку | — (не поддерживается) | ✓ | ✓ |
| **Коэффициент отражения** | uint16 ρ (32768 = 1,0) | — (не поддерживается) | ✓ — отображается только при наличии у камеры датчика освещённости DAQ (собственного или унаследованного от массива) | то же, что и для мультиспектрального режима |
| **Индекс** | Визуализация растительного индекса (LUT) | — | ✓ — требует включенного, непустого выражения индекса на камере и не доступно для элементов комбинированной матрицы (матрица имеет один общий индекс) | — (для индекса требуется ≥2 полос; см. [Монохромные камеры и растительные индексы](mono-indices.md)) |

Сияние и отражательная способность никогда не доступны для камер RGB

— сияние по пикселям Байера не имеет смысла для широкополосного фотометрического датчика.

### Быстрейшая съемка

Переключатель **⚡ Самая быстрая съемка — только RAW**(оранжевый при включении) переопределяет все настройки экспорта на**только RAW** — плюс бесплатный композитный снимок с комбинированным индексом для массивов — благодаря чему кадр сохраняется максимально быстро: вычисления яркости/отражательной способности/отображения полностью пропускаются на этапе съемки.

{% hint style="info" %}
**Файл `.daq` по-прежнему сохраняется.** Если назначен датчик освещённости, функция «Самая быстрая съёмка» по-прежнему записывает показания DAQ по нисходящему излучению (в папку `daq/` с данными съёмки) — благодаря чему продукты по яркости, отражательной способности и индексу можно будет построить позже путём повторной обработки (см. [Переобработка снимков](#re-processing-captures-into-calibrated-products)). Кроме того, функция «Fastest Capture» не влияет на настройки, выбранные с помощью флажков: отключите её, и все настройки восстановятся.
{% endhint %}

### Параметры для каждого массива

Каждый подключённый массив имеет собственную групповую карту в панели:

* **Флажок «Включить»** (с тремя состояниями для всех элементов) и название массива с указанием режима отображения: «(объединённый | отдельный)».
* Флажок **«Выровнять»**(по умолчанию**включён**): привёртывает экспортируемые файлы элементов к профилю выравнивания массива, благодаря чему экспортированные данные регистрируются по пикселям между камерами. Исходные данные остаются некорректированными, но в их метаданных сохраняется трансформация. (Сам профиль рассчитывается в [панели настроек массива](camera-settings.md#alignment-co-registration).) Файлы элементов массива сохраняются в исходной ориентации каждой камеры, при этом любые настройки зеркального отражения/вращения записываются в файл, а не применяются.
* Строки камер-элементов вложены внутри карты.

Карта массива также содержит два рекордера. Можно рассматривать их как **мониторинг и анализ**:

| Рекордер | Уровень | Что записывает |
| --- | --- | --- |
| **● Запись индексного видео / ■ Остановка записи** *(только для комбинированных массивов)* | **Мониторинг** | Композитный сигнал комбинированного индекса в реальном времени, преобразуемый в видео со скоростью 10 кадров в секунду — 8-битный, разрешение предварительного просмотра, встроенная LUT. Требуется открытый проект и потоковое просмотр в реальном времени. Отображает кадры и время, прошедшее с начала записи. |
| **⦿ Запись необработанной серии кадров / ■ Остановить серию необработанных кадров** *(любая матрица)* | **Анализ**| Необработанные кадры по алгоритму Байера со скоростью захвата в реальном времени (без обработки) плюс манифест для каждого кадра и показания `.daq`, сохраняемые в формате `captures/bursts/`. После серии снимков появляется кнопка**Создать видео**: она переобрабатывает серию в автономном режиме в откалиброванное видео — с комбинированным индексом и/или показателями яркости / отражательной способности / индекса для каждой камеры — плюс опциональные файлы TIFF. Создание видео с комбинированным индексом запускается автоматически при остановке серии снимков. |

## Поток

«Захват всего»

Нажмите **«Захват всего»** в списке камер на боковой панели:

1. Каждая включённая, видимая и не приостановленная камера осуществляет съёмку с использованием выбранных типов экспорта. **Массивы срабатывают как один синхронизированный триггер** (единая синхронизированная группа, охватывающая всех участников — см. [Мультикамерные массивы](arrays.md)); автономные камеры осуществляют съёмку индивидуально.
2. Скрытые (с отключенным индикатором) или приостановленные камеры пропускаются. Массив полностью блокируется только в том случае, если *все* его элементы скрыты или приостановлены.
3. При назначении датчика освещенности соответствующее значение нисходящего излучения, полученное системой сбора данных (DAQ), сохраняется в виде файла `.daq` в папке `daq/` записей — даже для записей, содержащих только необработанные данные — чтобы впоследствии всегда можно было получить радиометрические продукты.
4. Кнопка отображает текущий ход процесса — «Захват… завершено/всего» — а в режиме «Непрерывный/Интервальный» принимает вид **«Стоп (N)»**. Для каждого элемента захвата установлен таймаут в 300 с.
5. По завершении прохода в результативном сообщении отображается **«Сохранено N файлов»**или**«Сохранено N, F не удалось»**, а также «(S скрыто/приостановлено/пропущено)», если камеры были пропущены. Если диск заполнится, запуск останавливается и выводится сообщение**«Остановлено: диск заполнен. Сохранено N, F не удалось»** — каждый файл, который не удалось записать, считается неудачным.

## Где сохраняются записи

Записи сохраняются в открытом проекте в папке `<project>/captures/`. Каждый тип экспорта помещается в **собственную подпапку**, поэтому в многоуровневой записи типы никогда не смешиваются:

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── clamp_masks/   radiance/…_clampmask.tif, reflectance/…, index/… — unmix clamp masks,
│                  one subfolder per product folder, only when a band was clamped
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── daq/           the downwelling reading(s) matched to each capture (.daq), each with a
                   .daq.cameras.json naming the cameras it describes
```

* `<ts>` — это временная метка записи, а `<serial>` — серийный номер камеры. Автономные снимки имеют имена в формате `capture_<ts>_SN<serial>_<level>`; снимки массива, полученные по одному синхронизированному триггеру, имеют имена в формате `sync_<ts>_SN<serial>_<level>` и **имеют одну и ту же метку времени для всех камер в группе** (суффикс уровня опускается, если камера сохраняет только один уровень).
* **Одно несоответствие, о котором следует знать:** уровень отображения хранится в папке с именем `preview/`, тогда как файлы сохраняют в имени `_display` — папка и суффикс различаются только для этого уровня.
* Неизвестные уровни по умолчанию помещаются в папку с их собственным именем; если подпапку создать невозможно, файл записывается в корневую папку снимков, а не теряется.
* TIFF-файлы снимков по умолчанию сжимаются без потерь (DEFLATE) и содержат полные метаданные калибровки и обработки **внутри XMP-файла** — снимки являются самоописательными и не имеют никаких дополнительных файлов, кроме файла чтения `.daq` (и его `.daq.cameras.json`).
* **Маски ограничения (новое в версии 1.3.0).**В тех случаях, когда при спектральном разделении 3×3 необходимо было ограничить полосу до 0 по крайней мере на одном пикселе, продукты яркости, отражательной способности и показателя преломления получают маску для каждого пикселя: `clamp_masks/<product folder>/<product name>_clampmask.tif` (бит 0 = полоса в канале R продукта, бит 1 = G, бит 2 = B); тег XMP продукта `Chloros:UnmixClampMask` указывает на неё. Маски находятся**рядом** с папками продуктов, но никогда внутри них, поэтому папку продукта, такую как `reflectance/`, можно передавать в программное обеспечение для фотограмметрии без изменений. Собственный импортер Chloros

игнорирует маски.
* **Ориентация (1.3.0).** Продукты «Preview», «Radiance», «Reflectance» и «Index» автономной камеры поворачиваются в соответствии с настройкой «Mirror/Rotation»; файлы «Raw» и «Debayered» остаются в том виде, в каком их считал датчик. Все файлы, входящие в массив, остаются в исходном формате. Каждый файл сохраняет настройки в своём XMP, поэтому при повторной обработке они применяются точно так же.
* **К какой камере относится файл `.daq` (1.3.0).** Идентификатор `.daq` съемки сопоставляется при обработке только с изображениями от камер, указанных в его идентификаторе `.daq.cameras.json`. Таким образом, автономная камера, не имеющая собственного датчика освещенности, больше не использует показания другой камеры — привяжите к ней датчик или запишите его на вкладке «Датчики освещенности». Запись датчика освещенности (а также любой `.daq` без этого файла, включая старые захваты) по-прежнему обслуживает каждую камеру.

Это та же структура, которую файлы `chloros-cli lattice capture` / `array-capture` записывают в свой каталог `-o` — описано в [Справочнике по CLI

, раздел «Как выглядит папка с снимками»](../reference/cli-reference.md#what-a-captures-folder-looks-like).

## Повторная обработка снимков в откалиброванные продукты

Снятые необработанные кадры плюс сохраненный файл `.daq` — это всё, что требуется для конвейера обработки; именно поэтому режим «Fastest Capture» безопасен для реальной работы.

* **GUI**: добавьте папку с кадрами в проект ([Добавление файлов в проект](../processing-images-gui/adding-files-to-a-project.md)) и обработайте как обычно.
* **CLI**: укажите `process` на **корневую папку с кадрами**:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

`process` обычно импортирует только указанную вами папку, но если в ней нет изображений и есть подпапки, он автоматически проходит по всем уровням вниз — таким образом, подпапки всех уровней и папка `daq/` импортируются за один раз. Каждый захват импортируется как **одно изображение**, к которому другие уровни присоединяются в качестве режимов просмотра, а не как отдельное изображение для каждого уровня.

Прямое указание имени подпапки уровня (например, `…/captures/raw/`) также работает, но при этом папка `daq/` остаётся без внимания — скопируйте её вместе с остальными, когда вы-получаете радиометрический продукт из `raw/`, иначе не будет с чем сопоставить временную метку.

{% hint style="warning" %}
**Обработка всегда начинается с `raw`.** В рамках каждой съемки исходным источником для конвейера является необработанный кадр; `debayered`, `radiance`, `reflectance`, и `preview` выступают в качестве режимов просмотра, но никогда не возвращаются обратно в конвейер — повторная обработка производного продукта привела бы к повторному применению виньетирования, цветокоррекции и вычислений яркости, уже запечённых в его пикселях, поэтому Chloros

отказывается от этого, чтобы избежать двойной обработки. Рендеры `index/` и `composite/` вообще не обрабатываются (они являются выходными данными, а не захваченными изображениями). Папка с захватами, сохраненная **без** импорта исходных данных, отображается нормально, но `process` пропускает её и сообщает об этом; `--input-level {raw,debayered,processed}` — это специально предусмотренный «аварийный выход», который принудительно устанавливает точку входа. Точные сообщения о пропуске см. в [Справочнике по CLI

](../reference/cli-reference.md#what-a-captures-folder-looks-like).
{% endhint %}

Ещё два особенности поведения, о которых стоит знать при написании скриптов для повторной обработки:

* Запуск `chloros-cli process`, который запрашивал продукты, но **не записал никаких изображений**, завершается с явной ошибкой и выходит с ненулевым кодом** — вы никогда не получите тихого пустого запуска. Успешные запуски сообщают количество продуктов. (Намеренный запуск, предназначенный только для метаданных, всё равно считается успешным.)
* Повторно импортированные обработанные экспорты никогда не занимают слот исходных данных захвата — исходные данные всегда остаются источником конвейера.

## Эквиваленты CLI



Всё, что описано на этой странице, можно запускать в режиме без графического интерфейса. Режимы захвата в графическом интерфейсе напрямую соответствуют `chloros-cli lattice array-capture`:

| GUI | CLI

|
| --- | --- |
| Однократный | `chloros-cli lattice array-capture` |
| Непрерывный | `array-capture --continuous [--count N] [--duration S]` |
| Интервальный | `array-capture --interval S [--duration S]` |
| Максимально быстрая запись | `array-capture --fastest` |
| Флажок «Выравнивание» | `--aligned / --no-aligned` |
| Флажки типа экспорта | `--processing LEVEL` или `--levels L1,L2,…` (по умолчанию `all`) |
| Запись индексного видео | `chloros-cli lattice array-record` |
| Запись необработанной серии кадров / Создание видео | `chloros-cli lattice array-burst` / `array-build-video` |

Полные таблицы флагов, опция съёмки с интеллектуальной автоэкспозицией (`--smart`) и модель с постоянной скоростью описаны в разделе [Справочник по CLI

, § Режимы съёмки, записывающие устройства и автономная переработка](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).
