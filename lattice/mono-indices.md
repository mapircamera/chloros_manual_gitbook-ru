# Монохромные камеры и индексы растительности

## Одна камера = один диапазон

Камера **M3M**— это монохромный аналог модели Bayer**M3C**: монохромный датчик IMX265, установленный за одним узкополосным интерференционным фильтром. Название диапазона указано в строке модели — `M3M-<lens>-F<wavelength>`, например, `M3M-L87-F685` (в программе Chloros отображается как `LATT-M3M-L87-F685`). Датчик выдает **один канал в оттенках серого** без мозаики Байера: здесь нечего демозаицировать, нет межканальных перекрестных помех, которые нужно устранять, и не требуется настраивать баланс белого.

Важные моменты, о которых следует знать перед планированием монохромной системы:

* **Яркость и отражательная способность полностью определены для каждого канала.**Это радиометрические карты для каждого диапазона, поэтому одна камера M3M генерирует откалиброванные значения излучения в формате float32 (Вт/м²/ср/нм) и отражательной способности в формате uint16 (`32768` = ρ 1,0) точно так же, как это делает диапазон камеры M3C. Монохромные кадры содержат**идентичную** матрицу отклика датчика — декомпозиция 3×3 не требуется и не применяется.
* **Одна монохромная камера не может вычислять растительный индекс.** Для расчёта NDVI, NDRE и других индексов требуется как минимум два диапазона. Чтобы вычислять индексы с помощью монохромного оборудования, необходимо объединить несколько камер M3M — см. ниже.
* Камеры M3M передают данные в формате **Mono12** (12 бит: 2 байта/пиксель по каналу передачи или 1,5 байта/пиксель, если массив использует [упакованную 12-битную передачу](arrays.md#packed-12-bit-transport)), что имеет значение для [расчета пропускной способности массива](arrays.md#bandwidth-how-many-cameras-fit).

## Что Chloros

пропускает для монохромного режима — и как он об этом сообщает

Этапы цветового конвейера просто не применимы к однополосному датчику. Chloros **пропускает их, выводя однострочное сообщение**, а не выдавая ошибку, и при этом нормально выполняет их для любой камеры M3C (Bayer) в той же сессии:

| Этап | Поведение в монорежиме (M3M) | Поведение в режиме M3C |
| --- | --- | --- |
| Демозаика / дебайеризация | Пропущено — уровень экспорта `debayered` представляет собой одноканальное изображение в оттенках серого. | 3-канальная демозаика. |
| Баланс белого (`lattice white-balance`) | Пропускается с однострочным сообщением. | Выполняется нормально. |
| Цветовой профиль (`lattice color-profile`) | Пропускается с однострочным сообщением. | Выполняется нормально. |
| Насыщенность/контраст (`lattice color`) | Пропущено с однострочным сообщением. | Работает нормально. |
| Разделение спектральных перекрестных помех | Идентичность (без матрицы 3×3). | Применяется матрица 3×3 для каждой камеры. |
| Яркость / отражательная способность | **Работает** — для каждого диапазона, полностью откалибровано. | Работает для каждого диапазона. |

Графический интерфейс применяет те же ограничения: для монохромной камеры панель настроек для каждой камеры скрывает строки, относящиеся только к RGB (баланс белого, гамма, цветовой профиль, насыщенность, контраст, разделение каналов), а гистограмма в реальном времени зафиксирована на одной трассе **MONO**. Дискриминатором на протяжении всего стека является токен `M3M` в строке модели, отображаемый в графическом интерфейсе пользователя/SDK как `is_mono`.

## Для индексов требуется ≥ 2 диапазона: выравнивание → стекирование → индексирование

Рабочий процесс с монохромным индексом всегда состоит из трёх одинаковых этапов:

1. **Выравнивание** — наведите несколько камер M3M на разные длины волн (например, F650 «Red» и F850 «NIR»), соедините их в [многокамерную матрицу](arrays.md) и позволить программе Chloros вычислить трансформацию совмещения между камерами.
2. **Сложение** — выровненные кадры объединяются в одно многополосное изображение (каждая камера вносит вклад в виде одной именованной полосы).
3. **Индекс** — вычисление формулы индекса по полосам стека с возможностью рендеринга через LUT.

В графическом интерфейсе вся эта цепочка представляет собой режим отображения массива **Combined Cameras**: композитное изображение в режиме реального времени уже выровнено, а калькулятор индекса массива (ниже) определяет формулу, по которой оно визуализируется. Экспортированные данные съёмки можно деформировать для получения того же выравнивания с помощью параметра съёмки**«Выровненная»**.

## Калькулятор индекса

Калькулятор индекса формирует выражение индекса, используемое в режиме реального времени и при экспорте индексов по каждой камере. Это единая общая поверхность, открываемая из двух мест на боковой панели вкладки «Камеры»:

* **Для каждой камеры**— «Предварительный просмотр в реальном времени» → значок настроек**«Индекс»** (только для камер с матрицей Байера RGN/OCN/NGB; отдельная монохромная камера не имеет управления индексом, поскольку одна полоса не может сформировать индекс).
* **Для массива**— настройки массива → «Просмотр в реальном времени» → значок шестеренки**«Индекс»**. Это монохроматический путь: список полос охватывает**все входящие в массив камеры**, поэтому монохроматическая пара вносит сюда свои две полосы.

Элементы управления, сверху вниз:

* **Чипы полос** («Полосы — нажмите, чтобы добавить в выражение») — по одной кнопке на каждую доступную полосу, с надписью «название цвета + длина волны в нм» (повторяющиеся названия цветов разграничиваются, например, как «Цвет 850»). При нажатии вставляется токен полосы в место курсора. Полосы от камер, которые не могут генерировать радианцию по отдельным полосам (RGB/FRGB), отфильтровываются.
* **Кнопки операторов и функций** — `+ - * / ( ) ^ ,` и `abs() sqrt() log() log10() exp() min() max() pow()`.
* **Текстовое поле выражения** — формула свободного ввода; в поле-заполнителе отображается классическая форма NDVI: `(NIR - Red) / (NIR + Red)`. Находящийся над ним токенизированный предварительный просмотр, доступный только для чтения, отображает фрагменты полос, числа и флаги в виде неизвестных токенов.
* **Баннер валидности**— серый «Пусто — индекс не будет применен»; зелёный «Допустимое выражение»; красный с конкретной ошибкой синтаксического анализа (неизвестный канал, неоднозначный канал, зафиксированный несколькими камерами, отсутствующая скобка и т. д.); или жёлтый, когда выражение допустимо, но**константа** (например, `X/X` или знаменатель NDVI, введённый как `−` вместо `+`) — константа преобразует весь кадр в один цвет.
* Отдельное предупреждение жёлтого цвета появляется, если применённое выражение верно, но **текущий кадр однороден** (плоская или насыщенная сцена) — обнаружено сжатие гистограммы.
* **Применить LUT**(по умолчанию включено; выключено = растяжение в оттенках серого),**Уровень**2/3/5/7 ступеней (по умолчанию 7 ступеней) и поля ввода**Мин. / Макс.**, расположенные по бокам полосы градиента. По умолчанию значение**Min**равно**0,2**— оно масштабирует цветовую шкалу в диапазон, релевантный растительности, тогда как значения ниже этого проходят как оттенки серого; установите**Min**равным −1 для полного диапазона индекса (кнопка**Сброс**восстанавливает диапазон от −1 до +1). По умолчанию значение**Max** равно 1.
* **Динамическая гистограмма** распределения индекса — столбцы с корневым масштабированием, янтарные линии 2-го и 98-го процентилей, белая линия медианы и показания хвостов, выходящих за пределы диапазона («◀ N% < lo» / «hi < N% ▶»), которые становятся янтарными при значении выше 1 % — это сигнал к расширению диапазона Min/Max.
* **Применить** применяет выражение к потоку данных в реальном времени; настройки LUT применяются в режиме реального времени без нажатия кнопки «Применить». При открытом проекте настройки выражения и LUT сохраняются вместе с проектом и восстанавливаются при его повторном открытии; без проекта они сохраняются только на время сеанса.

## Путь CLI



Та же цепочка «выравнивание → стек → индекс», полностью поддерживающая скрипты:

```bash
chloros-cli lattice align-calibrate --serials SN_RED,SN_NIR --save align.json
chloros-cli lattice index --live --profile align.json \
  --preset NDVI --channel red=Red_660 --channel nir=NIR_850 \
  --save-multiband -o output/
```

`align-calibrate` использует подключённый массив, в котором хранятся его камеры, или открывает их самостоятельно для одного прогона. `index --live` всегда открывает камеры самостоятельно (используя [временный массив](../reference/cli-reference.md#multi-camera-transient-sessions)) и не имеет `--serials`: он открывает каждую камеру в сети. Поэтому освободите все камеры, удерживаемые Chloros, до этого — GUI, `cam-connect`, `array-connect` (`chloros-cli lattice array-disconnect --all`): повторное открытие удерживаемой камеры может привести к остановке потока её держателя или к сбою бэкенда. Камера, не передающая кадры, приводит к сбою запуска, и ни стек, ни индекс не записываются.

`--channel` сопоставляет символы пресета с названиями полос в стеке. Два правила помогут вам избежать сбоя запуска:

* **Символы чувствительны к регистру** и должны точно совпадать с названиями каналов пресета — в пресетах используется нижний регистр (пресеты NDVI: `red`, `nir`; см. `--list-presets`). `--channel red=Red_660` работает; `--channel RED=660` завершается с ошибкой `channel_map missing entries`.
* В параметре band side необходимо указать название канала в выровненном стеке (их перечень приведён в `lattice align-info --profile align.json`). В автономном режиме также допускаются индексы каналов с нулевым началом, например, `--channel red=0 --channel nir=1`.

`lattice index` также работает в автономном режиме с сохраненным выровненным многополосным файлом TIFF. Каждая форма работает на бэкенде, поэтому он должен быть запущен и авторизован на платном тарифе Chloros+; относительные `--input` или `--output` определяются относительно папки, из которой вы запускаете команду:

```bash
chloros-cli lattice index --input aligned.tif --preset NDVI \
  --output ndvi.tif --colorize --gradient RdYlGn
```

### Пресеты индекса

`lattice index --preset` (а также [песочница «Индекс/LUT»](../image-viewer-gui/index-lut-sandbox.md) на вкладке «Изображение», которая использует тот же движок) поставляется с этими **22 пресетами**:

`NDVI, GNDVI, BNDVI, NDRE, ENDVI, SAVI, OSAVI, MSAVI, EVI, EVI2, CVI, MSR, TDVI, LAI, GLI, NGRDI, VARI, TGI, EXG, CIRE, CIGREEN, NDWI`

Запустите `chloros-cli lattice index --list-presets`, чтобы увидеть формулу и символы каналов для каждой предустановки, а `--list-gradients` — для просмотра доступных цветовых градиентов. Для пользовательских формул используйте `--formula EXPR` с тем же синтаксисом, что и в «Калькуляторе индексов». Обратите внимание, что этот список предустановок относится конкретно к индексной системе LATTICE — раскрывающийся список «Обработка» в «Настройках проекта» для импортированных изображений содержит другой список (см. [Формулы мультиспектральных индексов](../project-settings/multispectral-index-formulas.md)).

Полный набор флагов (`--output-format`, `--vmin/--vmax/--percentile`, `--bg-mode`, регуляторы выравнивания и деформации для `--live` и др.) описан в [Справочнике по CLI, раздел «Индексы / Математические вычисления для растительности»](../reference/cli-reference.md#index--vegetation-maths); эквиваленты SDK приведены в [Справочнике по SDK](../reference/sdk-reference.md).

## Захват индексных продуктов из мономассива

При подключенном массиве и примененном индексном выражении функция `array-capture` (или функция GUI **«Захватить всё»**) сохраняет уровни экспорта для каждой камеры *и* индексный рендер — `--index`/`--no-index` включает эту функцию в CLI, а по умолчанию захват включает все применимые уровни. Вклад монохромной камеры в каждую группу захвата составляет один канал на уровнях необработанных данных/дебайерированных данных (в оттенках серого)/излучения/отражения, плюс общий композитный индекс, когда массив работает в комбинированном режиме. См. [Массивы из нескольких камер § Сбор данных](arrays.md#capturing-monitoring-vs-analysis).
