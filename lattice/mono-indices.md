# Монохромные камеры и индексы растительности

## Одна камера = один диапазон

Камера **M3M**— это монохромная версия модели Bayer**M3C**: монохромный датчик IMX265, расположенный за одним узкополосным интерференционным фильтром. В строке модели указано название полосы — `M3M-<lens>-F<wavelength>`, например, `M3M-L87-F685` (отображается в Chloros как `LATT-M3M-L87-F685`). Датчик выдает**один канал в оттенках серого** без мозаики Байера: здесь нечего демозаицировать, нет межканальных перекрестных помех, которые нужно бы устранять, и не требуется настраивать баланс белого.

Важные моменты, о которых стоит знать перед планированием монохромной системы:

* **Яркость и коэффициент отражения полностью определены для каждого диапазона.**Это радиометрические карты для каждой полосы, поэтому одна камера M3M генерирует откалиброванные значения яркости в формате float32 (Вт/м²/ср/нм) и коэффициента отражения в формате uint16 (`32768` = ρ 1,0) точно так же, как это делает полоса камеры M3C. Монохроматические кадры содержат**идентичную** матрицу отклика датчика — разложения 3×3 не требуется и не применяется.
* **Одна монохромная камера не может генерировать растительный индекс.** Для расчёта NDVI, NDRE и подобных индексов требуется как минимум два диапазона. Чтобы вычислять индексы с помощью монохромного оборудования, необходимо объединить несколько камер M3M — см. ниже.
* Камеры M3M передают по потоку **Mono12** (12 бит, 2 байта/пиксель по каналу), что имеет значение для [распределения пропускной способности массива](arrays.md#bandwidth-the-rules-of-thumb).

## Что Chloros пропускает при работе с монохромными камерами — и как об этом сообщает

Этапы цветового конвейера просто не применимы к однополосному датчику. Chloros **пропускает их, выводя однострочное сообщение**, а не выдавая ошибку, и при этом продолжает нормально выполнять их для любой камеры M3C (Bayer) в том же сеансе:

| Этап | Поведение в монорежиме (M3M) | Поведение в режиме M3C |
| --- | --- | --- |
| Демозаика / дебайеризация | Пропущено — уровень экспорта `debayered` представляет собой одноканальное изображение в оттенках серого. | 3-канальная демозаика. |
| Баланс белого (`lattice white-balance`) | Пропускается с однострочным сообщением. | Выполняется нормально. |
| Цветовой профиль (`lattice color-profile`) | Пропускается с однострочным сообщением. | Выполняется нормально. |
| Насыщенность/контраст (`lattice color`) | Пропущено с однострочным сообщением. | Работает нормально. |
| Разделение спектральных перекрестных помех | Идентичность (без матрицы 3×3). | Применяется матрица 3×3 для каждой камеры. |
| Яркость / отражательная способность | **Выполняется** — для каждого диапазона, полностью откалибровано. | Выполняется для каждого диапазона. |

Графический интерфейс применяет ту же схему отбора: для монохромной камеры панель настроек для каждой камеры скрывает строки, относящиеся исключительно к RGB (баланс белого, гамма, цветовой профиль, насыщенность, Контраст, разделение каналов), а гистограмма в реальном времени фиксирована на одной кривой **MONO**. Дискриминатором на протяжении всего стека является токен `M3M` в строке модели, отображаемый в графическом интерфейсе как SDK.

## Для индексов требуется ≥ 2 полосы: выравнивание → стекирование → индексирование

Рабочий процесс индексирования монохроматических данных всегда состоит из трёх одинаковых этапов:

1. **Выравнивание** — наведение нескольких камер M3M на разные длины волн (например, F650 «Red» и F850 «NIR»), соедините их в [многокамерную матрицу](arrays.md) и позвольте Chloros вычислить трансформацию совместной регистрации между камерами.
2. **Стек** — выровненные кадры объединяются в одно многополосное изображение (каждая камера вносит вклад в виде одной именованной полосы).
3. **Индекс** — вычисляется формула индекса по полосам стека, при необходимости с рендерингом через LUT.

В графическом интерфейсе пользователя вся эта цепочка представляет собой режим отображения массива **«Объединенные камеры»**: композитное изображение в реальном времени уже выровнено, а калькулятор индекса массива (ниже) определяет формулу, по которой оно визуализируется. Записанные экспорты можно деформировать для получения того же выравнивания с помощью параметра записи**«Выровненное»**.

## Калькулятор индекса

Калькулятор индекса формирует выражение индекса, используемое в режиме реального времени и при экспорте индексов по каждой камере. Это единое окно, которое открывается из двух мест на боковой панели вкладки «Камеры»:

* **Для каждой камеры**— «Live Preview» → значок шестеренки**«Index»** (только для камер Bayer моделей RGN/OCN/NGB; у одиночной монохромной камеры нет управления индексом, поскольку один диапазон не может сформировать индекс).
* **По массиву**— настройки массива → «Предварительный просмотр» → значок шестеренки**«Индекс»**. Это путь для монохромных систем: список диапазонов охватывает**все камеры, входящие в массив**, поэтому монохромная пара вносит сюда свои два диапазона.

Элементы управления, сверху вниз:

* **Чипы полос** («Полосы — нажмите, чтобы добавить в выражение») — по одной кнопке на каждую доступную полосу, с надписью названия цвета + длины волны в нм (одноименные названия цветов разграничиваются, например, как «Цвет 850»). Нажатие вставляет маркер диапазона в место курсора. Диапазоны от камер, которые не могут генерировать яркость по каждому диапазону (RGB/FRGB), отфильтровываются.
* **Кнопки операторов и функций** — `+ - * / ( ) ^ ,` и `abs() sqrt() log() log10() exp() min() max() pow()`.
* **Текстовое поле выражения** — формула, вводимая в свободном формате; в качестве заполнителя отображается классическая форма NDVI в виде `(NIR - Red) / (NIR + Red)`. Расположенный над ним токенизированный предварительный просмотр, доступный только для чтения, отображает фрагменты полос, числа и флаги в виде неизвестных токенов.
* **Баннер проверки корректности**— серый «Пусто — индекс не будет применен»; зелёный «Допустимое выражение»; красный с конкретной ошибкой разбора (неизвестная полоса, неоднозначная полоса, зафиксированная несколькими камерами, отсутствующая скобка и т. д.); или жёлтый, когда выражение допустимо, но является**константой** (например, `X/X`, или знаменатель NDVI, в котором вместо `+` введено `−`) — константа преобразует весь кадр в один цвет.
* Отдельное янтарное предупреждение появляется, если примененное выражение верно, но **активный кадр однороден** (плоская или насыщенная сцена) — обнаружено сжатие гистограммы.
* **Применить LUT**(по умолчанию включено; выключено = растяжение в оттенках серого),**Уровень**2/3/5/7 ступеней (по умолчанию 7 ступеней) и поля ввода**Мин. / Макс.**, расположенные по бокам полосы градиента. По умолчанию значение**Min**равно**0,2**— оно масштабирует цветовую шкалу в диапазон, релевантный для растительности, в то время как значения ниже этого уровня пропускаются как оттенки серого; установите**Min**равным −1 для полного диапазона индекса (кнопка**Сброс**восстанавливает диапазон от −1 до +1). По умолчанию значение**Max** равно 1.
* **Динамическая гистограмма** распределения индекса — столбцы с квадратичным масштабированием, янтарные линии 2-го и 98-го процентилей, белая линия медианы и показания хвостов, выходящих за пределы диапазона («◀ N% &lt; lo» / «hi &lt; N% ▶»), которые становятся янтарными при значении выше 1 % в качестве сигнала к расширению диапазона Min/Max.
* **Применить**применяет выражение к потоку данных в реальном времени; настройки LUT применяются мгновенно без нажатия кнопки «Применить». Выражения намеренно**действуют только в рамках сеанса** — они не сохраняются между сеансами.

## Цепочка CLI

Та же цепочка «выравнивание → стек → индекс», полностью настраиваемая с помощью скриптов:

```bash
chloros-cli lattice array-connect --serials SN_RED,SN_NIR
chloros-cli lattice index --live --profile align.json \
  --preset NDVI --channel red=Red_660 --channel nir=NIR_850 \
  --save-multiband -o output/
```

`--channel` сопоставляет символы пресета с названиями полос стека. Два правила помогут вам избежать сбоя при выполнении:

* **В символах учитывается регистр**, и они должны точно совпадать с названиями каналов пресета — в пресетах используются строчные буквы (NDVI соответствуют `red`,`nir`; проверьте `--list-presets`). `--channel red=Red_660` работает; `--channel RED=660` завершается с ошибкой `channel_map missing entries`.
* В стороне полосы необходимо указать название полосы в выровненном стеке (их список приведён в команде `lattice align-info --profile align.json`). В автономном режиме также допускаются индексы полос, начиная с 0, например `--channel red=0 --channel nir=1`.

`lattice index` также полностью работает в автономном режиме с сохраненным выровненным многополосным TIFF:

```bash
chloros-cli lattice index --input aligned.tif --preset NDVI \
  --output ndvi.tif --colorize --gradient RdYlGn
```

### Предустановки индексов

`lattice index --preset` (а также [Песочница «Индекс/LUT»](../image-viewer-gui/index-lut-sandbox.md) на вкладке «Изображение», которая использует тот же движок) поставляется с этими **22 предустановками**:

`NDVI, GNDVI, BNDVI, NDRE, ENDVI, SAVI, OSAVI, MSAVI, EVI, EVI2, CVI, MSR, TDVI, LAI, GLI, NGRDI, VARI, TGI, EXG, CIRE, CIGREEN, NDWI`

Запустите `chloros-cli lattice index --list-presets` для просмотра формул и символов каналов каждой пресеты, а `--list-gradients` — для просмотра доступных цветовых градиентов. Для пользовательских формул используйте `--formula EXPR` с тем же синтаксисом, что и в «Калькуляторе индексов». Обратите внимание, что этот список предустановок относится конкретно к индексной системе LATTICE — раскрывающийся список «Обработка» в «Настройках проекта» для импортированных изображений представляет собой другой список (см. [Формулы мультиспектральных индексов](../project-settings/multispectral-index-formulas.md)).

Полный набор флагов (`--output-format`, `--vmin/--vmax/--percentile`, `--bg-mode`, регуляторы выравнивания и деформации для `--live`, и другие) описан в [Справочнике по CLI, раздел «Индексы / Математика растительности»](../reference/cli-reference.md#index--vegetation-maths); эквиваленты SDK приведены в [Справочнике по SDK](../reference/sdk-reference.md).

## Захват индексных продуктов из мономассива

При подключенном массиве и примененном индексном выражении команда `array-capture` (или кнопка **«Захватить всё»** в графическом интерфейсе) сохраняет уровни экспорта для каждой камеры *и* индексный рендер — `--index`/`--no-index` включает эту функцию в CLI, а по умолчанию захват включает все применимые уровни. Вклад монохромной камеры в каждую группу захвата состоит из её одной полосы на уровнях «сырой» / «без дебайера» (в оттенках серого) / «радианции» / «отражения», а также из общего композитного изображения с комбинированным индексом, когда массив работает в комбинированном режиме. См. [Массивы из нескольких камер § Захват](arrays.md#capturing-monitoring-vs-analysis).
