# Многокамерные массивы

**Массив**LATTICE представляет собой две или более камер LATTICE, соединенных в один синхронизированный блок. Одна из камер выступает в роли**ведущей**: она подает аппаратный триггерный импульс GPIO на общую линию синхронизации (по умолчанию**Line2**), благодаря чему все камеры фиксируют один и тот же момент времени. Chloros

добавляет синхронизацию времени по протоколу PTP, предварительный просмотр в реальном времени (в виде фрагментов по каждой камере или единого выровненного многополосного композитного изображения) и синхронизированную съемку — каждый цикл съемки формирует одну **группу кадров**, в которой все камеры имеют одинаковую временную метку и идентификатор кадра (указывается как `fid:N` на выходе съемки).

Массивы — это способ, с помощью которого монохромные (M3M) камеры формируют индексы растительности: каждая камера предоставляет один диапазон, а массив выравнивает их в многодиапазонный стек. См. [Монохромные камеры и растительные индексы](mono-indices.md).

Существует три равнозначных способа подключения массива, и все они запускают один и тот же поток «smart-prep»:

| Поверхность | Точка входа |
| --- | --- |
| GUI | Вкладка «Камеры» → **Подключить массив** (синяя кнопка) |
| CLI

| `chloros-cli lattice array-connect --serials SN1,SN2,…` (первый серийный номер = ведущий) |
| Python

SDK

| `connect_array(serials=[…])` → `ArraySession` (первый серийный номер = ведущий) |

Smart-prep выполняет: проверку сетевых возможностей (ICMP DF ping + GVSP-проба), выбор уровня синхронизации, прогнозирование частоты кадров при запрашиваемом размере кадра, выбор упакованной 12-битной передачи (см. [Упакованный 12-битный транспорт](#packed-12-bit-transport)), включение PTP, автоматический выбор формата пикселей для каждой камеры, начальные настройки автоэкспозиции на основе сохраненного состояния каждой камеры и настройку триггера GPIO на линии Line2.

**По умолчанию используется полный сенсор (новое в версии 1.3.0).** Connect сохраняет запрошенный вами размер кадра — полный сенсор 2048×1536, без биннинга и без кадрирования, если вы не выберете иное — и позволяет частоте кадров снижаться до того уровня, который обеспечивают хост и сеть. Программа никогда не выполняет биннинг или кадрирование самостоятельно (в версии 1.2.0 биннинг включался автоматически при частоте ниже 1,5 кадров в секунду). Решение о биннинге или меньшей области интереса (ROI) остается за вами: в диалоговом окне подключения выберите один из вариантов, и в поле «Прогнозируемый результат» отобразится соответствующая частота кадров; команда `array-connect` выводит на экран варианты с более высокой частотой кадров и их прогнозируемые значения.

{% hint style="info" %}
Камеры должны быть доступны по каналу связи, прежде чем что-либо из этого начнёт работать — см. [Подключение камер](connecting.md) для обнаружения, адресации и загрузки калибровочных данных при первом подключении. Для многокамерных установок настройки кольца приёма сетевой карты хоста имеют такое же значение, как и скорость канала связи; полная таблица «симптом→исправление» приведена в разделе [Справочник по CLI

§ Настройка и оптимизация сетевой карты хоста](../reference/cli-reference.md#host-nic-setup--tuning-lattice-arrays).
{% endhint %}

## Диалоговое окно «Подключение массива»

Вкладка «Камеры» → **«Подключить массив»**открывает мастер из трёх шагов:**«Выбрать» → «Режим отображения» → «Настройки»**.

### Шаг 1 — Выбор ведущей и ведомых камер

Сразу после открытия диалоговое окно начинает сканирование сети («Сканирование сети...»), а затем проверяет синхронизационные кабели («Проверка синхронизационных кабелей...»), чтобы определить, какие камеры подключены к линии синхронизации M8. Для создания массива требуется не менее **2 камер**.

Синхронизационные кабели M8 сходятся в одной точке соединения, поэтому **любая подключённая камера может выступать в роли ведущей**. Проверка заранее заполняет роли — камера RGB

(`-FRGB`) в качестве ведущей, если она подключена, в противном случае — первая подключённая камера, а остальные подключённые камеры — в качестве ведомых — и выводит одно из трёх сообщений:

| Сообщение | Значение |
| --- | --- |
| «Синхронизационный кабель обнаружен на {n} камерах. Любая из них может быть ведущей; камера RGB

(в противном случае — первая) выбрана по умолчанию.» (зелёный) | Зонд обнаружил камеры на линии синхронизации; флажки «Ведущая» и «Ведомая» уже установлены. |
| «Ведущая камера не обнаружена — проверьте кабель GPIO» (оранжевый) | Ни одна камера не уловила импульс запуска; проверьте подключение синхронизационного кабеля. Роли по-прежнему предварительно заполнены (RGB

-камера, в противном случае — первая камера в списке, в качестве ведущей), и вы можете их изменить. |
| «Нет кабеля синхронизации: {serials}» (оранжевый) | К перечисленным камерам не подключен кабель синхронизации. |

Таблица камер содержит столбцы **Камера / Серийный номер / IP / Ведущая (радиокнопка) / Ведомая (флажок)**. Строки перечислены в**порядке камер** — камеры M3C (Bayer) перед M3M (моно); среди M3C — FRGB, FRGN, FOCN, затем FNGB; M3M — по длине волны фильтра, начиная с самой низкой (F450 перед F808). Список камер на боковой панели и макет сетки по умолчанию используют тот же порядок.

* Выберите ровно **одного ведущего**и**одного или нескольких ведомых**. Повторное нажатие на переключатель текущего ведущего сбрасывает его выбор. Выбор другого ведущего осуществляется одним щелчком: новый ведущий покидает группу ведомых, а предыдущий ведущий становится ведомым (если у него есть синхронизационный кабель).
* Камеру с пометкой **«Без синхронизирующего кабеля»** невозможно выбрать в качестве подчиненной — подчиненная камера без проводов запуска будет бесконечно ждать сигнала по линии синхронизации и передавать нерабочий сигнал. Вместо этого подключите эту камеру в автономном режиме.
* Камеры, уже подключённые в автономном режиме, *не* отключаются: подключение к массиву освобождает автономную сессию и повторно открывает камеру внутри массива.

**Далее: Режим отображения →**становится доступным после выбора ведущей камеры и как минимум одной ведомой.**Повторное сканирование** запускает повторный поиск устройств и проверку подключений.

{% hint style="warning" %}
**Отмена** отключена во время сканирования или проверки — отмена в середине проверки может привести к сбою камерного SDK

в прошивке камеры LATTICE. Дождитесь завершения вращения индикатора.
{% endhint %}

### Шаг 3 — Настройки массива и прогнозируемый результат

<!-- SCREENSHOT-NEEDED: Array Connect dialog, Settings scene, healthy state: left column with ROI / Binning / Trigger Rate / Wire Budget controls (1.3.0 has no "Pin resolution" checkbox), right "Projected Outcome" column showing green "Simultaneous capture" tier, an fps range, the NIC line, the "Sim-emit burst" line, and the "Wire budget" line with a checkmark. -->



При входе в эту сцену Chloros

запрашивает у бэкенда **рекомендацию**и применяет её:**использование полного датчика — без биннинга и кадрирования ROI — при любой частоте кадров, которая это позволяет**, независимо от скорости, обеспечиваемой хостом и каналом связи. Только когда ни одна частота не позволяет использовать полный датчик, рекомендация уменьшает кадр, и в этом случае биннинг предпочтительнее кадрирования области интереса, поскольку биннинг сохраняет полное поле обзора. Дальше вы выбираете между разрешением и частотой кадров. Каждое внесенное изменение запускает повторный анализ в режиме реального времени и обновляет панель**Прогнозируемый результат** справа.

Левый столбец — настройки:

| Элемент управления | Варианты | По умолчанию | Примечания |
| --- | --- | --- | --- |
| **ROI (поле зрения)** | Полное (2048×1536) / Половина (1024×768) / Четверть (512×384) | Полное | Кадрирование датчика: кадрирование до половины или четверти в меньшую область с исходным шагом пикселей. |
| **Биннинг** | 1× / 2× (сумма 2×2) / 4× (сумма 4×4) | 1× | Аппаратный биннинг: 2×2 = полное поле зрения при затратах на передачу данных, равных одной четверти; 4×4 = полное поле зрения при затратах 1/16. Скрыто, если камеры не поддерживают биннинг. |
| **Изображение на линии передачи** (считывание) | — | — | Ширина × высота после биннинга, фактически передаваемая по линии, округлённая до кратных 16 (минимум 64). |
| **Частота триггера** | 0,5–60 кадров/с, шаг 0,1 | пусто = авто | Частота срабатывания триггера ведущего устройства. Оставьте пустым, чтобы Chloros

определил его самостоятельно. |
| **Пропускная способность канала**| 20–2000 МБ/с, шаг 10 | пустое поле = авто | Сколько хост может фактически принять, в МБ/с —**единственное число, от которого зависит всё распределение массива.** Определяется автоматически по сетевому адаптеру. Уменьшите его, если массив сообщает о повреждённых кадрах: обнаруженное значение завышает возможности USB-адаптеров и общих коммутаторов. Изменение этого параметра приводит к повторному запуску прогноза в режиме реального времени. Поле открывается с бюджетом, с которым был подключён последний массив (сохраняется вместе с проектом), поэтому бюджет, который вы однажды скорректировали, сохраняется. |

Флажок **Разрешение выводов** из версии 1.2.0 исчез: при подключении всегда сохраняется выбранный вами размер кадра, а частота кадров вместо этого снижается.

Правая колонка — **Прогнозируемый результат**:

* **Уровень синхронизации** — «Одновременная съемка» (зелёный), «Одновременная съемка (поэтапная передача FTD)» (зелёный), «Поэтапная съемка (смещение 100 мс)» (янтарный) или «Конфигурация слишком велика» (красный). Chloros

выбирает уровень: одновременная съемка, когда кабель можно использовать совместно со скоростью, соответствующей темпу работы камер (частота кадров снижается по мере уменьшения доли каждой камеры), и съемка с задержкой — только когда это невозможно. Таким образом, массив подключается к любой сети с той частотой кадров, которую позволяет эта сеть.
* **Прогнозная частота кадров** — частота кадров, с которой, как ожидается, будет работать массив. При одновременной съемке это одно число: сначала задается частота, а автоэкспозиция заполняет отведенный ей период, затем повышает коэффициент усиления, чтобы слабо освещенная сцена не снижала его (см. [Как автоэкспозиция распределяет время экспозиции и коэффициент усиления](camera-settings.md)). При ступенчатой съемке это отображается в виде диапазона («темно → светло»), поскольку в условиях слабого освещения длительность экспозиции каждой камеры увеличивает интервал между кадрами.
* **Линия сетевой карты** — скорость соединения и устойчивая пропускная способность («NIC {mbps} Мбит/с · устойчивая {N} МБ/с»).
* **Проверка одновременной передачи пакетов** — может ли кольцо сетевой карты хоста принять один одновременный поток данных от всех камер («Одновременная передача пакетов: X МБ · доступный объем кольца сетевой карты: Y МБ ✓/✗»).
* **Проверка пропускной способности кабеля** — сопоставление совокупного спроса в установившемся режиме и безопасного для предотвращения коллизий предельного значения пропускной способности кабеля («Пропускная способность кабеля: {спрос} МБ/с, требуемый {n} камерами · предельное значение {ceiling} МБ/с ✓/✗ превышение пропускной способности»).
* **«Максимальное количество камер на этом канале: {n} — устанавливается минимальным значением пропускной способности на камеру, поэтому объединение в группы не увеличивает это значение»** — отображается, когда вы приближаетесь к предельному количеству камер (или превышаете его).
* **«При таких настройках КАДРЫ БУДУТ ПРОПУСКАТЬСЯ.»**— красное предупреждение с указанием причины со стороны бэкенда, а также списком препятствий и синими**рекомендациями по устранению** («Чтобы разместить этот массив в сети» / «Чтобы разблокировать одновременную съёмку»).

Кнопка **«Применить и подключиться»** заблокирована до тех пор, пока не будет сформирован прогноз, а её надпись объясняет, почему происходит отказ:

| Название кнопки | Значение | Что действительно помогает |
| --- | --- | --- |
| «Анализ...» | Анализ ещё не завершён. | Подождите. |
| **«Слишком много камер для этой сети»**| Сеть не может передавать данные даже от одной камеры за раз (провал проверки агрегирования): количество камер значительно превышает пропускную способность сети или по ней уже передаются данные от других камер. | Уменьшите количество камер, включите передачу джамбо-фреймов по всей длине трасса или установите более быструю сетевую карту.**Уменьшение области интереса (ROI) НЕ поможет** — см. ниже. |
| **«Уменьшите ROI, чтобы включить»** | При этих настройках кадры будут пропадать (проверка пакетной передачи/кольца не прошла). | Уменьшите ROI, увеличьте биннинг или устраните неполадку в кольце приёма сетевой карты. |

Во время подключения может появиться зелёная **панель загрузки калибровки** с индикатором прогресса для каждого последовательного порта: при первом подключении камеры к компьютеру Chloros

загружает из камеры пакет заводской калибровки объёмом ~3,8 МБ по GigE (примерно 70 секунд на каждую камеру). Для камер, данные о которых уже находятся в кэше, эта панель не отображается; при подключении более шести камер строки панели прокручиваются. См. [Подключение камер](connecting.md).

### Упакованная 12-битная передача

12-битные форматы (`BayerRG12`, `Mono12`) обычно передаются в виде 16-битных слов. **Упакованная**передача отправляет те же 12 бит в 1,5 байта на пиксель и распаковывает их на хосте, поэтому передача каждого кадра занимает на 25 % меньше времени — при полной загрузке датчика это примерно на треть больше кадров в секунду.**Сохраняемые данные идентичны.** Array Connect выбирает этот режим автоматически (`auto`): упаковка используется только в тех случаях, когда это целесообразно и на хосте имеется достаточно ресурсов процессора для распаковки. В графическом интерфейсе пользователя нет переключателя для этого; в командной строке (CLI

) используйте `array-connect --packed {auto,on,off}` (по умолчанию — `auto`). 8-битные и 16-битные форматы никогда не упаковываются.

## Пропускная способность: сколько камер помещается

То, сколько камер может передавать массив, зависит от канала связи, а не от Chloros

, поэтому расчётные данные приводятся в руководстве по оборудованию: **[Планирование пропускной способности массива](https://mapir.gitbook.io/lattice-camera/setup/array-bandwidth-planning)**.

Как Chloros

обрабатывает эти данные: диалоговое окно подключения запускает проверку сети, прогнозирует достижимую частоту кадров и выбирает подходящий уровень. Массив подключается к любой сети: при медленном соединении каждая камера адаптируется к своей доле пропускной способности канала, и частота кадров снижается, а не происходит отказ в подключении массива или сокращение размера его кадров. Отказ происходит только в том случае, если канал не способен передавать данные даже от одной камеры из массива за раз (**Слишком много камер для этой сети**), а не в виде бесшумного сброса пакетов — см. панель прогнозируемых результатов, описанную выше.

## Когда пропадают кадры

Камера может отсутствовать в опубликованной группе по двум совершенно разным причинам,
и для их устранения требуются противоположные меры. Chloros

учитывает их отдельно, а не выдает одно
«неполное» число, не указывающее ни одну из них:

| Что произошло | Что это означает | Где искать |
| --- | --- | --- |
| **Повреждён**— кадр пришёл, но имел структурные ошибки | Потеря пакетов GVSP на сетевом пути |**Пропускная способность кабеля**, кольцо приёма сетевой карты, джамбо-кадры, коммутатор |
| **Никогда не поступил**— кадр вообще не пришёл | Камера не сработала или из неё ничего не вышло |**Синхронизационный кабель M8**, линия синхронизации, все ли устройства находятся в режиме «готовности» |

Распределение переоценивается каждые 10 секунд во время потоковой передачи массива. При значении выше 5 % оно
регистрируется с указанием обоих чисел, и о каждом повреждённом буфере сообщается при первом
случае для каждой камеры, затем данные сводятся раз в минуту, чтобы длинная сессия оставалась читаемой.

**Повреждённые кадры с нулевым показателем «не поступили» означают, что срабатывание и синхронизация по кабелю идеальны**,
а каждый потерянный кадр связан с сетевым путем. Решением является снижение **Wire Budget** и
повторное подключение.

{% hint style="warning" %}
**Снижение частоты триггера не помогает при повреждённых кадрах.** Пакетизация камеры
задаётся однократно при подключении. Снижение частоты триггера изменяет частоту появления
пакетов, но не скорость, с которой сам пакет поступает в сеть. На протестированной установке из 4 камер
уменьшение частоты срабатывания в 5 раз ничего не изменило, тогда как снижение «бюджета кабеля» с 240 до
200 МБ/с позволило снизить долю повреждённых кадров в той же системе с 10,4 % до нуля.
{% endhint %}

Работающий массив не может перепланировать себя — необходимо отключить и повторно подключить его, чтобы алгоритм выбора времени подключения
мог работать с учётом нового бюджета.

### USB-сетевые адаптеры имеют ограничения

USB-адаптер Ethernet объявляет свою скорость *Ethernet*-соединения, но то, что он может фактически
поддерживать, ограничено шиной USB и её драйвером. USB-ключу 10GbE раньше приписывали
пропускную способность примерно 1000 МБ/с — значение, которое никто никогда не измерял, — и синхронизация
четырёх камер с этим мнимым запасом приводила к повреждению 6–18 % кадров, в то время как массив
по-прежнему показывал нормальную целевую частоту кадров. Сейчас пропускная способность адаптеров, подключённых по USB, ограничена
**200 МБ/с** в Windows

и на NVIDIA Jetson, а также **400 МБ/с** в Linux

x86_64. Это ограничение является абсолютным, а не процентным, поскольку ограничивающим фактором является
шина: USB-адаптер 1 Гб/с обеспечивает скорость около 80 МБ/с и не подвержен этому ограничению.

Если ваш хост действительно работает быстрее, чем установленное ограничение, увеличьте значение **Wire Budget**, чтобы это отразить.

## Синхронизация времени по PTP

*Синхронизация* кадров осуществляется с помощью аппаратного триггера; **PTP** (IEEE 1588 PTPv2) обеспечивает сопоставимые *временные метки* на всех устройствах. Она включена по умолчанию при подключении массива:

* **Бэкенд хоста Chloros

выполняет роль PTP-грандмастера**. Камеры LATTICE и световые датчики DAQ-E работают в качестве ведомых устройств в домене 0, поэтому временные метки изображений и спектры DAQ синхронизируются по одному такту (~1 мс).
* `--no-ptp` (CLI

) отключает эту функцию для лабораторных работ — в этом случае временные метки между камерами **не** будут сопоставимы.
* Проверьте состояние синхронизации с помощью CLI

:

```bash
chloros-cli time-sync status     # grandmaster state, clock identity, health (OK, or why its packets are not reaching the network)
chloros-cli time-sync peers      # slaves seen (cameras + DAQ-E sensors)
chloros-cli time-sync cameras    # per-camera PtpStatus / PtpOffsetFromMaster / PtpMeanPathDelay
```

На вкладке «Камеры» нет индикатора PTP; для каждой камеры отображаются доступные только для чтения параметры: **Роль**(ведущая/ведомая),**Линия синхронизации** и уровень возможностей массива. Состояние PTP DAQ-E отображается в деталях датчика на вкладке «Световые датчики».

**Отдельный режим** показывает по одной плитке на камеру. На каждой плитке отображаются:

* название камеры (вверху слева),
* **показатель частоты кадров** (вверху справа) — это *реальная частота захвата* камеры, сообщаемая бэкендом, а не частота опроса предварительного просмотра (живой предварительный просмотр ограничен 30 кадрами в секунду независимо от частоты захвата),
* индикатор состояния — зелёный (потоковая передача) / жёлтый (загрузка) / красный (ошибка),
* **индикатор устаревшего кадра**, если в течение 2 с не поступил новый кадр — это нормально в течение ~5 с после любого подключения/отключения, пока бэкенд перераспределяет пропускную способность канала между камерами.**Комбинированный режим**отображает одну составную плитку: бэкенд выполняет дебайеризацию, масштабирование, выравнивание, шумоподавление, преобразование в яркость по полосам (плюс коэффициент отражения DLS, если подключен датчик освещенности), вычисляет выражение индекса массива, применяет LUT и передаёт результат в формате MJPEG. До тех пор, пока не будет отображён первый выровненный кадр, плитка отображает своё состояние: «Подготовка массива…», «Калибровка выравнивания…», «Ожидание первого кадра…» или — если исчерпаны попытки автоматического выравнивания плитки (около минуты) — «Требуется выравнивание» с кнопкой**«Калибровать выравнивание»**.

Показатель fps плитки массива также сообщает о состоянии потока:**«Применение настроек…»**, пока изменение настроек (формат, биннинг, область интереса) перезапускает камеры,**«Зависло»**, когда массив активен, но перестал передавать группы кадров, и**«Остановлен»**, когда он прекратил передачу потока — в этом случае переподключите матрицу. Если при спектральном разделении пришлось ограничить полосу, отображаемую на композитном изображении, на значительной доле её пикселей (25 % или более), на плитке отображается надпись**«Данные полосы с низкой достоверностью · N%»**: значения индекса, построенные на основе этой полосы, являются сомнительными (обычно одна полоса получила слишком мало света).

Полезные сведения о комбинированном режиме:

* Композитный снимок привязан к кадру **главной**камеры. Наведение AE-ROI и точечный экспонометр на композитном снимке дают точные результаты для главной камеры и приблизительные — для подчиненных; используйте**Разделенный вид** (настройки массива → «Показать камеры-участницы») для просмотра плиток с пиксельной точностью по каждой камере без открытия дополнительных подключений к камерам.
* ****Display Layers**(настройки массива; по умолчанию выключено) позволяет выбрать передний и задний слои — любую камеру-участницу или**Index**. Если в качестве переднего слоя выбран**Index**, пиксели, выходящие за пределы минимального и максимального значений LUT, отображают задний слой.
* **Разрешение рендеринга** (по умолчанию 720p) устанавливает высоту прямой трансляции *и* размер экспортируемого композитного изображения. Изображения с каждой камеры всегда экспортируются в полном разрешении.
* Выравнивание рассчитывается для каждой сессии и никогда не сохраняется. Chloros

автоматически выравнивает **каждый массив после подключения, в обоих режимах отображения**, как только автоматическая экспозиция камер-участниц стабилизируется (программа продолжает попытки до 5 минут). В разделе**«Выравнивание»**панели настроек массива отображаются среднеквадратичные отклонения и кнопка**«Перекалибровать выравнивание»** — в том числе для отдельных массивов, не входящих в составную мозаику.

|

Значок шестеренки рядом с **«Захватить всё»** открывает панель «Настройки захвата» (требуется открытый проект — результаты захвата сохраняются в него):

* **Режим захвата**:**Одиночный**(один проход) /**Непрерывный**(последовательно; ограничен количеством снимков (по умолчанию 1) или продолжительностью (по умолчанию 10 с)) /**Интервальный** (таймлапс: N снимков каждые X интервалов, всего Y; по умолчанию — 1 снимок каждые 5 с в течение 1 минуты).
* **Типы экспорта для каждой камеры**: Raw, Debayered, Radiance, Reflectance, Preview, Index — по умолчанию включены все применимые типы. Типы Radiance/Reflectance скрыты для камер с RGB

-фильтром; **«Отражательная способность» отображается только в том случае, если камера имеет датчик освещённости DAQ** (собственный или унаследованный от массива); для «Индекс» требуется настроенное выражение индекса.
* **Выравнивание**(для каждого массива, по умолчанию**включено**): деформирует экспортируемые файлы элементов в соответствии с профилем выравнивания массива, чтобы экспортированные файлы были пиксельно совмещены. Необработанные данные всегда остаются без деформации, но трансформация сохраняется в метаданных. Файлы элементов массива сохраняются в исходной ориентации каждой камеры (любые настройки зеркального отражения/вращения записываются в файл, но не применяются).
* **Быстрая съемка** (переключатель): только необработанные данные + назначенное значение DAQ + бесплатный композитный индекс, с пропуском калибровочных вычислений во время съемки для максимальной скорости — восстановление яркости/отражательной способности/индекса позже из сохраненного файла `.daq`.
* Выделения сохраняются вместе с проектом. Скрытые или приостановленные камеры пропускаются.
* **Непрерывный режим** для массивов работает внутри бэкэнда Chloros

(новое в версии 1.3.0): когда каждая камера в списке принадлежит к массиву, бэкэнд сам запускает цикл съёмки, записывая одну группу данных, пока выбирает следующую, без отдельного запроса на каждую съёмку. Заполнение диска останавливает выполнение («Остановлено: диск заполнен. Сохранено N, F не удалось»). См. [Настройки и режимы захвата](capture.md#capture-modes) для ознакомления с примечанием Microsoft Defender о высоких скоростях захвата.

Эквивалентный интерфейс CLI

(тот же конечный пункт бэкэнда, та же семантика):

```bash
# One synced group, every applicable export level per camera (the default)
chloros-cli lattice array-capture -o output/

# Interval timelapse: one reflectance pass every 10 s for 5 minutes
chloros-cli lattice array-capture --interval 10 --duration 300 --processing reflectance -o timelapse/

# Fastest grab for a moving rig — raw + .daq now, calibrate later
chloros-cli lattice array-capture --fastest -o flightline/

# 30-second monitoring clip of the combined index view, plus a GIF
chloros-cli lattice array-record --duration 30 --fps 10 --gif -o monitoring/

# 5-second analysis-grade raw burst, then build the combined index video
chloros-cli lattice array-burst --duration 5 --build --products combined:index --fps 10 -o capture/
```

Сжатие TIFF

-файлов при захвате: `deflate` (без потерь, по умолчанию) или `none` — полные таблицы флагов, структура папки захвата и правила повторной обработки приведены в [Справочнике по CLI

](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).

## Подключение датчика освещенности DAQ

Для предварительного просмотра с коррекцией отражательной способности и освещенности требуются данные о нисходящем освещении от датчика DAQ (подключенного на вкладке **Датчики освещенности**):

* В **строке массива**на боковой панели отображается**кнопка «DAQ · вкл./выкл.»** — она находится в положении *вкл.*, если установлен датчик освещенности на уровне массива **или** у любой камеры в массиве есть собственный датчик; в всплывающей подсказке указано, какой именно датчик подаёт данные на какую камеру.
* Назначьте параметр для всего массива в настройках массива → **Датчик окружающего освещения**→ выпадающий список**Датчик освещенности**. Этот выбор сохраняется в проекте, распространяется на каждую камеру в массиве, при этом отдельные камеры по-прежнему могут переопределить его с помощью собственного датчика.
* Строка состояния ниже отображает текущее состояние: **Выкл.**→ «Ожидание первого спектра…» →**«Активно — для всех камер в массиве выполнена коррекция освещенности»** → или, если за последние 3 с не поступило нового спектра, уведомление об устаревших данных — продолжает использоваться последнее значение (значения никогда не истекают на пути захвата).

При назначенном датчике: становится доступен тип экспорта «Отражательная способность», предварительный просмотр в реальном времени корректируется с учётом освещённости, прогнозируемая автоэкспозиция может использовать спектр, и при каждой съёмке отражательной способности показания DAQ, фактически использованные при съёмке, записываются в файл **`.daq`** в папке съёмок `daq/`, чтобы запись можно было переобрабатывать позже. Рядом с ним файл `.daq.cameras.json` указывает камеры, кадры которых описывает данное показание; при повторной обработке программа Chloros

сопоставляет показание только с изображениями с этих камер.
