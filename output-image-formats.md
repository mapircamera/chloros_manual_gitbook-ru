# Форматы выходных изображений

Chloros экспортирует обработанные результаты в четырех форматах файлов. Выберите формат в настройках проекта (GUI), с помощью `--format` (CLI) или с помощью `export_format` (SDK). CLI и SDK принимают именно те строки, которые приведены ниже.

| Строка формата | Расширение | Тип пикселя | Диапазон пикселей | Примечания |
| --- | --- | --- | --- | --- |
| `TIFF (16-bit)` *(по умолчанию)* | `.tif` | цифровое число uint16 | 0 – 65535 | Рекомендуется для фотограмметрии / ГИС. |
| `TIFF (8-bit)` | `.tif` | 8-битное целое число | 0 – 255 | Для всех 8-битных снимков, которые поддерживают только 8-битные форматы: Chloros не увеличивает разрядность. |
| `TIFF (32-bit, Percent)` | `.tif` | float32 | 0,0 – 1,0 | 1,0 = 100 % коэффициент отражения. Некоторые приложения не могут читать TIFF-файлы с плавающей запятой; файлы имеют больший размер. |
| `PNG (8-bit)` | `.png` | цифровое число uint8 | 0 – 255 | Сжатие без потерь, подходит для просмотра в Интернете и визуализации. |
| `JPG (8-bit)` | `.jpg` | цифровое число uint8 | 0 – 255 | Сжатие с потерями, файлы наименьшего размера. |

## Где сохраняются выходные файлы

Файлы сохраняются в папке проекта, сгруппированные по камерам, а затем по форматам файлов:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera (model+lens+filter)
    ├── tiff16/                          # follows --format: tiff16, tiff8, png8, jpg8, or tiff32
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one <INDEX>_Index_Images/ folder per requested index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

Папка для камеры LATTICE — `LATT-<sensor>-<lens>-F<filter>`, а для Survey3 — `<model>_<filter>` (например, `Survey3N_RGN`). **Каждый экспортированный продукт сохраняет имя исходного файла — продукт идентифицируется по папке, а не по суффиксу имени файла.** Полные правила см. в разделе [Где сохраняются выходные файлы](reference/cli-reference.md) в Справочнике по интерфейсу командной строки (CLI).

## Продукты LATTICE (уровни захвата и экспорта)

Один необработанный кадр LATTICE за один проход преобразуется во все запрошенные продукты. Для каждого типа продукта предусмотрен собственный переключатель (флажки в графическом интерфейсе или команды CLI: `--debayered` / `--preview` / `--radiance` / `--reflectance`, все включены по умолчанию):

| Уровень | Содержимое | Тип данных |
| --- | --- | --- |
| `raw` | Данные Байера напрямую с датчика (монохромные камеры: один диапазон). Обработка всегда начинается с необработанных данных. | Как снято |
| `debayered` | Линейная демозаика — 3-канальная для M3C, 1-канальная в оттенках серого для M3M: удаляется темновое смещение из пакета калибровки, затем выполняется демозаика с учетом краев, без коррекции линейности, плоского поля или разложения. Экспорт `process` записывает тот же файл, что и сохраняется при съемке на этом уровне, в любом режиме обработки. | Линейная DN |
| `radiance` | Абсолютная спектральная яркость, полученная по полной радиометрической цепочке, в **Вт/м²/ср/нм**. Всегда записывается в формате 32-битного TIFF (`tiff32/Radiance_Images/`), независимо от выбранного формата экспорта. | float32 |
| `reflectance` | Коэффициент отражения ρ, где **DN 32768 = ρ 1,0 (100 %)** с запасом до ρ 2,0. Готов к использованию в Pix4D. | uint16 |
| `preview` | Рендеринг, готовый к отображению: RGB = баланс белого + гамма; мультиспектральный = растяжение в ложных цветах. | 8-битный дисплей |

### Ориентация

Файлы `raw` и `debayered` всегда сохраняют **исходную** ориентацию датчика; настройки зеркального отражения/поворота камеры применяются только к другим продуктам (предварительный просмотр, излучательная способность, коэффициент отражения, индекс). При захвате массива файлы каждого элемента сохраняются в исходной ориентации, если вы не укажете иную ориентацию (`--orient` в CLI, `orient=True` в SDK). В каждом файле в формате XMP записывается ориентация, соответствующая его пикселям — `ChlorosRotation`, `ChlorosFlipHorizontal`, `ChlorosFlipVertical` — а `ChlorosOrientationApplied` указывает, содержатся ли эти данные в его собственных пикселях (`false` для необработанных и дебейерированных файлов). Программа просмотра изображений Chloros изменяет файлы в формате RAW и файлы после дебайеризации в соответствии с этой записью исключительно для целей отображения; сами файлы никогда не перезаписываются. Файл без этой записи (созданный до версии 1.3.0 или с помощью другого инструмента) отображается в том виде, в котором он был сохранен.

## Маски ограничения

Показатели яркости и отражательной способности мультиспектральной камеры M3C проходят размикширование по полосам 3×3. Если в результате размикширования в какой-либо полосе получается отрицательное значение, оно ограничивается до нуля (в режиме реального времени ограничение происходит точно так же). Нововведение версии 1.3.0: продукт, в котором хотя бы один пиксель был ограничен, получает сопутствующую **маску ограничения**, которая точно указывает, какие именно пиксели и полосы:

* **Где:**в папке `clamp_masks/`**рядом с** папками с продуктами, но никогда внутри них: `tiff16/Reflectance_Calibrated_Images/x.tif` → `tiff16/clamp_masks/Reflectance_Calibrated_Images/x_clampmask.tif`, и `tiff32/Radiance_Images/x.tif` → `tiff32/clamp_masks/Radiance_Images/x_clampmask.tif`.
* **Что:** однополосный файл TIFF `uint8` на собственной пиксельной сетке продукта (с учетом ориентации, области интереса (ROI), биннинга и выравнивания массива). Бит 0 (`mask & 1`) устанавливается там, где был обрезан канал R продукта, бит 1 (`& 2`) — в канале G, бит 2 (`& 4`) — в канале B. Доля обрезанных пикселей по каждому каналу также отмечается в продукте как `Chloros:BandRUnmixClampFraction`, `Chloros:BandGUnmixClampFraction` и `Chloros:BandBUnmixClampFraction`.
* **Как это указано в продукте:** тег XMP `Chloros:UnmixClampMask` содержит путь к маске относительно папки продукта (`../clamp_masks/<product folder>/<name>_clampmask.tif`, всегда разделённые символом `/`), `none` — если ни один пиксель не был обрезан (маска не записывается), или `unavailable` — если маску не удалось записать. Продукт без тега никогда не проходил процесс разделения каналов (камеры RGB и монохромные, уровни в формате RAW и после дебейеризации).

Поскольку ни одна папка продукта не содержит маски, вы можете передать папку продукта, например `Reflectance_Calibrated_Images/`, в Pix4D, Metashape или другое программное обеспечение для фотограмметрии в том виде, в каком она есть, включая подпапки — передавайте именно папку продукта, а не папку формата, расположенную над ней. Собственный импорт Chloros пропускает маски ограничения. CLI учитывает их отдельно: `Image products written: N (plus M clamp masks)`.

## Индексные продукты

Каждый индекс помещается в собственную папку `<INDEX>_Index_Images/` (например, `NDVI_Index_Images/`).

* **Целочисленные форматы**(`TIFF (16-bit)`, `TIFF (8-bit)`, `PNG (8-bit)`, `JPG (8-bit)`) хранят**линейное растяжение для каждого изображения**, а не отображение −1…1: DN 0 — это наименьшее значение индекса данного кадра, а полный масштаб — наибольшее. Файл содержит `Chloros:IndexScaling=linear_minmax`, `Chloros:IndexMin` и `Chloros:IndexMax`, а значит, и `value = IndexMin + DN / full_scale × (IndexMax − IndexMin)`. Поскольку каждый кадр имеет свои собственные конечные точки, сравнивайте кадры по значениям, а не по DN.
* **`TIFF (32-bit, Percent)`** хранит сами индексные значения в формате float32 без перемасштабирования — это лучший выбор для количественных исследований в рамках всего полёта.

Нововведение версии 1.3.0: индексный продукт описывает **сам себя**, а не повторяет теги исходных необработанных данных. Его теги GPS и камеры копируются из продукта, на основе которого он был рассчитан (продукт отражательной способности, если таковой имеется), а затем:

| Тег | Значение |
| --- | --- |
| `Chloros:ProcessingLevel` | `index` (поэтому файл никогда не импортируется повторно как съёмка) |
| `Chloros:IndexApplied` / `Chloros:IndexExpression` | `True` / используемая формула |
| `Chloros:IndexLevel` | `reflectance` или `radiance` — на основе чего был рассчитан индекс (отсутствует, если ни того, ни другого) |
| `Chloros:IlluminationInvariant` | `True` для индекса, рассчитанного по коэффициенту отражения, `False` — по яркости или значениям датчика |
| `Chloros:ChlorosPipelineVersion` | версия Chloros, с помощью которой был создан индекс |

`Chloros:PixelScale` удалён из индексных продуктов — используйте `IndexMin` / `IndexMax` выше. Полная инструкция по чтению приведена в разделе «Целочисленный индексный растр представляет собой растяжение контрастности для каждого изображения» в [Справочнике по CLI](reference/cli-reference.md).

## Чтение значений отражательной способности пикселей

Отражательная способность хранится в виде целочисленного цифрового значения, и **значение DN, соответствующее ρ = 1,0 (100 % отражательной способности), зависит от исходной камеры**:

| Исходная камера | ρ = 1,0 соответствует DN | Как определить |
| --- | --- | --- |
| LATTICE (M3C / M3M) | `32768` (диапазон до ρ 2,0) | В файле проставлен тег XMP `Chloros:PixelScale=32768`. |
| Survey3 | `65535` (обрезано при ρ 1,0) | Тег `Chloros:PixelScale` отсутствует — это и является признаком. (Продукты Survey3 действительно содержат другие теги обработки `Chloros:*`, такие как `Chloros:CalibrationApplied`, в каждом режиме обработки начиная с версии 1.3.0.) |

**Считайте тег XMP `Chloros:PixelScale` и делите на его значение**, а не принимайте за постоянную величину. Этот тег определён в домене uint16, поэтому он остаётся `32768` во всех выходных форматах, в которых происходит перемасштабирование — сначала нормализуйте сохраненный тип данных обратно к uint16 (×257 из 8-битного, ×65535 из float32).

{% hint style="warning" %}
**8-битные съёмки.** Экспортные данные 8-битной съёмки имеют 8-битную разрядность. Её коэффициент отражения перемасштабируется и помечается как `Chloros:PixelScale=32768`, поэтому масштаб сохраняется; 8-битные продукты DN и файлы отражательной способности, записанные до версии 1.3.0, обрезаются до диапазона 0–255 и не содержат метки масштаба. Если метка отсутствует в файле отражательной способности LATTICE, не следует предполагать наличие масштаба; вместо этого выполните повторный экспорт в 16-битном или 32-битном формате.
{% endhint %}

Полный перечень правил (включая теги, совместимые с MicaSense) см. в разделе **«Чтение пикселей отражательной способности»** в [Справочнике по CLI](reference/cli-reference.md).
