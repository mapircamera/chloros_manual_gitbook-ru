# Форматы выходных изображений

Chloros экспортирует обработанные результаты в четырёх форматах файлов. Выберите формат в настройках проекта (графический интерфейс), с помощью `--format` (CLI) или с помощью `export_format` (SDK). CLI и SDK принимают именно те строки, которые приведены ниже.

| Формат строки | Расширение | Тип пикселя | Диапазон пикселей | Примечания |
| --- | --- | --- | --- | --- |
| `TIFF (16-bit)` *(по умолчанию)* | `.tif` | целое число uint16 | 0 – 65535 | Рекомендуется для фотограмметрии / ГИС. |
| `TIFF (32-bit, Percent)` | `.tif` | float32 | 0,0 – 1,0 | 1,0 = 100 % коэффициент отражения. Некоторые приложения не могут считывать файлы TIFF с плавающей запятой; файлы имеют больший размер. |
| `PNG (8-bit)` | `.png` | цифровое число типа uint8 | 0 – 255 | Сжатие без потерь, подходит для просмотра в Интернете и визуализации. |
| `JPG (8-bit)` | `.jpg` | цифровое число uint8 | 0 – 255 | Сжатие с потерями, файлы минимального размера. |

## Где сохраняются выходные файлы

Файлы сохраняются в папке проекта, сгруппированные по камерам, а затем по формату файла:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera (model+lens+filter)
    ├── tiff16/                          # follows --format: tiff16, tiff8, png8, jpg8, or tiff32
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one <INDEX>_Index_Images/ folder per requested index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

Папка для камеры LATTICE — `LATT-<sensor>-<lens>-F<filter>`, а для Survey3 — `<model>_<filter>` (например, `Survey3N_RGN`). **Каждый экспортированный продукт сохраняет имя исходного файла — папка идентифицирует продукт, а не суффикс имени файла.** Полные правила см. в разделе [Где сохраняются выходные данные](reference/cli-reference.md) в Справочнике по CLI.

## Продукты LATTICE (уровни захвата и экспорта)

Один необработанный кадр LATTICE за один проход разветвляется на все запрошенные продукты. У каждого типа продукта есть свой переключатель (флажки в графическом интерфейсе или CLI `--debayered` / `--preview` / `--radiance` / `--reflectance`, все включены по умолчанию):

| Уровень | Содержание | Тип данных |
| --- | --- | --- |
| `raw` | Данные Байера непосредственно с датчика (монохромные камеры: однополосная съёмка). Обработка всегда начинается с необработанных данных. | В исходном виде |
| `debayered` | Линейная демозаика — 3-канальная для M3C, 1-канальная в оттенках серого для M3M. | Линейный DN |
| `radiance` | Абсолютная спектральная яркость, полученная по полной радиометрической цепочке, в **Вт/м²/ср/нм**. Всегда записывается как 32-битный TIFF (`tiff32/Radiance_Images/`), независимо от выбранного формата экспорта. | float32 |
| `reflectance` | Коэффициент отражения ρ, где **DN 32768 = ρ 1,0 (100 %)** с запасом до ρ 2,0. Готов к использованию в Pix4D. | uint16 |
| `preview` | Рендеринг, готовый к отображению: RGB = баланс белого + гамма; мультиспектральный режим = растяжение в ложных цветах. | 8-битное отображение |

## Чтение значений отражательной способности пикселей

Коэффициент отражения хранится в виде целого числового значения, и **значение DN, соответствующее ρ = 1,0 (100 % отражения), зависит от исходной камеры**:

| Исходная камера | ρ = 1,0 соответствует DN | Как определить |
| --- | --- | --- |
| LATTICE (M3C / M3M) | `32768` (запас до ρ 2,0) | Тег XMP `Chloros:PixelScale=32768` проставлен в файле. |
| Survey3 | `65535` (обрезано при ρ = 1,0) | Тегов XMP `Chloros:*` нет — это отсутствие и является признаком. |

**Считайте значение тега XMP `Chloros:PixelScale` и разделите на него**, а не принимайте за постоянную величину. Тег определён в области uint16, поэтому он остаётся неизменным `32768` при преобразовании в выходные форматы, которые изменяют масштаб — сначала нормализуйте сохраненный тип данных обратно в uint16 (×257 из 8-битного, ×65535 из float32).

{% hint style="warning" %}
**Один случай по замыслу не имеет масштаба.** Когда данные, захваченные из 8-битного источника (BayerRG8), записываются как 8-битные TIFF, конвейер обрезает значения до диапазона 0–255 вместо перемасштабирования, поэтому файл не описывает масштаб — в Chloros намеренно опущен `Chloros:PixelScale`. Если этот тег отсутствует в файле отраженного излучения LATTICE, не следует предполагать наличие масштаба; вместо этого выполните повторный экспорт в 16-битном или 32-битном формате.
{% endhint %}

Полный перечень правил (включая теги, совместимые с MicaSense) см. в разделе **«Чтение пикселей отражательной способности»** в [CLI Справочнике](reference/cli-reference.md).
