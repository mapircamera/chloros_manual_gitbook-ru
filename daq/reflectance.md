# Алгоритмы работы с коэффициентом отражения

Датчик освещенности системы сбора данных (DAQ) преобразует радиометрические изображения в коэффициент отражения. Существует два различных алгоритма работы:

1. **Один датчик** — один датчик DAQ измеряет интенсивность нисходящего излучения, пока камера ведет съемку, а Chloros делит яркость, зарегистрированную камерой, на это эталонное значение.
2. **Двухдатчиковый** — два датчика системы сбора данных (DAQ), один из которых отслеживает небо, а другой — объект, формируют кривую спектрального коэффициента отражения в реальном времени без участия камеры.

## Один датчик + камера (нисходящее излучение в качестве эталона)

Система сбора данных (DAQ) выступает в роли датчика нисходящего излучения (DLS): камера измеряет восходящее излучение **L**(Вт/м²/стр/нм), DAQ измеряет нисходящее излучение**E** (Вт/м²/нм), а Chloros вычисляет коэффициент отражения по каждому диапазону по формуле:

> ρ = π · L / E

Показания DAQ всегда **синхронизированы по временной метке с экспозицией** — именно поэтому DAQ и камеры используют общий тактовый генератор с синхронизацией по PTP (см. [Сетевые подключения и синхронизация времени DAQ-E](ethernet-ptp.md)). Наденьте козинусную шапочку Sunshine для работы на открытом воздухе и правильно задекларируйте её; декларация шапочки напрямую влияет на масштабирование E (см. [Профили шапочек и откалиброванный диапазон](caps-and-range.md)). Для количественных измерений помните о характеристиках прибора: количественное значение освещенности рассчитывается как среднее значение показаний за период не менее 15 с.

### Захват в реальном времени

Привяжите DAQ к камере на вкладке «Камеры»: на панели настроек каждой камеры есть раскрывающийся список **Датчик освещенности**, в котором перечислены все подключенные DAQ (DAQ-U/M/E) из вкладки «Датчики освещенности»; для синхронизированного массива выбор датчика освещенности для всего массива распространяется на каждый элемент (отдельные камеры по-прежнему могут переопределить этот выбор). После привязки спектры датчика поступают в слот DLS камеры, а экспортируемые значения отражательной способности делятся на соответствующее измеренное значение.

Два важных момента, о которых стоит знать:

* **Если DAQ не привязан → данные о отражательной способности отклоняются, а не подставляются фиктивные значения.** Chloros отклоняет результат расчёта отражательной способности и фиксирует причину пропуска, а не возвращает без предупреждения результат с пониженной точностью.
* **Использованное значение сохраняется.** Для каждого кадра отраженного излучения фактически примененное показание DAQ записывается в виде файла `.daq` рядом с изображением, чтобы съемку можно было повторно обработать позже ([Запись и формат .daq](recording.md)).

### Обработка записанных изображений

Для обработки после полёта запишите файл `.daq` во время сеанса и сохраните его вместе с изображениями — конвейер автоматически определяет нисходящий поток, сопоставленный по временной метке, при первом использовании извлекая из облака MAPIR любую недостающую заводскую калибровку. Записи из графического интерфейса автоматически добавляются в открытый проект после их завершения.

Эталон отражательной способности можно выбрать во время обработки — `--reflectance-source` на `chloros-cli process` или настройка «Источник отражательной способности» в «Настройках проекта» графического интерфейса:

| Значение | Поведение |
| --- | --- |
| `auto` (по умолчанию) | В качестве абсолютного эталона используется прошедшая контроль качества калибровочная мишень в кадре; в качестве резервного варианта используется нисходящее излучение DAQ (ρ = π·L/E) |
| `daq` | Авторитет DAQ |
| `target` | Строгое требование к цели в кадре; замена на данные DAQ не допускается |

См. [Мишени калибровки](../calibration-targets.md) для описания рабочих процессов с мишенями и [главу «LATTICE»](../lattice/README.md), а также [справочник CLI](../reference/cli-reference.md) для ознакомления с полным конвейером обработки. При чтении экспортированных пикселей отражательной способности используйте указанный масштаб (LATTICE: 32768 = ρ 1,0, XMP `Chloros:PixelScale`; Survey3: 65535) — см. [Форматы выходных изображений](../output-image-formats.md).

### Диапазоны, выходящие за пределы откалиброванного диапазона DAQ

Радиометрически откалиброванный диапазон DAQ составляет ~374–974 нм. Chloros отклоняет данные отражательной способности, полученные с помощью DAQ, для любого диапазона камеры, у которого менее половины спектрального веса находится в пределах этого диапазона, сообщая причину пропуска `dls-uncalibrated-band-<nm>`. Среди поставляемых моделей это касается только F988: коэффициент отражения F988 калибруется с помощью панели отражения, установленной в поле обзора; поскольку диапазон лежит за пределами калиброванного диапазона светового датчика DAQ, Chloros применяет данные последней съемки панели и сохраняет их между съемками панели. Если камера F988 работает только в режиме DAQ, код ошибки Chloros отклоняет отражательную способность, основанную на данных DAQ, для этого диапазона с причиной пропуска `dls-uncalibrated-band-988` — поддерживаемым способом является рабочий процесс с использованием панели.

## Двойной датчик (окружающий свет + объект)

Два датчика сбора данных — любая пара, независимо от способа транспортировки — обеспечивают получение спектра отражательной способности в реальном времени без использования камеры: один датчик направлен на небо (**Источник окружающего света**), другой — на объект (**Сканер объекта**), и Chloros вычисляет по каждой длине волны:

> R(λ) = объект(λ) / окружающий свет(λ)

(нулевое значение, если окружающий свет ≤ 0).

### В графическом интерфейсе

После подключения обоих датчиков на вкладке «Световые датчики» откройте всплывающее окно добавления датчика (кнопка «+» на плитке графика в режиме сетки) и выберите **Объединить окружающий свет + объект**. Выберите два датчика в раскрывающихся списках «Источник окружающего света» и «Сканер объекта» и нажмите «Создать». Группа отобразится в виде отдельного графика и строки на боковой панели с зелёным значком**REF**.

Под графиком отражательной способности (режим просмотра списка) в режиме реального времени **таблица индексов растительности** вычисляет индексы на основе кривой, используя центры полос: синий 450, зеленый 550, красный 670 и NIR 800 нм. Индексы, основанные на соотношениях, которые нивелируют абсолютную шкалу (NDVI, GNDVI, ENDVI, WDRVI, GRVI, CVI, GCI, MSR) отображаются всегда; индексы, для которых требуется абсолютная отражательная способность (EVI, SAVI, OSAVI, GSAVI, GOSAVI, MSAVI2, RDVI, TDVI, LAI, NLI, MNLI, FCI, GEMI) отображаются только в том случае, если оба датчика являются моделями с калибровкой по мощности.

### Кажущееся и относительное — правило присвоения меток

Chloros обозначает выходные данные пары датчиков в соответствии с тем, что эта пара датчиков может фактически обеспечить:

| Пара датчиков | Обозначение |
| --- | --- |
| Оба датчика откалиброваны — загружен заводской набор | **Кажущаяся отражательная способность** |
| Хотя бы один датчик не откалиброван | **Относительная отражательная способность** |

Все три модели являются радиометрическими: как только загружен заводской калибровочный набор датчика, его спектры выражаются в абсолютных значениях Вт/м²/нм, поэтому соотношение значений пары откалиброванных датчиков определяет абсолютную кажущуюся отражательную способность — транспортный механизм не влияет на этот показатель. Датчик, по-прежнему передающий необработанные данные (набор недоступен), понижает статус результата до относительной кривой (форма спектра остаётся верной). Оба датчика должны иметь правильно заданные ограничения ([Профили ограничений и откалиброванный диапазон](caps-and-range.md)).

### Из Python

В объединенной поверхности SDK нет специального вызова для работы с двумя датчиками: откройте две сессии с помощью `chloros_sdk.connect_daq_sensor()` и самостоятельно сопоставьте их спектры `latest()`, применяя одинаковую конвенцию маркировки. (Инструмент записи с двумя датчиками также существует на внутреннем прямом аппаратном интерфейсе MAPIR, указанном в [Справочнике по CLI](../reference/cli-reference.md) для полноты информации — он не входит в комплект поставки CLI; описанный выше рабочий процесс с использованием графического интерфейса является поддерживаемым способом работы.)
