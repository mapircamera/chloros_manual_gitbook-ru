# Алгоритмы расчета коэффициента отражения

Датчик освещенности DAQ преобразует радиометрические изображения в коэффициент отражения. Существует два различных алгоритма:

1. **Один датчик** — один датчик DAQ измеряет интенсивность нисходящего излучения, пока камера ведет съемку, а программа Chloros
делит яркость, зафиксированную камерой, на это эталонное значение.
2. **Двухдатчиковый** — два датчика DAQ, один из которых наблюдает за небом, а другой — за объектом, формируют кривую спектрального коэффициента отражения в режиме реального времени без участия камеры.

## Один датчик + камера (нисходящий эталон)

DAQ выступает в роли датчика нисходящего излучения (DLS): камера измеряет восходящее излучение **L**(Вт/м²/стр/нм), DAQ измеряет интенсивность нисходящего излучения**E** (Вт/м²/нм), а Chloros
вычисляет коэффициент отражения по каждому диапазону по формуле:

> ρ = π · L / E

Показания DAQ всегда **синхронизированы по временной метке с экспозицией** — именно поэтому DAQ и камеры используют общий тактовый генератор с синхронизацией по протоколу PTP (см. [Сетевое взаимодействие и синхронизация времени DAQ-E](ethernet-ptp.md)). Наденьте козинусный колпачок Sunshine для работы на открытом воздухе и правильно его задекларируйте; декларация колпачка напрямую влияет на масштабирование E (см. [Профили колпачков и откалиброванный диапазон](caps-and-range.md)). Для количественных измерений помните о характеристиках прибора: количественное значение интенсивности излучения рассчитывается как среднее значение показаний за период не менее 15 с.

### Захват в реальном времени

Свяжите модуль сбора данных (DAQ) с камерой на вкладке «Камеры»: на панели настроек каждой камеры есть раскрывающийся список **Датчик освещенности**, в котором перечислены все подключенные модули сбора данных (DAQ-U/M/E) из вкладки «Датчики освещенности»; для синхронизированной матрицы выбор датчика освещенности для всей матрицы распространяется на каждый элемент (отдельные камеры по-прежнему могут переопределять этот выбор). После привязки спектры датчика поступают в слот DLS камеры, а экспортируемые значения отражательной способности делятся на соответствующее значение датчика. В массиве элемент, имеющий собственный датчик, использует свои собственные показания — для своих полос в композитном изображении в реальном времени, для экспортируемых данных и для автоматической экспозиции, — а остальные элементы используют показания всего массива.

Две особенности, о которых стоит знать:

* **Отсутствие привязки к DAQ → данные о отражательной способности отклоняются, а не подставляются.** Программа Chloros
отклоняет результат расчета отражательной способности и записывает причину пропуска, а не молча возвращает ухудшенный результат.
* **Используемое значение сохраняется.** Для каждого кадра отражательной способности фактически примененное значение DAQ записывается в виде файла `.daq` в папке `daq/` записей, чтобы запись можно было переобрабатывать позже ([Запись и формат .daq](recording.md)). Файл `.daq.cameras.json`, расположенный рядом, указывает камеры, которые он описывает, и при повторной обработке сопоставляется только с изображениями этих камер.

### Обработка записанных изображений

Для обработки после полёта запишите файл `.daq` во время сеанса и сохраните его вместе с изображениями — конвейер автоматически сопоставляет нисходящие потоки данных по временным меткам, загружая при первом использовании любую недостающую заводскую калибровку из облака MAPIR
. Записи из графического интерфейса автоматически добавляются в открытый проект по завершении записи.

Эталон отражательной способности можно выбрать во время обработки — `--reflectance-source` на `chloros-cli process` или настройка «Источник отражательной способности» в «Настройках проекта» графического интерфейса:

| Значение | Поведение |
| --- | --- |
| `auto` (по умолчанию) | Цель калибровки в кадре, прошедшая контроль качества (QA), является абсолютным эталоном; нисходящий поток DAQ (ρ = π·L/E) используется в качестве резервного варианта. Мишень, прошедшая контроль качества с флагом (опущенная панель или неисправная полоса), не выбирается автоматически: цепочки «мишень», «мишень+DAQ» и «только DAQ» пробуются в порядке их оценок, полученных на тестовых панелях. |
| `daq` | Авторитетность DAQ |
| `target` | Строгая мишень в кадре; замена DAQ не допускается |

См. [Калибровочные мишени](../calibration-targets.md) для рабочих процессов с мишенями, а также [главу «LATTICE»](../lattice/README.md), а также [справочник по CLI
](../reference/cli-reference.md) — для ознакомления с полным конвейером обработки. При чтении экспортированных пикселей отражательной способности используйте указанный масштаб (LATTICE: 32768 = ρ 1,0, XMP `Chloros:PixelScale`; Survey3
: 65535) — см. [Форматы выходных изображений](../output-image-formats.md).

### Полосы, выходящие за пределы откалиброванного диапазона DAQ

Радиометрически откалиброванный диапазон DAQ составляет ~374–974 нм. Программа Chloros
отклоняет данные отраженного излучения, полученные с помощью DAQ, для любого диапазона камеры, у которого менее половины спектрального веса находится в пределах этого диапазона, сообщая о причине пропуска `dls-uncalibrated-band-<nm>`. Среди поставляемых моделей это касается только F988: коэффициент отражения F988 калибруется с помощью панели отражения, установленной в поле съёмки: данная полоса лежит за пределами калиброванного диапазона светового датчика DAQ, поэтому Chloros
применяет ваши последние данные с панели и сохраняет их между измерениями панели. Если камера F988 работает только в режиме DAQ, Chloros
отклоняет коэффициент отражения на основе данных DAQ для этого диапазона с причиной пропуска `dls-uncalibrated-band-988` — поддерживаемым способом является использование панели.

## Двойной датчик (окружающее освещение + объект)

Два датчика DAQ — любая пара, независимо от способа транспортировки — обеспечивают спектр отражательной способности в реальном времени без использования камеры: один датчик направлен на небо (**Источник окружающего света**), другой — на объект (**Сканер объекта**), и Chloros
вычисляет значение для каждой длины волны:

> R(λ) = объект(λ) / окружающее освещение(λ)

(нулевое значение, если окружающее освещение ≤ 0).

### В графическом интерфейсе

После подключения обоих датчиков на вкладке «Световые датчики» откройте окно добавления датчика (кнопка «+» на плитке графика в режиме сетки) и выберите **Объединить окружающее освещение + объект**. Выберите два датчика в раскрывающихся списках «Источник окружающего света» и «Сканер объекта» и нажмите «Создать». Группа отобразится в виде отдельного графика и строки на боковой панели с зелёным значком**REF**.

Под графиком отражательной способности (режим просмотра списка) **таблица индексов растительности** в режиме реального времени вычисляет индексы на основе кривой, используя центральные длины волн: синий 450, зелёный 550, красный 670 и NIR
800 нм. Всегда отображаются индексы, основанные на соотношениях, которые нивелируют абсолютную шкалу (NDVI
, GNDVI
, ENDVI, WDRVI
, GRVI
, CVI
, GCI
, MSR), всегда отображаются; индексы, требующие абсолютной отражательной способности (EVI
, SAVI
, OSAVI
, GSAVI, GOSAVI, MSAVI2, RDVI, TDVI, LAI
, NLI, MNLI, FCI, GEMI
), отображаются только в том случае, если оба датчика являются моделями с калибровкой по мощности.

### Кажущаяся отражательная способность против относительной — правило маркировки

Chloros
маркирует выходные данные с двумя датчиками в соответствии с тем, что фактически может обеспечить данная пара датчиков:

| Пара датчиков | Маркировка |
| --- | --- |
| Оба датчика откалиброваны — загружен заводской набор | **Кажущаяся отражательная способность** |
| Хотя бы один датчик не откалиброван | **Относительная отражательная способность** |

Все три модели являются радиометрическими: как только загружен заводской пакет калибровки датчика, его спектры представляют собой абсолютные значения в Вт/м²/нм, поэтому соотношение значений пары откалиброванных датчиков определяет абсолютную кажущуюся отражательную способность — транспортный модуль не влияет на это. Датчик, по-прежнему передающий необработанные данные (набор недоступен), понижает статус результата до относительной кривой (форма спектра остаётся верной). Оба датчика должны иметь правильно заданные ограничения ([Профили ограничений и откалиброванный диапазон](caps-and-range.md)).

### Из Python


В объединенном интерфейсе SDK
нет специального вызова для работы с двумя датчиками: откройте две сессии с помощью `chloros_sdk.connect_daq_sensor()` и самостоятельно сопоставьте их спектры с помощью `latest()`, применяя одинаковую конвенцию именования. (Инструмент записи данных с двух датчиков также существует во внутреннем интерфейсе MAPIR
для прямого доступа к аппаратному обеспечению; он указан в [Справочнике по CLI
](../reference/cli-reference.md) для полноты информации — он не входит в состав поставляемого CLI
; описанный выше рабочий процесс с графическим интерфейсом является поддерживаемым способом работы.)
