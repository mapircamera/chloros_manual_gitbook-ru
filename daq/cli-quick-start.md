# Краткое руководство по работе с CLI (pool-*)

Поставляемые драйверы `chloros-cli` управляют датчиками DAQ с помощью семейства команд **`daq pool-*`** — «тонких» HTTP-клиентов, которые управляют датчиками через постоянный пул датчиков бэкэнда Chloros. Бэкенд управляет транспортом, поэтому графический интерфейс, CLI и скрипты SDK используют один общий активный дескриптор, а не борются за порт. Все, что нужно пользователю, доступно через `pool-*`: подключение, потоковая передача, запись откалиброванных файлов `.daq` и замена профилей капсюлей.

`pool-*` — это поддерживаемый интерфейс сбора данных (DAQ) в выпущенных сборках. Команда `chloros-cli daq --help` выводит список подкоманд `pool-*`, а команды `daq discover` / `daq list` запускают то же сканирование, что и `pool-discover`. Если подкоманда DAQ для прямого доступа к аппаратному обеспечению недоступна, программа завершает работу с явным сообщением об ошибке, в котором указывается отсутствующий пакет и предлагается вернуться к `pool-*` — ничто не завершается без уведомления. (`pip install chloros-sdk` также не предоставляет команд для прямого доступа к аппаратному обеспечению.)

***

## Необходимые условия

* **Бэкенд Chloros должен быть запущен** — команды `pool-*` являются HTTP-клиентами, а не драйверами оборудования. В Windows запустите настольное приложение Chloros (оно запускает бэкенд). На безмониторной системе Linux/Jetson включите службу от имени своего пользователя: `sudo systemctl enable --now chloros-backend@$USER.service` (см. [Установка на Linux](../linux/linux-installation.md#always-on-ptp-for-headless-hosts)).
* **Вход в систему Chloros+ (платный тариф)**: сначала запустите `chloros-cli login`. Проверка аутентификации происходит на стороне сервера — без входа в систему команды завершаются с ошибкой `401 AUTH_REQUIRED`; на бесплатном (Iron) тарифе — с ошибкой `403 PLAN_UPGRADE_REQUIRED`.
* По умолчанию команды нацелены на `http://127.0.0.1:5000`; семейство `daq pool-*` учитывает переменную среды `CHLOROS_BACKEND_URL`, если ваш бэкенд работает в другом месте.

***

## Пятиминутный сеанс

```bash
# 1. Connect a sensor into the backend pool (pick the line matching your model)
chloros-cli daq pool-connect                                  # smart-detect any DAQ
chloros-cli daq pool-connect --port COM3                      # DAQ-U on a specific COM port
chloros-cli daq pool-connect --mac AA:BB:CC:DD:EE:FF          # DAQ-M by BLE MAC
chloros-cli daq pool-connect --eth-host daq-e-def330.local    # DAQ-E by hostname (reliable)
#    (a DAQ-M's BLE MAC is not printed anywhere: find it with `chloros-cli daq pool-discover --only ble`)

# 2. List the pool — this shows the sensor_id used by every command below
chloros-cli daq pool-list

# 3. Read the most recent calibrated spectrum frame (add --json for scripting)
chloros-cli daq pool-latest --sensor-id daq-e-def330 --json

# 4. Record a calibrated .daq file for 60 seconds
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 60 \
  --device-name "field-A"

# 5. Release the sensor when done
chloros-cli daq pool-disconnect --sensor-id daq-e-def330
```

## `pool-connect` — открыть датчик в пуле

| Вариант | Значение |
| --- | --- |
| `daq pool-connect` | Интеллектуальный поиск: найти любой DAQ на этом компьютере. |
| `daq pool-connect --port PORT` | DAQ-U на определённом последовательном порте (например, `COM3`, `/dev/ttyUSB0`). |
| `daq pool-connect --ble` | DAQ-M по BLE, автоматическое сканирование MAC-адресов. |
| `daq pool-connect --mac MAC` | DAQ-M с известным MAC-адресом BLE (подразумевает `--ble`). |
| `daq pool-connect --eth-host HOST` | DAQ-E с известным именем хоста или IP-адресом — **надежный путь**. |
| `daq pool-connect --eth` | DAQ-E с автоматическим обнаружением (mDNS, с резервным использованием ARP). См. предостережение ниже. |

Флаги настройки, все необязательные:

| Флаг | Значение |
| --- | --- |
| `--integration-time MS` / `-t MS` | Время интеграции, задаваемое вручную, в миллисекундах. |
| `--frame-avg N` / `-f N` | Среднее количество кадров на один отчётный спектр. |
| `--no-ae` | Отключить автоматическую экспозицию (по умолчанию включена). |
| `--no-stream` | Установить соединение без запуска потока (возобновить позже с помощью `pool-stream --start`). |
| `--cap-id CAP` | Профиль коррекции капа; по умолчанию для бэкенда используется `sunshine_cosine`. См. [`pool-set-cap`](#pool-set-cap-declare-the-fitted-cap). |

Подключение устройства DAQ-E, которое уже находится в пуле под другим своим адресом — именем хоста `daq-e-<id>.local` или IP-адресом — возвращает существующую запись в пуле вместо повторного открытия устройства.

{% hint style="warning" %}
**Предостережение относительно автоматического обнаружения `--eth`.** На хосте с несколькими сетевыми интерфейсами (более одного активного сетевого интерфейса) *первый* запрос `pool-connect --eth` после загрузки может не дать результата, даже если датчик исправен — процесс обнаружения может пропустить интерфейс датчика, пока кэш ARP не загрузится. Если команда `--eth` ничего не обнаружила, повторите попытку или полностью пропустите обнаружение, используя команду `--eth-host <ip-or-hostname>`, что является надёжным способом на машинах с несколькими сетевыми интерфейсами. Имя хоста DAQ-E — `daq-e-<id>.local` (например, `daq-e-def330.local`); можно использовать и простой IP-адрес.
{% endhint %}

## `pool-discover` — сканирование без подключения

```bash
chloros-cli daq pool-discover                  # USB, BLE and Ethernet
chloros-cli daq pool-discover --only ble       # BLE only: this is how you find a DAQ-M's MAC
chloros-cli daq pool-discover --json           # machine-readable
```

Выполняет сканирование датчиков, к которым можно подключиться, и отображает адрес для подключения, не устанавливая соединения. `--only` принимает подмножество `usb,ble,eth`, разделенное запятыми; `--timeout SEC` устанавливает время сканирования для каждого транспорта (по умолчанию 5 с, ограничено диапазоном 1–20 с). Датчики, уже открытые в пуле, в список не включаются (подключённый DAQ-M перестаёт передавать информацию о себе) — для них используйте `pool-list`. В поставляемой сборке команды `chloros-cli daq discover` и `daq list` выполняют то же самое сканирование.

## `pool-list` — просмотр подключённых устройств

Отображает все датчики в пуле бэкэнда, включая `sensor_id`, необходимый для выполнения всех остальных команд:

| Модель | Формат `sensor_id` | Пример |
| --- | --- | --- |
| DAQ-U / DAQ-M | 5-октетовый с дефисом | `CB-7C-A8-2E-5F` |
| DAQ-E | `daq-e-<6 hex digits>` | `daq-e-def330` |

DAQ-E, у которого PTP отключен (настройка сохраняется в устройстве), помечается в `pool-list` с помощью `!! PTP is switched OFF on this unit (saved in its flash): its timestamps are not PTP-synced.` и команды, которая включает его обратно — см. [`pool-enable-ptp`](#pool-enable-ptp-switch-a-daq-es-ptp-back-on).

## `pool-latest` — чтение кадров спектра

```bash
chloros-cli daq pool-latest --sensor-id daq-e-def330 --recent 10 --json
```

Возвращает самый последний кадр или `--recent N` самых последних кадров; `--json` выводит машиночитаемый вывод для использования в скриптах. Кадры представляют собой радиометрически откалиброванную спектральную освещенность (Вт/м²/нм) на сетке из 135 точек в диапазоне 340–1010 нм с уже примененным профилем крышки датчика. Для получения количественных значений освещенности необходимо усреднить данные как минимум за 15 секунд — это характеристика прибора, а не дефект.

## `pool-stream` — приостановить или возобновить потоковую передачу

```bash
chloros-cli daq pool-stream --sensor-id daq-e-def330 --stop    # pause
chloros-cli daq pool-stream --sensor-id daq-e-def330 --start   # resume
```

## `pool-record` — запись файла `.daq`

```bash
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
  --output ~/Documents/spectra --device-name "rooftop-A"
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--duration SEC` / `-d SEC` | `0` | Продолжительность записи в секундах; `0` означает, что запись будет продолжаться до тех пор, пока не будет выдан сигнал `--stop`. |
| `--output DIR` / `-o DIR` | `~/Documents/DAQ Live View/` | Каталог вывода. При использовании бэкэнда на этом компьютере относительный путь определяется относительно папки, в которой была запущена команда; при использовании удалённого бэкэнда путь определяется **на компьютере, на котором работает бэкэнд**. |
| `--device-name NAME` | — | Метка, сохраняемая вместе с записью. |
| `--stop` | — | Остановить текущую запись. |
| `--confirm-after SEC` | `20` | После запуска ждать до указанного времени, пока не будет записана первая строка, и выдать громкое предупреждение (`!! WARNING: no rows written after …s. This recording is producing an EMPTY file.`), если она не поступит. `0` отключает эту проверку. |
| `--heartbeat SEC` | `30` | С помощью `--duration` выводить количество строк каждые SEC секунд и выдавать предупреждение, если оно перестает расти. `0` отключает эту функцию. |

{% hint style="info" %}
Запись происходит на бэкенде, поэтому файл `.daq` попадает в файловую систему **бэкенд-машины** — по умолчанию в `~/Documents/DAQ Live View/` именно там, а не обязательно там, где вы запустили CLI. Имена файлов включают идентификатор датчика и временную метку.
{% endhint %}

## `pool-set-cap` — указание установленной крышки

```bash
chloros-cli daq pool-set-cap --sensor-id daq-e-def330 --cap-id sunshine_cosine
```

Идентификатор колпачка выбирает измерённый на заводе профиль коррекции, применяемый к каждому спектру, и он **должен соответствовать колпачку, физически установленному на датчике** — ни датчик, ни программное обеспечение не могут самостоятельно обнаружить колпачок, и выбор фиксируется в каждом файле `.daq`. По умолчанию везде используется `sunshine_cosine` (каждый DAQ поставляется с установленной крышкой Sunshine с косинусной коррекцией, обеспечивающей по конструкции ослабление примерно в 12 раз — незаявленная замена крышки приводит к некорректной коррекции спектров примерно на этот коэффициент).

| `--cap-id` | Доступно на |
| --- | --- |
| `sunshine_cosine` (по умолчанию) | DAQ-U, DAQ-M, DAQ-E |
| `fov_15`, `fov_45`, `fov_90` | DAQ-U, DAQ-E |
| `fov_30`, `fov_60` | Только DAQ-U |
| `none` | Только DAQ-E — см. примечание |

Идентификатор крышки, не входящий в набор датчика, отклоняется при подключении с явной ошибкой. `none` (DAQ-E) означает, что крышка физически снята — при этом по-прежнему применяется заводской геометрический профиль для утопленного стеклянного рассеивателя DAQ-E, поэтому это не является «no-op», а DAQ-E без крышки представляет собой лабораторную конфигурацию, а не поддерживаемую полевую конфигурацию. (Дата-приемник DAQ-U без крышки является полностью «голым» и не требует никакого профиля коррекции; дата-приемник DAQ-M используется со своей крышкой Sunshine.)

## `pool-disconnect` — освобождение датчиков

```bash
chloros-cli daq pool-disconnect --sensor-id daq-e-def330   # one sensor
chloros-cli daq pool-disconnect --all                      # everything in the pool
```

`pool-disconnect` освобождает датчик независимо от того, кто его открыл, поэтому он также освобождает датчик, оставленный в пуле сбойным скриптом (при этом сначала завершается запись на нём). Датчик, который не находится в пуле, не может быть освобождён: команда выводит сообщение `<sensor-id>: already released (not in the pool)` и завершает работу с кодом `0`. Освобождение, которое бэкенд отклонил или не подтвердил, завершается с кодом `1`.

## `pool-enable-ptp` — повторное включение PTP на DAQ-E

```bash
chloros-cli daq pool-enable-ptp --sensor-id daq-e-def330
```

DAQ-E хранит настройку включения/выключения PTP в своей собственной памяти, поэтому устройство, PTP которого было выключено, остаётся выключенным — и его временные метки не синхронизируются по PTP — до тех пор, пока его не включат обратно. `pool-list` помечает такое устройство и выводит для него эту команду. Программа Chloros никогда не включает устройство самостоятельно, так как отключение может быть намеренным. Новое в версии 1.3.0.

## Настройки устройства DAQ-E

```bash
chloros-cli daq pool-info --sensor-id daq-e-def330
chloros-cli daq pool-set-network --sensor-id daq-e-def330 \
  --static 192.168.1.50 --gateway 192.168.1.1
chloros-cli daq pool-set-network --sensor-id daq-e-def330 --auto
chloros-cli daq pool-set-auto-stream --sensor-id daq-e-def330 --on
chloros-cli daq pool-reboot --sensor-id daq-e-def330
chloros-cli daq pool-update-firmware --sensor-id daq-e-def330
```

`pool-info` отображает прошивку датчика (а также информацию о том, содержит ли данная версия Chloros более новую прошивку), его адрес и способ его получения, сохраненные сетевые настройки (если они отличаются от текущих), потоковую передачу данных при включении и PTP. `pool-set-network` перезапускает датчик для применения изменений и повторно подключает его с прежними настройками; `--no-reboot` только сохраняет настройки. Статический адрес должен находиться в сети этого компьютера, иначе Chloros отклонит его; команда `--force` отменяет это ограничение, но только для компьютера, которому будет присвоен новый адрес или который будет перенаправлен на него. Перезапуск не допускается во время записи данных датчиком. `pool-update-firmware` — это аналог команды **Update to \<version\>**</version\> из графического интерфейса <version\>для командной строки, а также способ обновления DAQ-E в Linux, где нет графического интерфейса. Новое в версии 1.3.0.***

## Сводка команд

| Команда | Назначение |
| --- | --- |
| `daq pool-connect [--port P \| --ble \| --mac M \| --eth \| --eth-host H] [-t MS] [-f N] [--no-ae] [--no-stream] [--cap-id CAP]` | Открыть датчик в пуле бэкэнда. |
| `daq pool-discover [--only usb,ble,eth] [--timeout SEC] [--json]` | Сканирование датчиков без подключения (поиск MAC-адреса BLE устройства DAQ-M). |
| `daq pool-list` | Отобразить все датчики в пуле с их `sensor_id`. |
| `daq pool-latest --sensor-id ID [--recent N] [--json]` | N последних откалиброванных спектральных фреймов. |
| `daq pool-stream --sensor-id ID [--start \| --stop]` | Возобновление / приостановка потоковой передачи. |
| `daq pool-record --sensor-id ID [-d SEC] [-o DIR] [--device-name NAME] [--confirm-after SEC] [--heartbeat SEC] [--stop]` | Запуск / остановка записи `.daq` (на стороне бэкэнда). |
| `daq pool-set-cap --sensor-id ID --cap-id CAP` | Смена профиля коррекции ограничения во время выполнения. |
| `daq pool-disconnect --sensor-id ID [--all]` | Освобождение одного датчика или всех датчиков. |
| `daq pool-enable-ptp --sensor-id ID` | Включить PTP для DAQ-E, у которого PTP отключен. |
| `daq pool-info --sensor-id ID [--json]` | Прошивка DAQ-E, адрес, сохраненные сетевые настройки, потоковая передача при включении и PTP. |
| `daq pool-set-network --sensor-id ID (--auto \| --static IP [--mask M] [--gateway G]) [--no-reboot] [--force]` | DHCP или статический адрес; перезапускает и повторно подключает датчик. |
| `daq pool-set-auto-stream --sensor-id ID (--on \| --off)` | Потоковая передача данных при включении питания. |
| `daq pool-reboot --sensor-id ID` | Перезапуск DAQ-E и повторное подключение. |
| `daq pool-update-firmware --sensor-id ID` | Запись прошивки DAQ-E из этого выпуска на датчик более старой версии. |

## Устранение неполадок при первом подключении DAQ-E

1. У DAQ-E нет светодиодного индикатора состояния — убедитесь в наличии питания по индикатору PoE/соединения на коммутаторе или порту инжектора и подождите несколько секунд после включения питания, чтобы устройство загрузилось и подключилось к сети.
2. Сервер должен находиться в **том же домене широковещания**, что и датчик — mDNS не проходит через маршрутизаторы.
3. Брандмауэр должен пропускать mDNS (UDP 5353), данные DAQ-E (UDP 5002) и PTP (UDP 319/320). Установщик для Windows добавляет соответствующее правило, а в Linux `.deb` открывает их в `ufw` / `firewalld`, который был активен во время установки; сторонний брандмауэр или брандмауэр, включённый позже, должен разрешить их прохождение.
4. По-прежнему нет ответа от `--eth`? Используйте `--eth-host` с именем хоста устройства (`daq-e-<id>.local`) или его IP-адресом, что позволит обойти процесс обнаружения.
