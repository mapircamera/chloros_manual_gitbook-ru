# Запись и формат .daq

Файл `.daq` — это формат записи данных светового датчика Chloros: **база данных SQLite**, содержащая откалиброванные спектральные кадры, полученные одним датчиком DAQ. Запишите один такой файл во время сеанса съёмки, и конвейер обработки коэффициентов отражения сможет впоследствии поделить каждое изображение на интенсивность нисходящего излучения, измеренную именно в этот момент.

## Что содержит файл .daq

| Свойство | Значение |
| --- | --- |
| Контейнер | База данных SQLite, по одному файлу на датчик на каждую запись |
| Имя файла | Содержит **идентификатор датчика**и**метку времени**, например `daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| Спектр на кадр | 135 точек, 340–1010 нм с шагом 5 нм, плюс тристимульные координаты CIE XYZ |
| Единицы | Калиброванная спектральная интенсивность излучения, **Вт/м²/нм** (применены заводская калибровка и профиль колпачка) |
| Встроенные метаданные | Идентификатор датчика (ключ для получения заводской калибровки данного устройства) и действующий профиль колпачка — см. [Профили колпачков и калиброванный диапазон](caps-and-range.md) |

Формат одинаков для DAQ-U, DAQ-M, DAQ-E и DAQ-E-S, поэтому при последующей обработке не имеет значения, какое устройство сбора данных (DAQ) осуществило запись. В записи DAQ-E-S помимо каждого спектра также сохраняются данные о наклоне, крене и тангаже устройства.

**Записи сохраняются при отключении питания (версия 1.3.0).**Текущая запись записывается с использованием журнала и полной синхронизацией с диском при каждой фиксации, поэтому отключение питания или завершение процесса приводит к потере данных примерно за последние 3 секунды, а не всего файла. Запись, остановленная в середине записи, может оставить файл `<name>.daq-journal` рядом с файлом `.daq`:**сохраните и скопируйте оба файла вместе.** При первом чтении файла программа Chloros откатывает журнал назад. Загруженный диск задерживает запись файла, но никогда не задерживает показания датчика.

**DAQ-E, который перестал передавать данные, подключается заново (версия 1.3.0).** Когда поток данных с DAQ-E прерывается (перезапуск коммутатора, обрыв соединения), бэкенд повторно подключает его с прежними настройками, и запись на нём продолжается в том же файле `.daq` с отметкой пропуска в файле.

Для калиброванной записи требуется пакет заводской калибровки датчика. Для DAQ-U и DAQ-M бэкенд загружает пакет из облака MAPIR по идентификатору датчика (если это невозможно, запись отклоняется); устройства DAQ-E исключаются из этого правила, поскольку они хранят калибровку на самом устройстве.

## Запись через графический интерфейс

Для записи через графический интерфейс необходимо **открыть проект** (в противном случае кнопки записи будут отключены):

* **Запись всего / Остановить всё** — в верхней части боковой панели «Световые датчики»; запускает или останавливает запись `.daq` на всех подключенных датчиках одновременно.
* **Запись / Остановить запись** — для каждого датчика отдельно, в модальном окне настроек (значок шестеренки). Во время записи в строках оперативной информации датчика отображается красный индикатор «REC».

Файлы записываются в `<project>/light_sensor/`, и когда запись останавливается — будь то с помощью кнопок «Остановить», «Остановить всё» или отключения датчика, ведущего запись — готовый файл `.daq` **автоматически добавляется в открытый проект**. Он появляется в списке файлов проекта без необходимости ручного добавления и уже готов к обработке коэффициентов отражения.

## Запись из CLI



CLI осуществляет запись через пул датчиков бэкэнда (бэкенд должен быть запущен — эти команды являются «тонкими» HTTP-клиентами):

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

Получить значение `--sensor-id` из `chloros-cli daq pool-list`. Два значения по умолчанию, о которых стоит знать:

| Параметр | Значение по умолчанию |
| --- | --- |
| `--duration` | `0` — запись до `pool-record --stop` |
| `--output` / `-o` | `~/Documents/DAQ Live View/` в файловой системе **бэкэнда**, а не CLI |

Различие в каталогах вывода имеет значение, когда CLI указывает на бэкенд на другом компьютере: файл попадает туда, где работает бэкенд. Если бэкенд находится на том же компьютере, относительный путь `-o` (например, `./out` выше) преобразуется относительно папки, в которой была запущена команда.

## Запись из Python

: `DAQSensorSession` (возвращаемый `chloros_sdk.connect_daq_sensor()`) предоставляет доступ к той же объединенной записи: `record_start(output_dir=None, device_name=None)` возвращает путь к файлу, а `record_stop()` — `{path, rows}`. См. [Справочник по SDK](../reference/sdk-reference.md) для ознакомления с полным набором API сеансов. Классы SDK, напрямую взаимодействующие с аппаратным обеспечением (только для настольных установок), по умолчанию записывают записи в `~/Documents/DAQ/`; для выпущенных сборок поддерживается указанный выше путь к объединенному пулу.

## Использование файла .daq на этапе обработки

Для расчёта коэффициента отражения по изображениям программе Chloros требуется значение интенсивности нисходящего излучения, сопоставленное с каждой экспозицией:

* **Сохраняйте файл `.daq` вместе с изображениями.**Во время обработки конвейер автоматически определяет**направленное вниз излучение с совпадающей временной меткой** на основе записанного файла `.daq` (любой модели DAQ) — или на основе собственного файла DAQ-M `.csv` — найденного рядом с изображениями. Записи из графического интерфейса пользователя автоматически удовлетворяют этому требованию, поскольку они добавляются в проект сразу после остановки записи.
* **Калибровка загружается по запросу.** Если пакет заводской калибровки для конкретной камеры или DAQ ещё не кэширован локально, Chloros автоматически загружает его из облака MAPIR при первом использовании (требуется однократное подключение к Интернету; кэшируется под именем `~/.chloros/`).
* **Записи в режиме реального времени создают собственный сопутствующий файл.** Для любого кадра отражательной способности, захваченного в режиме реального времени, фактически использованное значение с DAQ сохраняется в виде файла `.daq` в папке `daq/` с данными захвата, что позволяет впоследствии повторно обработать запись без исходного файла.
* **Записи с регистраторов `chloros_scripts` (версия 1.3.0).**Файл `.daq`, записанный общедоступными регистраторами [`chloros_scripts`](https://github.com/mapircamera/chloros_scripts), указывается в качестве модели DAQ, которая его создала, и его ограничение можно установить в**«Настройки проекта» → «Датчик освещенности DAQ»**, как и для любой другой записи. Эти регистраторы записывают необработанные данные датчика; Chloros извлекает заводскую калибровку датчика по последовательному интерфейсу и применяет её.
* **Чьи это показания (1.3.0).**Рядом с каждым захватом `.daq` указано имя камеры (камер) `.daq.cameras.json`, кадры которой (которых) описывает данное значение, и обработка сопоставляет его**только с изображениями с этих камер**. Таким образом, автономная камера, не имеющая собственного датчика освещённости, больше не использует показания другой камеры — к ней нужно привязать датчик или записать собственные данные. Запись, сделанная с помощью самого DAQ (GUI Record, `daq pool-record`), а также любой файл `.daq` без этого файла (включая старые записи), по-прежнему обслуживает каждую камеру.

## Извлечение данных об освещенности

Обработка проекта также экспортирует все имеющиеся в нём записи датчиков освещённости в папку
`Light Sensor/` рядом с изображениями. Для этого **не** требуются изображения:
запись датчика освещённости сама по себе является полным набором данных, а папка, содержащая только файлы `.daq`,
является допустимым входным материалом. Проект, содержащий только записи датчиков освещённости, отображает их список и
обрабатывает как из приложения, так и из CLI, и они остаются в списке после завершения запуска. Отчёт о запуске
указывает, сколько продуктов датчиков освещённости было записано.

| Продукт | Что это |
| --- | --- |
| `<name>_calibrated.daq` | Архив, поддающийся повторной обработке, по той же схеме, что и запись в реальном времени, теперь с указанием пакета калибровки, с помощью которого он был создан. Повторный импорт **не** приводит к повторной калибровке. |
| `<name>_calibrated.csv` | Спектральная интенсивность излучения в Вт/м²/нм по собственной сетке длин волн датчика, по одной строке на каждое измерение, плюс фотометрические столбцы: общая мощность, фотопические и скотопические люксы, PPFD с разбивкой по синему, зелёному и красному спектрам, а также пиковая длина волны. |

DAQ-U или DAQ-M, пакет калибровки которого невозможно загрузить — вы находитесь в автономном режиме или
для данного датчика в файле отсутствует калибровка — **пропускается с указанием причины** и никогда не записывается
в виде «откалиброванного» файла, содержащего необработанные данные. Подключитесь к Интернету и запустите процесс заново. DAQ-E
имеет собственную калибровку, поэтому она требуется только в том случае, если устройство не подключено и
локально ничего не кэшировано.

### DAQ-A: необработанные отсчёты и почему это правильный подход

**DAQ-A** появился до внедрения системы калибровочных пакетов для каждого серийного номера и не имеет пакета, который
нужно загрузить. Это не упущение: DAQ-A калибруется в полевых условиях по
мишени отражательной способности, а для калибровки по мишени требуется только *относительная*
чувствительность датчика — а это именно то, чем являются его исходные отсчёты. Компания Chloros и сегодня использует их для калибровки.

Таким образом, запись DAQ-A экспортируется, но под другим именем:

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw`, а не `_calibrated` — это другое имя файла, а не флаг внутри файла,
поскольку информация должна сохраняться при отправке файла по электронной почте в виде простого имени. Заголовок `.csv`
указывает `raw spectral sensor counts (NOT irradiance)` и предупреждает, что значения
сопоставимы **в пределах** файла, но не между датчиками. Столбцы, которые имеют значение
только для реальной интенсивности излучения — общая мощность, люкс, PPFD — остаются пустыми, а не
вычисляются на основе количества импульсов.

Более старые записи DAQ-A-SD (схема v1.01 / v1.02) фиксируют только время записи файла, а не
временную метку для каждого считывания. Chloros не будет сопоставлять изображения с этими данными — сопоставление кадра с
временем записи было бы неверным, хотя на первый взгляд и не выглядело бы так — но экспорт читает их нормально, и
в CSV-файле указано, к какому таймеру они относятся.

Полную информацию о работе с коэффициентом отражения — с одним датчиком и камерой, а также с двумя датчиками (окружающая среда/объект) — см. в разделе [Рабочие процессы с коэффициентом отражения](reflectance.md).
