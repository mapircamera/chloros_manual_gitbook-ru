# Запись и формат .daq

Файл `.daq` представляет собой формат записи данных светового датчика Chloros: **база данных SQLite**, содержащая откалиброванные спектральные кадры, полученные одним датчиком DAQ. Запишите один такой файл во время сеанса съёмки, и конвейер обработки коэффициентов отражения сможет впоследствии поделить каждое изображение на интенсивность нисходящего излучения, измеренную именно в этот момент.

## Что содержит файл .daq

| Свойство | Значение |
| --- | --- |
| Контейнер | База данных SQLite, по одному файлу на датчик на запись |
| Имя файла | Содержит **идентификатор датчика**и**метку времени**, например `daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| Спектр на кадр | 135 точек, 340–1010 нм с шагом 5 нм, плюс тристимульные координаты CIE XYZ |
| Единицы | Калиброванная спектральная интенсивность излучения, **Вт/м²/нм** (применены заводская калибровка + профиль колпачка) |
| Встроенные метаданные | Идентификатор датчика (ключ для получения заводской калибровки данного устройства) и действующий профиль крышки — см. [Профили крышек и калиброванный диапазон](caps-and-range.md) |

Формат одинаков для DAQ-U, DAQ-M и DAQ-E, поэтому при последующей обработке не имеет значения, какое устройство передачи данных осуществило запись.

Для калиброванной записи требуется пакет заводской калибровки датчика. Для DAQ-U и DAQ-M бэкенд извлекает пакет из облака MAPIR по идентификатору датчика (если это невозможно, запись отклоняется); устройства DAQ-E не подпадают под это требование, поскольку хранят данные калибровки на самом устройстве.

## Запись через графический интерфейс

Для записи через графический интерфейс пользователя необходимо **открыть проект** (в противном случае кнопки записи будут отключены):

* **Запись всего / Остановить всё** — в верхней части боковой панели «Световые датчики»; запускает или останавливает запись `.daq` на всех подключенных датчиках одновременно.
* **Запись / Остановить запись** — для каждого датчика отдельно, в модальном окне настроек (значок шестеренки). Во время записи в строках оперативной информации датчика отображается красный индикатор «REC».

Файлы записываются в `<project>/light_sensor/`, и когда запись останавливается — будь то с помощью кнопок «Остановить», «Остановить всё» или отключения датчика записи — готовый файл `.daq` **автоматически добавляется в открытый проект**. Он появляется в списке файлов проекта без необходимости ручного добавления и уже готов к обработке отражательной способности.

## Запись с датчика CLI

CLI осуществляет запись через пул датчиков бэкэнда (бэкенд должен быть запущен — эти команды являются «тонкими» клиентами HTTP):

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

Получить значение `--sensor-id` из `chloros-cli daq pool-list`. Два значения по умолчанию, о которых стоит знать:

| Параметр | Значение по умолчанию |
| --- | --- |
| `--duration` | `0` — записывать до `pool-record --stop` |
| `--output` / `-o` | `~/Documents/DAQ Live View/` в файловой системе **бэкенда**, а не CLI |

Различие в каталогах вывода имеет значение, когда CLI нацелен на бэкенд на другом компьютере: файл попадает туда, где работает бэкенд.

## Запись из Python

`DAQSensorSession` (возвращаемый `chloros_sdk.connect_daq_sensor()`) предоставляет доступ к той же записи из пула: `record_start(output_dir=None, device_name=None)` возвращает путь к файлу, а `record_stop()` — `{path, rows}`. См. [Справочник по SDK](../reference/sdk-reference.md) для полной сессии API. Классы прямого доступа к аппаратному обеспечению SDK (только для настольных установок) по умолчанию записывают записи в `~/Documents/DAQ/`; для выпущенных сборок поддерживается указанный выше общий путь.

## Использование файла .daq на этапе обработки

Для расчёта коэффициента отражения по изображениям Chloros требуется значение интенсивности излучения, направленного вниз, соотнесённое с каждой экспозицией:

* **Храните файл `.daq` вместе с изображениями.**Во время обработки конвейер автоматически определяет**направленную вниз интенсивность излучения, совпадающую по временной метке**, на основе записанного файла `.daq` (любой модели DAQ) — или из собственного файла DAQ-M `.csv` — находящегося рядом с изображениями. Записи из графического интерфейса пользователя автоматически удовлетворяют этому требованию, поскольку они добавляются в проект сразу после остановки.
* **Калибровка загружается по запросу.** Если пакет заводской калибровки для конкретной камеры или DAQ ещё не кэширован локально, файл Chloros автоматически загружает его из облака MAPIR при первом использовании (требуется однократное подключение к Интернету; кэшируется под `~/.chloros/`).
* **При захвате в реальном времени создаётся собственный файл-сайдкар.** Для любого кадра отражательной способности, захваченного в реальном времени, фактически использованное значение с DAQ сохраняется в виде файла-сайдкара `.daq` рядом с изображением, что позволяет впоследствии повторно обработать захват без исходной записи.

## Извлечение данных об интенсивности излучения

При обработке проекта также экспортируются все содержащиеся в нём записи датчиков освещённости в
папку `Light Sensor/`, расположенную рядом с изображениями. Для этого **не** требуются изображения:
световой датчик, запущенный отдельно, представляет собой полную запись, а папка, содержащая только файлы `.daq`,
является допустимым входным материалом. Отчет о запуске указывает, сколько продуктов светового датчика было записано.

| Продукт | Что это |
| --- | --- |
| `<name>_calibrated.daq` | Архив, поддающийся повторной обработке, в той же схеме, что и запись в реальном времени, теперь с указанием пакета калибровки, с помощью которого он был создан. Повторный импорт **не** приводит к повторной калибровке. |
| `<name>_calibrated.csv` | Спектральная интенсивность излучения в Вт/м²/нм по собственной сетке длин волн датчика, по одной строке на каждое измерение, плюс фотометрические столбцы: суммарная мощность, фотопические и скотопические люксы, PPFD с разбивкой по синему, зелёному и красному спектрам, а также пиковая длина волны. |

DAQ-U или DAQ-M, калибровочный пакет которого невозможно загрузить — вы находитесь в автономном режиме или
для данного датчика в файле отсутствует калибровка — **пропускается с указанием причины** и никогда не записывается
в виде «откалиброванного» файла, содержащего необработанные отсчёты. Подключитесь к Интернету и запустите процедуру заново. DAQ-E
имеет собственную калибровку, поэтому она требуется только в том случае, если устройство не подключено и
локально ничего не кэшировано.

### DAQ-A: необработанные отсчёты и почему это правильный подход

**DAQ-A** появился до внедрения системы калибровочных пакетов для каждого серийного номера и не имеет пакета, который
нужно загрузить. Это не упущение: DAQ-A калибруется в полевых условиях по
мишени отражения, а для калибровки по мишени требуется только *относительная*
характеристика датчика — а это именно то, чем являются его исходные отсчёты. Chloros калибруется с их помощью и сегодня.

Таким образом, запись DAQ-A экспортируется, но под другим именем:

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw`, а не `_calibrated` — это другое имя файла, а не флаг внутри файла,
поскольку информация должна сохраняться при отправке файла по электронной почте в виде простого имени. Заголовок `.csv`
указывает на `raw spectral sensor counts (NOT irradiance)` и предупреждает, что значения
сопоставимы **в пределах** файла, но не между датчиками. Столбцы, которые имеют значение
только для реальной интенсивности излучения — суммарная мощность, люкс, PPFD — остаются пустыми, а не
вычисляются на основе импульсов.

Более старые записи DAQ-A-SD (схема v1.01 / v1.02) фиксируют только время записи файла, а не
временную метку для каждого считывания. Chloros не будет сопоставлять изображения с этими данными — сопоставление кадра с
временем записи было бы неверным, хотя на первый взгляд и не выглядело бы так — но экспорт читает их нормально, и
CSV указывает, к какому тактовому генератору он относится.

Полную информацию о рабочих процессах с отражательной способностью — с одним датчиком и камерой, а также с двумя датчиками (окружающая среда/объект) — см. в разделе [Рабочие процессы с отражательной способностью](reflectance.md).
