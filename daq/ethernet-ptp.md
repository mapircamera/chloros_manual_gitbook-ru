# Сетевые настройки и синхронизация времени DAQ-E

> Информация о физической настройке сети для датчика — прокладке кабелей, PoE, присвоении IP-адреса и собственных сетевых настройках устройства — приведена в **[руководстве пользователя DAQ](https://mapir.gitbook.io/daq/daq-e/network-setup)**. На этой странице рассматриваются аспекты, связанные с Chloros

: подключение, синхронизация времени и действия в случае, если обнаружение не дало результатов.

DAQ-E — это Ethernet-устройство из семейства DAQ: питание через PoE, обнаружение через mDNS (служба `_daq-e._tcp`) и адресация по имени хоста, образованному на основе его идентификатора датчика — `daq-e-<6 hex>.local`, например, `daq-e-def330.local`. На этой странице описано, как устройство передаёт данные по сети и как участвует в синхронизации времени по протоколу PTP.

## Режимы передачи

| Режим | Конечная точка | Потребители | Примечания |
| --- | --- | --- | --- |
| **Многоадресная рассылка** (по умолчанию) | UDP `239.10.10.10:5002` | Любое количество устройств в одной локальной сети получает один и тот же поток | Каждая датаграмма проверяется с помощью CRC-16/CCITT |
| **Raw** | TCP-порт `5000` | Ровно один клиент (исключительно) | Полная байтовая совместимость с DAQ-U |

Chloros

по умолчанию использует многоадресную рассылку, что позволяет графическому интерфейсу, интерфейсу командной строки (CLI

) и набору средств разработки (SDK

) одновременно отслеживать один датчик.

## Требования к сети

* **Один и тот же домен широковещания.** Компьютер, на котором работает Chloros

, должен находиться в том же сегменте сети уровня 2, что и датчик — обнаружение mDNS не проходит через маршрутизаторы.
* **Брандмауэр.** В Windows

установщик добавляет правило брандмауэра **Chloros

Backend (UDP-In)**для бэкэнда во все сетевые профили; оно охватывает данные DAQ-E (UDP 5002), mDNS (UDP 5353) и PTP (UDP 319/320), а также правило**«Chloros

Backend (TCP-In)»**, ограниченное локальной подсетью, для соединения, которое DAQ-E устанавливает с компьютером во время обновления прошивки. В Linux

`.deb` открывает UDP-порты в `ufw` или `firewalld`, если этот брандмауэр активен во время установки. Для брандмауэра стороннего производителя или брандмауэра, включенного позже, необходимо разрешить те же порты.
* **Питание по PoE, отсутствие светодиодного индикатора состояния.** У DAQ-E нет собственного светодиодного индикатора — проверьте наличие питания по индикатору Link/PoE на коммутаторе или порту инжектора и подождите несколько секунд после включения питания, чтобы устройство загрузилось и подключилось к сети.

## Подключение

**Графический интерфейс:** Вкладка «Датчики освещенности» → «Подключить датчик» → Тип устройства «DAQ-E (Ethernet)». Поиск датчиков выполняется только пока диалоговое окно подключения открыто (просмотр mDNS плюс ARP-сканирование в Windows

), повторяясь каждые 15 секунд; кнопка «Обновить» запускает повторный поиск немедленно. Обнаруженные датчики появляются в раскрывающемся списке; первый обнаруженный датчик выбирается автоматически.

<!-- SCREENSHOT-NEEDED: DAQ connect dialog with Device Type set to "DAQ-E (Ethernet)" and at least one discovered sensor listed in the Hostname/IP dropdown (e.g. daq-e-xxxxxx.local), Connect button enabled. -->

**CLI** (работающий бэкенд):

```bash
chloros-cli daq pool-connect --eth                              # auto-discover on the LAN
chloros-cli daq pool-connect --eth-host daq-e-def330.local      # explicit host — the reliable form
chloros-cli daq pool-connect --eth-host 192.168.1.57            # a plain IP works too
```

DAQ-E, уже находящийся в пуле, распознаётся как по имени хоста, так и по IP-адресу: повторное подключение по другому адресу возвращает существующую запись в пуле, а не открывает устройство во второй раз.

### Хосты с несколькими сетевыми картами и первое подключение после загрузки

На хостах с более чем одним активным сетевым интерфейсом **первое** подключение `pool-connect --eth` после загрузки может завершиться безрезультатно, даже если датчик исправен — процесс обнаружения может пропустить интерфейс, на котором находится датчик, пока кэш ARP ещё не загружен. Надежным способом решения этой проблемы является пропуск обнаружения и явное указание адреса:

```bash
chloros-cli daq pool-connect --eth-host daq-e-def330.local
```

`--eth-host` принимает имя хоста mDNS или IP-адрес, всегда нацеливается на нужный датчик и является рекомендуемым вариантом для скриптов и установок без графического интерфейса. В графическом интерфейсе воспользуйтесь кнопкой «Обновить» в диалоговом окне подключения и дождитесь завершения цикла повторного сканирования.

## Настройки устройства и прошивка

Сам датчик хранит свои сетевые настройки: DHCP (заводская настройка, при отсутствии ответа от DHCP-сервера используется локальный адрес 169.254.x.x) или статический адрес. Он также хранит информацию о том, начинает ли он передачу данных при включении питания. Измените эти настройки в графическом интерфейсе (в настройках датчика, значок шестеренки, **Сеть**:**Изменить…**,**Потоковая передача при включении**,**Перезапустить датчик**; см. [Вкладку «DAQ»](gui.md)), либо через интерфейс командной строки (CLI

) и набор средств разработки (SDK

) с помощью команд `pool-set-network`, `pool-set-auto-stream` и `pool-reboot` (`DAQSensorSession.set_network()`, `set_auto_stream()`, `reboot()`; см. [Справочник по CLI

](../reference/cli-reference.md#daq-e-device-settings)). Датчик перезапускается для применения изменений в сети, и Chloros

повторно подключается к нему. Статический адрес должен находиться в сети компьютера, на котором запущен Chloros

: Chloros

отклоняет адрес, к которому не смог подключиться после перезапуска. Идентификатор датчика и его имя хоста `daq-e-<id>.local` никогда не меняются. Новое в версии 1.3.0.

**Функция обновления прошивки встроена в графический интерфейс пользователя.** Если подключённый DAQ-E работает на прошивке, более старой, чем образ, входящий в комплект вашей сборки Chloros

, в строке этого датчика отображается жёлтый значок **«Доступно обновление»**, а в модальном окне настроек в виде шестеренки появляется <version>кнопка</version>

«Обновить до<version>». Обновление передаётся по сети примерно за 30 секунд; датчик перезапускается и автоматически подключается заново, а в случае прерывания передачи текущая версия прошивки остаётся неизменной. Из командной строки (CLI) или с помощью SDK, а также в Linux, где нет графического интерфейса, запустите команду `chloros-cli daq pool-update-firmware --sensor-id <id>` (`DAQSensorSession.update_firmware()`).

## Синхронизация времени по PTP

Прошивка DAQ-E версии 1.2.0+ участвует в стандарте IEEE 1588 PTPv2 в качестве обычного (только ведомого) генератора тактовой частоты. **Бэкенд хоста Chloros является главным часовым генератором PTP** — каждый DAQ-E и каждая камера LATTICE в локальной сети синхронизируются с ним в домене 0, поддерживая все временные метки устройств с погрешностью ~1 мс. Именно благодаря этому общему генератору времени показания DAQ можно сопоставить по временным меткам с экспозициями камеры (см. [Запись и формат .daq](recording.md)).

Проверьте синхронизацию через интерфейс CLI:

| Команда | Отображает |
| --- | --- |
| `chloros-cli time-sync status` | Состояние главного генератора хоста, приоритеты BMCA, идентификатор тактового генератора, а также `health`: `OK` или `SENDS_FAILING` / `DEGRADED` / `NO_SOCKETS` / `PEERS_SILENT` с указанием причины, по которой его пакеты не доходят до сети |
| `chloros-cli time-sync peers` | Все обнаруженные подчиненные устройства (датчики DAQ-E + камеры LATTICE) |
| `chloros-cli time-sync cameras` | Состояние PTP для каждой камеры (`PtpStatus`, `PtpOffsetFromMaster`, `PtpMeanPathDelay`) |
| `chloros-cli time-sync restart` | Перезапуск процесса «grandmaster» |

В графическом интерфейсе пользователя (GUI) в модальном окне настроек DAQ-E отображается строка **PTP Sync** в режиме реального времени с текущим состоянием PTP датчика.**DAQ-E с отключенным PTP остаётся в этом состоянии.** Устройство сохраняет настройку включения/выключения PTP в своей собственной памяти, поэтому устройство, у которого PTP был отключён, остаётся в этом состоянии после повторного подключения или перезапуска, и его временные метки не синхронизируются по PTP. `chloros-cli daq pool-list` помечает такое устройство (`!! PTP is switched OFF on this unit …`) и выводит команду, устраняющую эту проблему:

```bash
chloros-cli daq pool-enable-ptp --sensor-id daq-e-def330
```

Chloros никогда не включает устройство самостоятельно, поскольку отключение может быть намеренным.

Подробная информация для пользователей, требующих строгой синхронизации:

* Каждый передаваемый датаграмм содержит поле флагов; **бит 2 устанавливается в кадрах, временные метки которых синхронизированы по PTP**. Конвейеры, требующие строгой синхронизации камеры и системы сбора данных (DAQ), должны использовать этот бит в качестве триггера.
* Перед синхронизированной съемкой убедитесь, что датчик отображается в `chloros-cli time-sync peers` и что `chloros-cli daq pool-list` не помечает его PTP как отключенный. (Внутренние инструменты MAPIR, напрямую взаимодействующие с аппаратным обеспечением, также могут синхронизировать запись по фиксации PTP с помощью флага `--wait-ptp`, который ожидает до 15 с, пока датчик не перейдёт в состояние SLAVE; эти инструменты не входят в состав поставляемого CLI.)
* Пока PTP активно работает в режиме ведомого устройства, датчик отклоняет ручные попытки синхронизации («PTP обеспечивает тактовую частоту»). Это предусмотрено конструкцией — доверяйте PTP.

## Примечания по Linux

* **Порты PTP без прав root.** PTP привязывается к UDP 319/320. `.deb` записывает `/etc/sysctl.d/60-chloros-ptp.conf` (`net.ipv4.ip_unprivileged_port_start = 319`), поэтому бэкенд привязывает их, работая под вашим пользователем. Начиная с версии 1.3.0 пакет не устанавливает на бэкенде файловую способность (`setcap`) и не требует `libcap2-bin`; не добавляйте эту способность самостоятельно, так как в этом случае распакованный бэкенд не запустится. Если PTP не может привязаться к порту 319, см. [Установка в Linux](../linux/linux-installation.md#ptp-will-not-start--cannot-bind-port-319).

* **Jetson без монитора / хост с Linux:** пакет устанавливает службы бэкенда, но не включает ни одну из них. Для обеспечения постоянной работы PTP (и доступности DAQ) без необходимости запуска команды пользователем включите службу от имени своего пользователя:

  ```bash
  sudo systemctl enable --now chloros-backend@$USER.service    # $USER expands to your user name
  ```

  Без этого PTP работает только тогда, когда что-то запустило бэкэнд — команда `chloros-cli` или скрипт SDK. См. [Установка в Linux](../linux/linux-installation.md#always-on-ptp-for-headless-hosts) для получения информации о пользователе root `chloros-backend.service` и о том, как переключиться с него.

## Устранение неполадок: «Не найдено устройств DAQ-E»

| Проверка | Подробности |
| --- | --- |
| Питание | Светодиод на датчике не горит — проверьте индикаторы PoE и связи на коммутаторе/порте инжектора; подождите несколько секунд после включения питания |
| Домен широковещания | Хост и датчик находятся в одном сегменте L2; mDNS не маршрутизируется |
| Брандмауэр | Windows: правило **Chloros Backend (UDP-In)** установщика пропускает поток DAQ-E (UDP 5002), mDNS (5353) и PTP (319/320); для стороннего брандмауэра требуются такие же настройки. Linux: `.deb` открывает эти порты в `ufw` / `firewalld` только в том случае, если брандмауэр был активен во время установки — разрешите их самостоятельно в одном из включенных позже |
| Хост с несколькими сетевыми картами | Функция обнаружения просматривает mDNS с резервным использованием ARP; `--eth-host <ip-or-hostname>` пропускает обнаружение и подключается напрямую |
| Повторное сканирование в графическом интерфейсе | Функция обнаружения работает только при открытом диалоговом окне подключения; используйте кнопку «Обновить» |</version>
