# Сетевые настройки и синхронизация времени DAQ-E

> Информация о физической настройке сети для датчика — прокладка кабелей, PoE, присвоение IP-адреса и собственные сетевые настройки устройства — приведена в **[руководстве пользователя DAQ](https://mapir.gitbook.io/daq/daq-e/network-setup)**. На этой странице рассматриваются аспекты, связанные с Chloros: подключение, синхронизация времени и действия в случае, если обнаружение не дало результатов.

DAQ-E — это Ethernet-устройство семейства DAQ: питание через PoE, обнаружение через mDNS (служба `_daq-e._tcp`) и адресация по имени хоста, образованному на основе идентификатора датчика — `daq-e-<6 hex>.local`, например, `daq-e-def330.local`. На этой странице описано, как устройство передаёт данные по сети и как участвует в синхронизации времени по протоколу PTP.

## Режимы передачи

| Режим | Конечная точка | Потребители | Примечания |
| --- | --- | --- | --- |
| **Многоадресная рассылка** (по умолчанию) | UDP `239.10.10.10:5002` | Любое количество устройств в той же локальной сети получает один и тот же поток | Каждая датаграмма проверяется с помощью CRC-16/CCITT |
| **Raw** | TCP-порт `5000` | Ровно один клиент (исключительно) | Полная байтовая совместимость с DAQ-U |

Chloros по умолчанию использует многоадресную рассылку, что позволяет графическому интерфейсу, CLI и SDK одновременно отслеживать один датчик.

## Требования к сети

* **Один и тот же домен широковещания.** Компьютер, на котором запущен Chloros, должен находиться в том же сегменте сети уровня 2, что и датчик — обнаружение mDNS не проходит через маршрутизаторы.
* **Запрос брандмауэра Windows: разрешите его.** При первом привязывании Chloros сокетов многоадресной рассылки Defender Windows запрашивает разрешение один раз. Разрешение этого запроса охватывает данные DAQ-E (UDP 5002), mDNS (UDP 5353) и PTP (UDP 319/320). В Linux это происходит без уведомления.
* **Питание по PoE, светодиод состояния отсутствует.** У DAQ-E нет собственного светодиода — проверьте наличие питания по индикатору Link/PoE на коммутаторе или порте инжектора и подождите несколько секунд после включения питания, чтобы устройство загрузилось и подключилось к сети.

## Подключение

**Графический интерфейс:** Вкладка «Датчики освещенности» → «Подключить датчик» → Тип устройства «DAQ-E (Ethernet)». Поиск датчиков выполняется только пока диалоговое окно подключения открыто (просмотр mDNS плюс ARP-сканирование по адресу Windows), повторяясь каждые 15 секунд; нажатие кнопки «Обновить» запускает повторный поиск немедленно. Обнаруженные датчики появляются в раскрывающемся списке; автоматически выбирается первый обнаруженный датчик.

**CLI** (бекенд запущен):

```bash
chloros-cli daq pool-connect --eth                              # auto-discover on the LAN
chloros-cli daq pool-connect --eth-host daq-e-def330.local      # explicit host — the reliable form
chloros-cli daq pool-connect --eth-host 192.168.1.57            # a plain IP works too
```

### Хосты с несколькими сетевыми адаптерами и первое подключение после загрузки

На хостах с более чем одним активным сетевым интерфейсом **первый** запрос `pool-connect --eth` после загрузки может не дать результата, даже если датчик исправен — процесс обнаружения может пропустить интерфейс, на котором находится датчик, пока кэш ARP ещё не загружен. Надёжным решением является пропуск сканирования и явное указание адреса:

```bash
chloros-cli daq pool-connect --eth-host daq-e-def330.local
```

`--eth-host` принимает имя хоста mDNS или IP-адрес, всегда нацеливается на нужный датчик и является рекомендуемым вариантом для скриптов и установок без графического интерфейса. В графическом интерфейсе воспользуйтесь кнопкой «Обновить» в диалоговом окне подключения и дождитесь завершения цикла повторного сканирования.

## Настройки устройства и прошивка

Сам датчик хранит сетевые настройки — статический IP или DHCP + локальная адресация, имя устройства, автоматический запуск потока при загрузке, пароль для OTA-обновления. Эти настройки на стороне устройства не доступны в виде команд в поставляемом CLI; ими управляют через графический интерфейс Chloros, где они отображаются, или с помощью службы поддержки MAPIR.

**Функция обновления прошивки встроена в графический интерфейс.**Если подключённый DAQ-E работает под управлением прошивки, более старой, чем образ, входящий в комплект вашей сборки Chloros, в строке датчика отображается янтарный значок**«Доступно обновление»**, а в модальном окне настроек в виде шестеренки появляется<version>

кнопка</version> «Обновить до<version>

». Обновление передаётся по сети примерно за 30 секунд; датчик автоматически перезапускается и повторно подключается, а в случае прерывания передачи текущая версия прошивки остаётся неизменённой.

## Синхронизация времени по PTP

Прошивка DAQ-E версии 1.2.0+ и выше участвует в стандарте IEEE 1588 PTPv2 в качестве обычного (только ведомого) генератора тактовой частоты. **Бэкенд хоста Chloros является главным часовым сервером PTP** — каждый DAQ-E и каждая камера LATTICE в локальной сети подчиняются ему в домене 0, поддерживая все временные метки устройств с погрешностью ~1 мс. Именно этот общий генератор времени позволяет сопоставлять временные метки показаний DAQ с экспозициями камер (см. [Запись и формат .daq](recording.md)).

Проверьте синхронизацию по CLI:

| Команда | Показывает |
| --- | --- |
| `chloros-cli time-sync status` | Состояние главного генератора хоста, приоритеты BMCA, идентификатор часов |
| `chloros-cli time-sync peers` | Все обнаруженные подчиненные устройства (датчики DAQ-E + камеры LATTICE) |
| `chloros-cli time-sync cameras` | Состояние PTP для каждой камеры (`PtpStatus`, `PtpOffsetFromMaster`, `PtpMeanPathDelay`) |
| `chloros-cli time-sync restart` | Перезапуск процесса главного сервера |

В графическом интерфейсе пользователя (GUI) в модальном окне настроек DAQ-E отображается строка **PTP Sync** в режиме реального времени с текущим состоянием PTP датчика.

Подробная информация для потребителей, требующих строгой синхронизации:

* Каждая передаваемая датаграмма содержит поле флагов; **бит 2 устанавливается в кадрах, временная метка которых синхронизирована по PTP**. Конвейеры, требующие строгой синхронизации камеры и DAQ, должны использовать этот бит в качестве триггера.
* Перед синхронизированной съемкой убедитесь, что датчик отображается в списке `chloros-cli time-sync peers`. (Внутренние средства прямого аппаратного управления MAPIR также могут синхронизировать запись по фиксации PTP с помощью флага `--wait-ptp`, который ожидает до 15 с, пока датчик не перейдёт в состояние SLAVE; этот механизм не входит в состав поставляемого CLI.)
* Пока PTP активно работает в режиме подчинения, датчик отклоняет ручные попытки подачи тактовой частоты («PTP обеспечивает тактовую частоту»). Это предусмотрено конструкцией — доверяйте PTP.

## Примечания по Linux

* **Для PTP требуется `libcap2-bin` при установке.** Скрипт `.deb` postinst предоставляет права `cap_net_bind_service=+ep` на `/usr/lib/chloros/chloros-backend`, чтобы он мог привязывать порты PTP 319/320 без прав root. Если файл `libcap2-bin` отсутствует, этот шаг пропускается, и PTP не запустится. Решение:

  ```bash
  sudo apt install libcap2-bin
  sudo apt reinstall chloros
  ```

* **Jetson / Raspberry Pi без монитора:** при первой установке модуль systemd `chloros-backend.service` создается, но не включается. Для постоянного функционирования PTP (и доступности DAQ) без графического интерфейса:

  ```bash
  sudo systemctl enable --now chloros-backend.service
  ```

  Без него PTP работает только при открытом графическом интерфейсе Chloros.

## Устранение неполадок: «Не найдено устройств DAQ-E»

| Проверка | Подробности |
| --- | --- |
| Питание | Светодиод на датчике не горит — проверьте индикаторы PoE и связи на коммутаторе/порте инжектора; подождите несколько секунд после включения питания |
| Домен широковещания | Хост и датчик находятся в одном сегменте L2; mDNS не маршрутизируется |
| Брандмауэр Windows | При первом запуске подтвердите запрос Defender (UDP 5002, 5353, 319/320) |
| Хост с несколькими сетевыми картами | При первом обнаружении после загрузки датчик может не быть найден — подключитесь с помощью `--eth-host <ip-or-hostname>` |
| Повторное сканирование в графическом интерфейсе | Обнаружение выполняется только при открытом диалоговом окне подключения; используйте кнопку «Обновить» |</version>
