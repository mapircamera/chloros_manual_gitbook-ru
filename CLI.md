## Что такое CLI


`chloros-cli` — это интерфейс командной строки для того же механизма обработки, который использует настольное приложение Chloros
. Это «тонкий» HTTP
-клиент, работающий через бэкенд Chloros
(локальный сервер на `127.0.0.1:5000`) — большинство команд запускают бэкенд автоматически, поэтому для скрипта достаточно одного вызова `chloros-cli process …`. Затем бэкенд продолжает работать в ожидании следующей команды: он останавливается при выполнении команды `chloros-cli logout` (если только приложение не открыто или не выполняется запуск или сборка), при выполнении команды `chloros-cli backend stop` либо самостоятельно через 30 минут отсутствия клиента, запуска или подключённого устройства. `chloros-cli backend status` отображает это.

Работает на **Windows
10/11 (x64)**и**Linux
(x86_64, а также NVIDIA Jetson arm64 на JetPack 6)**, в любом терминале, без необходимости использования графического интерфейса. Проверьте установку с помощью:

```bash
chloros-cli --version    # prints "Chloros CLI 1.3.0"
```

Краткий обзор семейств команд:

* **Обработка и учёт** — `process`, `login`, `logout`, `status`, `export-status`, `language` (38 языков — см. [Поддерживаемые языки](supported-languages.md)), `set-project-folder` / `get-project-folder` / `reset-project-folder`, `selftest`, `update` (только для Linux
/Jetson)
* **Рабочее оборудование** — `lattice` (управление камерой LATTICE, более 45 подкоманд), `daq pool-*` (датчики освещенности DAQ), `time-sync` (PTP)
* **Автоматизация** — `project` (запуск сохраненного проекта Chloros
в режиме без интерфейса, включая рецепты захвата в формате YAML)

Глобальные параметры, о которых стоит знать: `--port N` (порт бэкэнда, по умолчанию `5000`), `-v/--verbose`, `--restart` (принудительный перезапуск бэкэнда), `--backend-exe PATH`. Полный список см. в [Справочнике по CLI
](reference/cli-reference.md).

## Установка

CLI
**входит в состав установщика Chloros** на всех платформах — отдельной загрузки CLI
нет. Загрузите установщик со страницы [Загрузка](download.md).

### Windows


Установщик размещает CLI
в папке:

```

C:\Program Files\Chloros\cli\chloros-cli.exe
```

и однократно добавляет эту папку в системный путь `PATH` (при обновлении также удаляются дубликаты записей, оставленные предыдущими установщиками) — **откройте новый терминал**после установки, чтобы система распознала обновлённый `PATH`. Установщик также помещает скрипты запуска (`Chloros_CLI.bat` / `Chloros_CLI.ps1`) в корневую папку установки, а также**Chloros
CLI
** в меню «Пуск», каждый из которых открывает терминал с готовым к использованию `chloros-cli`.

### Linux


Установите `.deb` для вашей архитектуры с помощью `apt` (а не `dpkg -i`, который игнорирует рекомендуемые требования Python
SDK
):

```bash
# Linux x86_64
sudo apt install ./chloros_1.3.0_amd64.deb

# NVIDIA Jetson (arm64, JetPack 6)
sudo apt install ./chloros_1.3.0_arm64_jp6.deb
```

Это устанавливает `chloros-cli` в `/usr/bin/chloros-cli` (уже в `PATH`), бэкенд и программы CLI
, распакованные в `/usr/lib/chloros/backend/` и `/usr/lib/chloros/cli/` (`/usr/lib/chloros/chloros-backend` — это программа запуска, которая запускает бэкенд), среду выполнения Arena SDK
, необходимую бэкенду для камер LATTICE, а также Python
SDK
для системы `python3`. Подробности см. в разделе [Установка в Linux
](linux/linux-installation.md).

### Проверка

```bash
chloros-cli --version    # "Chloros CLI 1.3.0"
chloros-cli selftest     # 7-step diagnostic: backend, API, GPU/CUDA, denoiser models
chloros-cli status       # license tier + logged-in user
```

## Вход в систему и лицензирование

Для доступа к CLI
(и Python
SDK
) требуется **платный тарифный план Chloros
+**— он доступен в любом платном тарифном плане, но отсутствует в бесплатном. Ограничение применяется**на стороне сервера** бэкендом, а не бинарным файлом CLI
: вызов без входа в систему отклоняется с кодом `401 AUTH_REQUIRED`, а вызов с авторизованным пользователем на бесплатном тарифе — с кодом ошибки `403 PLAN_UPGRADE_REQUIRED`, независимо от того, поступает ли он из `chloros-cli`, SDK
или самодельного HTTP
-клиента. Выполните обновление по ссылке [https://cloud.mapir.camera/pricing](https://cloud.mapir.camera/pricing).

Входите в систему **один раз с каждого компьютера**:

```bash
chloros-cli login user@example.com 'YourPassword'
chloros-cli status
```

{% hint style="warning" %}
**Пароли со специальными символами**(`$`, `!`, spaces): wrap the password in**single quotes**, as shown above. In PowerShell double quotes, `$$` искажается оболочкой (CLI
обнаруживает это по ошибке 401 и автоматически повторяет попытку, но использование одинарных кавычек полностью устраняет эту проблему).
{% endhint %}

Сессия кэшируется в `~/.chloros/user_session.json` и продолжает работать в автономном режиме в течение льготного периода тарифного плана (30 дней для месячных тарифных планов, до истечения срока действия для годовых). `chloros-cli status` работает даже без платного тарифного плана, поэтому причина отказа всегда видна.

{% hint style="danger" %}
**Планируете запуск задач в фоновом режиме? Сначала войдите в систему.**Команды, запускающие бэкэнд (`process`, `status`, `export-status`, …) при запуске**без кэшированной сессии**не завершается с ошибкой сразу — она переходит в интерактивный режим с приглашением `Email:` / `Password:` на stdin. Поэтому автозапускаемое задание cron или этап CI**зависнет в ожидании ввода**. Перед планированием каких-либо задач запустите `chloros-cli login EMAIL 'PASSWORD'` один раз на компьютере.
{% endhint %}

## Ваш первый запуск обработки

Укажите `process` на папку с данными съёмки — программа автоматически обнаружит Survey3
(`.raw` + `.jpg`), LATTICE (`.tif`/`.tiff`), `.dng` или их комбинацию:

```bash
chloros-cli process "C:\Images\flight_001"          # Windows
chloros-cli process ~/images/flight_001              # Linux
```

Потоки прогресса отображаются в реальном времени для каждого потока конвейера (обнаружение, анализ, обработка, экспорт), и успешный запуск завершается отчётом о количестве записанных изображений: `Image products written: N`, за которым следует `(plus M clamp masks)`, если в ходе выполнения также были записаны [маски ограничения](output-image-formats.md#clamp-masks) (они не учитываются в качестве продуктов).

<!-- SCREENSHOT-NEEDED: terminal capture of a `chloros-cli process` run on a LATTICE captures folder completing successfully — per-thread progress lines visible and the final "Image products written: N (plus M clamp masks)" summary line -->


Если бэкенд Chloros
уже запущен (например, в настольном приложении), `process` использует его и открывает в нём свой проект. Он отказывает, пока приложение открыто на проекте, открытом приложением: запустите процесс из приложения или закройте этот проект. Если предыдущий запуск ещё завершается, он ждёт его до 15 секунд, прежде чем отказать. Код ошибки `--restart` принудительно запускает новый бэкенд. В Linux
бэкенд, запущенный в качестве службы systemd, никогда не перезапускается: `process` использует его в том виде, в каком он есть, и в тех случаях, когда в ином случае он бы его перезапустил (`--restart` или импорт, не найдя ничего), он выводит сообщение `sudo systemctl restart <unit>` и завершает работу `1`.

### Куда попадают результаты

`process` записывает результаты в **папку проекта**, а не в вашу папку входных данных:

* Если `-o` отсутствует: проект создаётся в вашей папке проектов по умолчанию (общей с графическим интерфейсом; управлять ею можно с помощью `get-project-folder` / `set-project-folder`; если ничего не указано, то в вашей пользовательской папке), с именем, заданным параметром `-n/--project-name` или временной меткой (`YYYYMMDD_HHMMSS`), если параметр опущен.
* С `-o PATH`: эта папка **является** папкой проекта. Если в ней уже содержится файл `project.json`, вместо перезаписи создаётся файл с суффиксом `_1`/`_2`… с таким суффиксом вместо перезаписи. Относительный путь `PATH` определяется относительно папки, из которой запускается `chloros-cli`.

{% hint style="info" %}
**Относительные пути (изменено в версии 1.3.0).** Каждый путь, который открывает бэкенд — `-o`/`--output` при выполнении любой команды (включая `output` по умолчанию для команд захвата), `--input`, `--burst-dir`, `--profile`, `--save` и `--mask` — преобразуется относительно папки, из которой запускается `chloros-cli`, поэтому `-o captures/` записывает данные в `<current folder>/captures/`. В версии 1.2.0 бэкенд преобразовывал их в своей собственной папке установки, что приводило к ошибке «Доступ запрещен». При работе с удалённым бэкендом (`CHLOROS_BACKEND_URL`) пути отправляются в том виде, в каком они введены, и преобразуются на той машине.
{% endhint %}

{% hint style="warning" %}
**Windows
: используйте короткую папку проекта, если не включена поддержка длинных путей.** Если в Windows
отключена поддержка длинных путей (по умолчанию), длина пути к файлу не должна превышать 260 символов, а папки продуктов должны находиться не выше, чем на 130 символов ниже папки проекта. `process` проверяет это перед запуском: слишком глубокая папка проекта отклоняется с сообщением **«Папка проекта слишком глубокая для этого компьютера»**, предлагается самая длинная подходящая папка проекта и инструкция по включению длинных путей — никакая обработка не производится. Используйте более короткую версию `-o` (или `set-project-folder`) либо включите поддержку длинных путей в Windows
(параметр установщика **Включить длинные пути Windows**, отмеченный по умолчанию) и перезапустите Chloros
.
{% endhint %}

Внутри проекта продукты сгруппированы **по камере, а затем по формату файла**:

```
<project>/
├── project.json
├── calibration_data.json
└── LATT-M3M-L41-F550/                  # one folder per camera model+lens+filter
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per requested index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

Папка камеры для LATTICE — `LATT-<sensor>-<lens>-F<filter>` (соответствующая EXIF-данным съёмки `Model`), а для Survey3 — `<model>_<filter>` (например, `Survey3N_RGN`) для камеры Survey3
. Папка с форматами следует за `--format`: `tiff16`, `tiff8`, `png8`, `jpg8` или `tiff32` для `TIFF (32-bit, Percent)`.

Для мультиспектральной камеры M3C в папке формата, наряду с папками продуктов, также может появиться папка `clamp_masks/` (например, `tiff16/clamp_masks/Reflectance_Calibrated_Images/` и `tiff32/clamp_masks/Radiance_Images/`). В ней хранятся пиксельные маски продуктов яркости и отражательной способности, в которых при разложении по полосам отрицательные значения были приведены к нулю — см. [Маски ограничения](output-image-formats.md#clamp-masks). Папка с продуктами никогда не содержит маски.

{% hint style="info" %}
**Каждый экспортированный продукт сохраняет имя исходного файла.**Экспорт яркости из `capture_..._raw.tif` по-прежнему называется `capture_..._raw.tif` — он просто находится в `tiff32/Radiance_Images/`.**Продукт идентифицируется по папке, а не по имени файла**, поэтому используйте глобальный шаблон для поиска по каталогу, а не по суффиксу `*radiance*`.
{% endhint %}

### Параметры, которые вы будете использовать на практике

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `-o, --output PATH` | папка проекта по умолчанию | Расположение папки проекта (см. выше). |
| `-n, --project-name NAME` | метка времени | Название проекта. |
| `--format FMT` | `TIFF (16-bit)` | Один из следующих: `TIFF (16-bit)`, `TIFF (8-bit)`, `TIFF (32-bit, Percent)`, `PNG (8-bit)`, `JPG (8-bit)`. Chloros
не увеличивает разрешение: на всех 8-битных изображениях формат с большей глубиной записывается как `TIFF (8-bit)`, и об этом сообщается один раз. |
| `--indices NAME [NAME ...]` | нет | Индексы растительности для экспорта (см. [Индексы растительности](#vegetation-indices)). |
| `--debayer {standard,texture-aware}` | `standard` | `texture-aware` = нейронный дебайеризатор, более медленный, наивысшее качество (Chloros
+, требуется графический процессор с поддержкой CUDA: без него используется `standard`; не применяется к снимкам LATTICE, для которых всегда используется `standard`). |
| `--vignette / --no-vignette` | включено | Коррекция виньетирования. |
| `--reflectance / --no-reflectance` | включено | Калибровка отражательной способности; для LATTICE это также переключатель продукта отражательной способности. |
| `--input-level {auto,raw,debayered,processed}` | `auto` | Принудительное задание точки входа в конвейер для TIFF-файлов LATTICE. |

По всем остальным параметрам — настройка обнаружения целей, PPK, фиксаторы экспозиции, флаги выравнивания массивов — см. [раздел `process` в Справочнике по CLI
](reference/cli-reference.md).

## Выбор элементов для экспорта (продукты LATTICE)

Обработка LATTICE распределяется **по всем применимым продуктам за один проход**. Четыре переключателя для каждого продукта**по умолчанию включены**; используйте форму `--no-`, чтобы отключить один из них:

| Переключатель | Продукт |
| --- | --- |
| `--debayered` | Линейная демозаика → `Debayered_Images/`: удаление темнового смещения из калибровочного пакета, затем демозаика с учетом краев, без коррекции линейности, плоского поля или разложения — тот же файл, который сохраняется при съемке на уровне `debayered`. Сохраняется в исходной ориентации датчика (записано в XMP). |
| `--preview` | Предварительный просмотр (баланс белого + гамма; растяжение в ложных цветах для мультиспектральных снимков) → `Preview_Images/` |
| `--radiance` | float32 яркость, Вт/м²/ср/нм → `Radiance_Images/` (всегда `tiff32/`) |
| `--reflectance` | uint16 коэффициент отражения, готовый для Pix4D → `Reflectance_Calibrated_Images/` |

Камеры RGB
-типа всегда выдают только данные после дебайеризации + предварительный просмотр — значения яркости/коэффициента отражения по отдельным полосам не имеют смысла для широкополосного датчика, поэтому эти переключатели для них не действуют. Survey3
`.raw` игнорирует эти переключатели и следует стандартному пути для коэффициента отражения/целевого значения.

```bash
# Radiance only — no DAQ downwelling needed
chloros-cli process ~/captures/lattice_flight --no-debayered --no-preview --no-reflectance
```

**`--reflectance-source {auto,target,daq}`** (по умолчанию `auto`) выбирает эталон отражательной способности: `auto` использует прошедшую контроль качества [калибровочную мишень](calibration-targets.md), находящуюся в кадре, в качестве абсолютного эталона и переключается на соотношение «свет-тень» датчика освещенности системы сбора данных (ρ = π·L/E), если мишень отсутствует (мишень, прошедшая контроль качества с флагом, конкурирует с DAQ по измеренному результату); `target` действует строго (без замены на данные DAQ); `daq` является авторитетным для DAQ. Сканированные данные по отдельным единицам измерения мишени могут быть предоставлены с помощью `--target-reflectance-dir`.

{% hint style="info" %}
**Считывание пикселей отражательной способности:**значение DN, означающее ρ = 1,0, относится**к каждому источнику** — файлы LATTICE помещают тег `Chloros:PixelScale=32768` в XMP; файлы Survey3
используют значение 65535 и не содержат тега `Chloros:PixelScale` (однако в них присутствуют другие теги обработки `Chloros:*`). Считывайте этот тег и делите на его значение, а не принимайте за постоянную величину. Подробности и единственный преднамеренный крайний случай без масштабирования приведены в [Справочнике по CLI
](reference/cli-reference.md).
{% endhint %}

**Обработка всегда начинается с `raw`.** Производные продукты (экспорт данных после дебайеризации, яркости или отражательной способности) никогда не возвращаются в конвейер — их повторный импорт и обработка привели бы к двойному применению калибровочных вычислений, поэтому Chloros
пропускает их и сообщает об этом. `--input-level` — это специально предусмотренный «запасной выход» на случай, если вам действительно нужно принудительно задать точку входа.

## Когда запуск завершается сбоем

Начиная с версии 1.2.0, `process` явно завершается с ошибкой, а не «успешно» без вывода результатов:

* Запуск, который **запросил продукты, но не записал ни одного**— только `project.json` и `calibration_data.json` — выводит сообщение `Processing finished but wrote no image products.` и**завершается с ненулевым кодом**, поэтому скрипты могут это обнаружить. Обычные причины: входная папка не была распознана как набор данных (проверьте структуру и `--input-level`), либо все запрошенные продукты были неприменимы для этих камер (например, запрос радианса/отражения от камер, поддерживающих только RGB
).
* **Намеренный запуск только с метаданными** (все продукты отключены, без `--indices`) всё равно считается успешным — в данном случае пустой выходной файл изображения является правильным результатом.
* Запустите процесс заново с параметром `--verbose` и проверьте журнал бэкэнда на наличие строк `[LATTICE-EXPORT]` / `[EXPORT-CHECK]`, которые объясняют пропуски по камерам.
* В Windows
, где отключены длинные пути, папка проекта, глубина которой превышает ограничение в 260 символов, отклоняется **до** начала обработки, при этом используется самая длинная папка проекта, которая укладывается в ограничение (см. [Где размещаются выходные файлы](#where-the-outputs-land)).
* Команды захвата (`lattice capture`, `lattice array-capture` и другие семейства команд захвата) перечисляют все файлы, которые не удалось записать, и завершают работу с кодом `1`; повторяющиеся захваты останавливаются, когда диск заполнен.

Коды завершения: `0` — успех · `1` — общая ошибка · `2` — ошибка аргумента · `130` — прервано нажатием Ctrl+C.

## Индексы растительности

Запустите `--indices` с одним или несколькими названиями предустановок; каждый индекс помещается в свою собственную папку `<INDEX>_Index_Images/`:

```bash
chloros-cli process ~/images/flight_001 --indices NDVI GNDVI OSAVI
```

22 предварительно заданных имени, которые принимает `process --indices`:

`NDVI` `GNDVI` `NDRE` `OSAVI` `SAVI` `MSAVI2` `EVI` `MSR` `TDVI` `LAI` `GCI` `GRVI` `GSAVI` `GOSAVI` `NLI` `MNLI` `RDVI` `WDRVI` `CVI` `ENDVI` `GLI` `VARI`

В проект добавляется имя, которого в нём ещё нет. Имя, которое не является предустановленным или которое не может быть сформировано диапазонами камер, пропускается с выводом предупреждения, указывающего это имя. Если интерфейс CLI
не может прочитать текущий список индексов проекта, он оставляет список без изменений и выдает предупреждение вместо его замены.

{% hint style="warning" %}
**Существует три списка индексов — не путайте их.**В раскрывающемся списке «Настройки проекта» графического интерфейса пользователя (GUI) имеется 27 формул (добавляются `FCI1`, `FCI2`, `GARI`, `GEMI`, `LCI` — эти пять доступны только в графическом интерфейсе и**не** применимы к `--indices`). Команда «в режиме реального времени/офлайн» `lattice index --preset` использует свой собственный отдельный список из 22 предустановок. Формулы и математические вычисления для полос описаны в [Формулы мультиспектральных индексов](project-settings/multispectral-index-formulas.md).
{% endhint %}

## Датчики освещённости DAQ: краткий обзор

Семейство `daq pool-*` управляет спектральными датчиками DAQ компании MAPIR
(DAQ-U через USB, DAQ-M через BLE, DAQ-E через Ethernet) через постоянный пул бэкэнда — графический интерфейс пользователя (GUI), интерфейс командной строки (CLI
) и набор средств разработки (SDK
) используют один и тот же дескриптор в режиме реального времени. **`pool-*` — это поддерживаемый путь DAQ в поставляемом CLI
**; другие подкоманды `daq`, на которые вы можете встретить ссылки, представляют собой внутренний для MAPIR
интерфейс, доступный только для чтения, и завершают работу с явной ошибкой, указывающей на `pool-*`.

```bash
# 1. Open a pooled session (pick the line matching your sensor)
chloros-cli daq pool-connect                              # smart-detect
chloros-cli daq pool-connect --port COM3                  # DAQ-U on a specific COM port
chloros-cli daq pool-connect --mac AA:BB:CC:DD:EE:FF      # DAQ-M by BLE MAC
chloros-cli daq pool-connect --eth-host daq-e-xxx.local   # DAQ-E by hostname (reliable)

# 2. List pooled sensors and their ids
#    (DAQ-U ids look like 'CB-7C-A8-2E-5F'; DAQ-E ids like 'daq-e-def330')
chloros-cli daq pool-list

# 3. Read the latest calibrated spectrum (W/m²/nm)
chloros-cli daq pool-latest --sensor-id CB-7C-A8-2E-5F

# 4. Record a calibrated .daq file for 60 s
chloros-cli daq pool-record --sensor-id CB-7C-A8-2E-5F --duration 60 \
  -o ~/Documents/spectra --device-name "field-A"

# 5. Release
chloros-cli daq pool-disconnect --sensor-id CB-7C-A8-2E-5F
```

`pool-record` без `--duration` работает до `pool-record --stop`; каталог вывода по умолчанию — `~/Documents/DAQ Live View/` **на машине бэкенда**. Профиль коррекции емкости выбирается при подключении (`--cap-id`, значение по умолчанию для бэкенда — `sunshine_cosine`) и может быть заменен в режиме реального времени с помощью `pool-set-cap` — профили капа и откалиброванный диапазон датчика описаны в главах, посвящённых DAQ, данного руководства.

{% hint style="warning" %}
**DAQ-E на хосте с несколькими сетевыми картами:** первое автоматическое обнаружение `pool-connect --eth` после загрузки может завершиться неудачей даже при исправном датчике. `--eth-host <ip-or-hostname>` является надёжным вариантом — используйте его, если обнаружение не даёт результатов.
{% endhint %}

## Камеры LATTICE, PTP и автоматизация проектов

Семейство команд `lattice` (более 45 подкоманд) охватывает весь цикл работы с камерами LATTICE: обнаружение, единичные снимки, постоянные синхронизированные массивы с помощью интеллектуального процесса подключения в графическом интерфейсе, предварительный просмотр в браузере в режиме реального времени, выравнивание, индексные вычисления и диагностика сетевых карт хоста. Пример:

```bash
chloros-cli lattice info                                          # discover cameras
chloros-cli lattice capture -o output/                            # one frame, all export types
chloros-cli lattice array-connect --serials SN1,SN2,SN3,SN4       # persistent synced array
chloros-cli lattice array-capture --processing reflectance -o out/
```

Наряду с этим: `chloros-cli time-sync` предоставляет отчёт о сервере PTP-grandmaster, запущенном на хосте Chloros
(камеры LATTICE и датчики DAQ-E работают в режиме ведомого устройства для синхронизации временных меток между устройствами), а `chloros-cli project` открывает сохраненный проект Chloros
и управляет его камерами, массивами и датчиками в режиме без графического интерфейса — включая скриптовые рецепты сбора данных в формате YAML.

Эти три семейства (`lattice`, `project`, `daq pool-*`) также являются единственными, которые поддерживают использование `CHLOROS_BACKEND_URL` для управления **удалённым** бэкендом; основные команды всегда нацелены на локальную машину.

Полные пошаговые инструкции приведены в главах, посвящённых LATTICE, данного руководства; описание всех флагов находится в [Справочнике по CLI
](reference/cli-reference.md).

## Устранение неполадок: 5 основных случаев

| Симптом | Решение |
| --- | --- |
| `Login required` или запланированная задача зависает на приглашении `Email:` | Запустите `chloros-cli login EMAIL 'PASSWORD'` один раз на этом компьютере — команды без кэшированной сессии будут выполняться в интерактивном режиме, а не завершаться с ошибкой. |
| `backend unreachable` | Запустите настольное приложение Chloros
или запустите бэкенд самостоятельно: `"C:\Program Files\Chloros\backend\chloros-backend.exe"` в Windows
(папка `backend` в папке установки; её нет в `PATH`), `chloros-backend` в Linux
. `chloros-cli backend status` показывает, запущен ли бэкенд; `lattice`/`project`/`daq pool-*` никогда не запускают его. Если вы настраиваете их на удалённый бэкенд, проверьте `CHLOROS_BACKEND_URL`. |
| Блокировано подключение к массиву: `FRAMES WILL DROP` / `Reduce ROI to enable` | Кольцо приёма сетевой карты хоста сброшено до значений по умолчанию — это самая распространённая причина, по которой ранее работавшая установка отказывается подключаться, как правило, после обновления драйвера сетевой карты. Запустите команду `chloros-cli lattice network --fix` из терминала с **повышенными правами** (или установите параметры `ReceiveBufferLen=256`, `PendingReceives=64`); см. раздел *Настройка и оптимизация сетевой карты хоста* в справочнике. |
| Подкоманда `daq` завершает работу с сообщением: «требуется полный пакет DAQ…» | Используйте команды `daq pool-*`, которые управляют тем же датчиком через бэкэнд: подключение, потоковая передача, запись, выбор капсулы, а для DAQ-E — его сетевые настройки, перезапуск и обновления прошивки (или `chloros_sdk.connect_daq_sensor()` из Python
). |
| Jetson выводит предупреждение о подкаче перед работой с большими папками | Добавьте подкачку на основе файлов — интерфейс CLI
выведет точные команды `fallocate`/`swapon` для запуска. |
