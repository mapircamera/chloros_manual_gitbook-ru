# Начало работы

<div data-full-width="false"><figure><img src=".gitbook/assets/chloros_logo_transparent.png" alt=""><figcaption></figcaption></figure></div>

Chloros — это программное приложение от [MAPIR](https://www.mapir.camera), предназначенное для обработки мультиспектральных снимков, управления оборудованием MAPIR в режиме реального времени и записи данных с датчиков. Chloros 1.3.0 поддерживает всю линейку продуктов MAPIR:

* **Камеры Survey3** — преобразуют снимки в формате RAW+JPG в откалиброванные карты отражательной способности и индексов растительности. См. [Поддерживаемые камеры](supported-cameras.md).
* **Камеры LATTICE** — подключение мультиспектральных камерных модулей GigE в режиме реального времени, по отдельности или в виде синхронизированных мультикамерных массивов: предварительный просмотр, съемка и преобразование в откалиброванные продукты яркости и отражательной способности. См. [раздел LATTICE](lattice/README.md).
* **Световые датчики DAQ** — спектральные датчики DAQ-U (USB), DAQ-M (Bluetooth), а также DAQ-E и DAQ-E-S (Ethernet): калиброванные спектры в режиме реального времени, `.daq` записи, а также данные о нисходящем освещении для обработки коэффициентов отражения. См. [раздел «DAQ»](daq/README.md).

{% hint style="success" %}
**Что нового в Chloros 1.3.0**: ИИ-помощники могут управлять Chloros через `chloros-mcp`, а CLI, SDK и `chloros-mcp` предлагают те же функции. Улучшены продукты LATTICE index, массивы полных датчиков работают быстрее и поддерживают любую сеть, а бэкэнд продолжает работать между командами. Ознакомьтесь со списком нововведений ниже и [скачайте](download.md) установщики.
{% endhint %}

Пример запроса: *«Прочитайте https://mapir.gitbook.io/chloros/reference/cli-reference.md,, затем напишите скрипт, который авторизуется и обрабатывает папку ~/flights/flight_001, преобразуя её в GeoTIFF-файлы с показателями отражательной способности и NDVI».*

## Что нового в Chloros 1.3.0

* **ИИ-помощники могут управлять Chloros.** `chloros-mcp` — сервер MCP, установленный вместе с Python SDK, — позволяет Claude Desktop, Claude Code, Cursor и другим клиентам MCP обрабатывать изображения и управлять камерами LATTICE, массивами и световыми датчиками DAQ. См. [Использование Chloros с ИИ-помощниками](ai-assistants.md).
* **CLI, SDK и `chloros-mcp` предлагают одинаковые функции.** Из соображений безопасности только вход в систему, настройка DAQ-E и прямые серверы DAQ остаются в CLI. Некоторые скрипты версии 1.2.0 требуют изменений: см. раздел **Изменения в версии 1.3.0** в начале [Справочника по CLI](reference/cli-reference.md) и [Справочника по SDK](reference/sdk-reference.md).
* **Улучшены индексные продукты LATTICE.** Показатель NDVI и другие индексные продукты, экспортируемые из снимков LATTICE, улучшены во всех режимах обработки.
* **Параметры установщика для Windows.**В разделе**«Настройки системы»**установщик предлагает параметры**«Включить длинные пути Windows»**и**«Исключить бэкенд Chloros из сканирования Microsoft Defender»**; оба параметра отмечены по умолчанию. Первая опция позволяет размещать папки проектов в каталогах, имеющих имена длиной более 260 символов; вторая предотвращает замедление съёмки камеры из-за сканирования в режиме реального времени (примерно на 30 % от скорости съёмки при высоких скоростях). Теперь установщик также добавляет папку CLI в `PATH` только один раз и удаляет дубликаты записей, оставленные предыдущими версиями установщика. См. [Скачать](download.md).
* **Слишком глубокие папки проектов отклоняются на начальном этапе.** Если в Windows отключены длинные пути (настройка по умолчанию), папка проекта, глубина которой превышает ограничение в 260 символов, отклоняется до начала выполнения, при этом отображается самая длинная подходящая папка проекта и инструкция по включению длинных путей. Раньше при таком запуске продукты не записывались. При включенных длинных путях продукты в очень глубоких папках теперь сохраняют свои метаданные (теги GPS и XMP).
* **Маски ограничения значений.** Когда при разделении каналов продукта яркости или отражательной способности LATTICE получается отрицательное значение канала, оно ограничивается до нуля, а в папке `clamp_masks/`, расположенной рядом с папками продуктов, создаётся маска на уровне пикселей, в которой фиксируется, какие пиксели и каналы были затронуты. Продукт указывает имя своей маски в теге `Chloros:UnmixClampMask`. В режиме реального времени обрезка теперь выполняется точно так же, как при экспорте. См. [Форматы выходных изображений](output-image-formats.md).
* **Продукты описывают себя сами.** Индексные продукты содержат собственные теги обработки (`Chloros:ProcessingLevel=index`, индексный выражение и информацию о том, были ли они вычислены на основе яркости или отражательной способности) вместо тегов исходных необработанных данных. Продукты Survey3 содержат теги обработки Chloros в каждом режиме обработки. Необработанные файлы LATTICE и файлы после удаления байеров сохраняют исходную ориентацию датчика и записывают её в XMP; программа просмотра изображений поворачивает их только для отображения.
* **Пакеты для Linux поставляются в распакованном виде.** Бэкенд и интерфейс командной строки (CLI) устанавливаются в виде папок в каталоге `/usr/lib/chloros/`, поэтому они больше не распаковываются при каждом запуске. На x86_64 бэкенд больше не тратит около 100 секунд на запуск, а размер `.deb` сократился примерно вдвое по сравнению с прежним. Входящий в комплект ExifTool теперь работает на чистой установке Ubuntu. `.deb` теперь также устанавливает Python SDK для системного `python3` (установите его с помощью `sudo apt install ./chloros_1.3.0_<arch>.deb`), увеличивает размер буферов приёма сокетов ядра, необходимых для потоков с камеры, и добавляет бэкенд-сервис, работающий под вашим пользователем. Пакет для Jetson, `chloros_1.3.0_arm64_jp6.deb`, скомпилирован для JetPack 6 и выполняет вычисления на графическом процессоре Jetson с помощью CUDA-версии PyTorch от JetPack. В Linux каждое экспортированное изображение теперь попадает на диск один раз (записывается и помечается в памяти, а затем копируется на место): на Jetson, где скорость определяет диск, запуск LATTICE с 288 изображениями занимает 14 минут вместо 24. См. [Установка в Linux](linux/linux-installation.md).
* **Камеры LATTICE с технологией OCN обеспечивают более точные считывания при солнечном свете.** Показатели яркости, отражательной способности и индексов проходят быструю коррекцию после разделения каналов, благодаря чему серый эталон при солнечном свете считывается с показателем NDVI, близким к нейтральному. Камеры RGN остались без изменений.
* **Отчеты об ошибках в приложении.** Значок ошибки в верхней части вкладки «Журнал отладки» отправляет в MAPIR описание, до 10 изображений, журналы и сведения о системе. См. [GUI: Навигация](navigation.md).
* **Массивы LATTICE.**По умолчанию массивы сохраняют данные всего датчика, а сжатая 12-битная передача (`--packed`, по умолчанию `auto`) повышает частоту кадров при использовании данных всего датчика примерно на треть; массив работает в любой сети с той частотой кадров, которую она поддерживает (медленный канал снижает частоту кадров, а не отклоняет массив или уменьшает размер его кадров); массив, камеры которого перезагружаются, восстанавливает работу самостоятельно с повторным включением PTP; автоматическая экспозиция больше не снижает эту частоту при слабом освещении (она заполняет период, а затем повышает коэффициент усиления); режим непрерывной съемки не отстает от быстрых массивов; регулятор**Highlights** для RGB-камер; а в SDK добавлены `ArraySession`, `grab()`, `frame_stream()` и `continuous()`. См. [раздел LATTICE](lattice/README.md).
* **Более стабильная автоматическая экспозиция.** Экспозиция остается постоянной при неизменном освещении и стабилизируется в течение нескольких секунд после изменения; небольшие яркие участки больше не затемняют сцену; при ручной экспозиции коэффициент усиления остается в режиме «Авто»; а камера, которая перестает реагировать при ярком солнечном свете, удерживается на уровне, соответствующем освещенности, определяемой датчиком освещенности или, при его отсутствии, собственными кадрами камеры. См. [Настройки камеры](lattice/camera-settings.md).
* **Датчики освещенности.** **Поддержка DAQ-E-S:** его фиксированный рассеиватель не требует коррекции крышки, и каждое измерение учитывает наклон, крен и тангаж устройства. В записи указывается, был ли выбран конкретный колпачок или его тип был определен автоматически, и при обработке выдается предупреждение в случае автоматического определения: модели DAQ-U, DAQ-M и DAQ-E поставляются без колпачка, поэтому необходимо указать установленный тип. Записи в режиме реального времени `.daq` сохраняются при отключении питания (сохраните файл `.daq-journal` вместе с его `.daq`), а DAQ-E, прекративший передачу данных, подключается заново с отметкой пропуска в записи. Проект, содержащий только записи датчиков освещенности, отображает их список и обрабатывает данные как из приложения, так и из CLI, а запись, сделанная с помощью `chloros_scripts`, отображается с указанием DAQ, который её создал, с возможностью установки ограничителя. Каждая запись сохраняет показания DAQ, использованного для неё. См. [раздел DAQ](daq/README.md).
* **Обработка.**Обработка кадров LATTICE начинается во время обнаружения цели. Ссылки на цель и DAQ определяются для каждого диапазона. При перемещении проекта его файлы перессылаются заново. Экспорт 8-битных снимков осуществляется в 8-битном формате**TIFF (8-bit)**. Запуск Survey3 без калибровочной мишени сохраняется как резервный продукт (`Vignette_Corrected_Images` или `Sensor_Response_Images`), а не как изображение отражательной способности. Теги DLS для каждого диапазона в изображении отражательной способности всегда относятся к его собственному кадру. Функция «Texture Aware» не поддерживается для снимков LATTICE, которые всегда обрабатываются стандартным дебайером.
* **CLI и SDK.** Относительные пути вывода теперь указывают на папку, из которой запускается команда или скрипт (ранее установленный бэкенд пытался разрешить их в своей собственной папке установки, что приводило к сбою). Бэкенд продолжает работать между командами и скриптами и останавливается самостоятельно после 30 минут простоя; этим управляют `chloros-cli backend status` и `backend stop`. Команды захвата выводят список всех файлов, которые не удалось записать, и завершают работу с кодом 1, а повторные захваты останавливаются при заполнении диска. Успешный запуск `process` выдает отчет `Image products written: N (plus M clamp masks)`. В Windows `ChlorosLocal` из SDK / `process_folder` находят установленный бэкенд (и используют тот, который уже запущен), а `read_image_audit_tags` работает из простого `pip install`.

## Что нового в Chloros 1.2.0

* **Управление камерами в режиме реального времени — новая вкладка «Камеры».** Подключайте камеры LATTICE по одной или в виде синхронизированных массивов из нескольких камер (синхронизация времени по PTP, съемка с аппаратным триггером) с наложением предварительного просмотра в реальном времени, гистограммами по отдельным полосам, интеллектуальной автоэкспозицией, калькулятором индекса в реальном времени и обновлениями прошивки камер прямо в приложении.
* **Датчики освещённости — новая вкладка «Датчики освещённости».** Подключайте датчики DAQ-U (USB), DAQ-M (Bluetooth) и DAQ-E (Ethernet); просматривайте откалиброванные спектры в реальном времени (Вт/м²/нм), записывайте файлы `.daq` в свой проект, выбирайте профили коррекции капа и обновляйте прошивку DAQ-E по сети.
* **Режимы съемки и регистраторы.** Однократная / непрерывная / интервальная съемка, а также режим «Самая быстрая съемка» (только в формате RAW); выбор для каждого проекта камер и типов экспорта, которые генерирует функция «Захватить всё»; матричные регистраторы для индексного видео мониторингового качества и серий необработанных кадров аналитического качества с возможностью автосборки видео в автономном режиме.
* **Конвейер обработки LATTICE.** Импорт папок с данными захвата LATTICE и преобразование каждого необработанного кадра в следующие продукты: с устраненным эффектом Бейера, предварительный просмотр, яркость в формате float32 (Вт/м²/стр/нм) и коэффициент отражения с переключателями для каждого продукта. Значения отражательной способности могут быть получены из калибровочной мишени в кадре или с помощью нисходящего излучения DAQ; к экспортируемым данным применяется выравнивание массива; отсутствующая заводская калибровка загружается автоматически по серийному номеру камеры.
* **Проекты запоминают конфигурацию оборудования.** Подключенные камеры и датчики освещенности сохраняются вместе с проектом (`cameras.json` / `sensors.json`) и при повторном открытии проекта подключаются с сохраненными настройками. См. [GUI: Проекты](projects.md).
* **Улучшения в программе просмотра изображений.** Считывание пикселей/индексов курсора с правильным масштабированием коэффициента отражения для каждого файла, гистограммы слоёв, ползунок биннинга GSD, режимы сетки «На триггер» / «На камеру», просмотр продуктов LATTICE и экспорт индекса/LUT в «песочницу» на диск.
* **Значительное расширение CLI и SDK.** Новые семейства команд `lattice`, `daq pool-*`, `project` и `time-sync`; новые опции `process` (`--input-level`, переключатели для отдельных продуктов, `--reflectance-source`, флаги выравнивания массивов); дескрипторы интеллектуального подключения SDK (`connect_camera` / `connect_array` / `connect_daq_sensor`), которые автоматически запускают бэкэнд; Автоматизация `open_project()`; колесо SDK входит в состав установщиков и опубликовано на PyPI как `chloros-sdk`.
* **Чёткая семантика ошибок.** Запуск `chloros-cli process`, который запрашивал продукты, но не создал ни одного, теперь завершается с явным сообщением об ошибке и возвращает ненулевой код завершения; успешные запуски сообщают, сколько образов продуктов было создано.
* **Новая структура вывода.** Продукты помещаются в папки `<project>/<camera>/<format>/<Product>_Images/` и сохраняют имя исходного файла — продукт идентифицируется по папке, а не по суффиксу имени файла. См. [Форматы выходных изображений](output-image-formats.md).
* **Дополнительные источники входных данных, планы и языки.** Поддержка входных данных `.dng`; полная поддержка всех 38 языков интерфейса; аппаратные ограничения для каждого плана с возможностью бесплатного (без входа в систему) использования до 4 камер и 2 датчиков освещенности.
* **Надёжность.** Функция «Остановить обработку» корректно завершает работу с подробной сводкой выполнения, в проектах с несколькими камерами экспортируются данные со всех камер, а обновления установщика больше не приводят к выходу из системы.***

Chloros доступен в трёх вариантах интерфейса:

## Chloros: настольное приложение с графическим интерфейсом

Автономное отдельное окно со всеми функциями, включая вкладки «Камеры» и «Датчики освещенности» в режиме реального времени. _Только для Windows._

## [Chloros CLI: интерфейс командной строки](CLI.md)

Пакетная обработка из командной строки, а также команды в режиме реального времени `lattice`, `daq pool-*`, `project` и `time-sync`. Идеально подходит для автоматизации, создания скриптов и работы в режиме без графического интерфейса. Доступно на **Windows, Linux amd64 и Linux arm64 (NVIDIA Jetson)**. _Для доступа к CLI требуется платный тарифный план Chloros+._

## [Chloros API: Python SDK](api-python-sdk.md)

Программный интерфейс на Python для автоматизации и настраиваемых рабочих процессов: обработка по полному конвейеру, сеансы работы с камерами/массивами в режиме реального времени, сеансы с датчиками DAQ и автоматизация на основе сохраненных проектов. Устанавливается вместе с пакетом для настольных ПК/CLI, а также публикуется как `pip install chloros-sdk`. _Для доступа к API требуется платный тарифный план Chloros+._

| **Linux amd64 (x86_64)** | Нет | Да | Да |
| **Linux arm64 (NVIDIA Jetson)** | Нет | Да | Да |

Инструкции по установке для Linux см. в разделе [Linux и пограничные вычисления](linux/linux-overview.md).

## Начните работу за три шага

1. **Установка** — загрузите и запустите установщик для вашей платформы. См. [Загрузка](download.md).
2. **Войдите в систему (необязательно для графического интерфейса)** — графический интерфейс обрабатывает изображения бесплатно без учетной записи. [Вход в Chloros+](chloros+-login.md) открывает доступ к параллельной обработке, ускорению на GPU, более высоким лимитам на количество устройств, а также к CLI и SDK.
3. **Создайте свой первый проект** — откройте Chloros, создайте [Новый проект](projects.md), [добавьте свои изображения](processing-images-gui/adding-files-to-a-project.md) и [начните обработку](processing-images-gui/starting-the-processing.md). Чтобы вместо этого управлять реальным оборудованием, откройте вкладку «Камеры» или «Световые датчики» — см. [GUI: Навигация](navigation.md).

## Chloros+

Хотя Chloros можно бесплатно использовать для большинства задач, вам может понадобиться больше возможностей. Именно в этом случае вам пригодится платная лицензия на Chloros+. С лицензией Chloros+ вы сможете получить доступ к новым функциям, таким как:

* **Многопоточная обработка**: значительно ускорьте обработку изображений в крупных проектах за счёт одновременной обработки изображений в конвейере.
* **Ускорение на GPU (CUDA)**: воспользуйтесь преимуществами современных графических процессоров с большим объёмом памяти для дальнейшего ускорения конвейера обработки изображений. Для достижения наилучших результатов мы рекомендуем 4 ГБ или более видеопамяти (VRAM).
* **Chloros+**[**CLI**](CLI.md) **Доступ**: запускайте Chloros+ из командной строки для автоматизации и интеграции в ваше собственное программное обеспечение. Доступно на любом платном тарифном плане; контроль осуществляется на стороне сервера.
* **Chloros+**[**API**](api-python-sdk.md) **Доступ:** запускайте Chloros+ из Python для программного управления, что обеспечивает бесшовную интеграцию с вашими исследовательскими конвейерами, рабочими процессами анализа данных и пользовательскими приложениями. Доступно на любом платном тарифе; контроль осуществляется на стороне сервера.
* **Более высокие аппаратные ограничения**: подключайте больше камер и датчиков освещенности одновременно. Без входа в систему графический интерфейс позволяет подключить до 4 камер и 2 датчика освещенности DAQ; платные тарифные планы повышают оба ограничения:

| Тариф | Камеры | Датчики освещенности DAQ |
| --- | --- | --- |
| Iron (бесплатный, без входа в систему) | 4 | 2 |
| Copper / Bronze | 6 | 3 |
| Silver | 10 | 6 |
| Gold | 20 | 12 |

* **Использование нескольких устройств**: каждая лицензия Chloros+ позволяет зарегистрировать 2 и более устройств. Используйте свою учетную запись MAPIR Cloud для управления зарегистрированными устройствами. Добавьте поддержку дополнительных устройств, обновив свою лицензию Chloros+.
* **Усовершенствованный метод дебайеризации с учетом текстуры:** высококачественный алгоритм дебайеризации с учетом контуров в сочетании с моделью шумоподавления на основе ИИ/машинного обучения, которая устраняет практически весь шум, возникающий при дебайеризации.
* **Пользовательские формулы мультиспектральных индексов:** вводите пользовательские мультиспектральные индексы в растровые калькуляторы Chloros, как для обработки, так и для тестовой среды просмотра изображений.
* **Linux и пограничные вычисления:** запускайте Chloros на платформах Linux x86_64 и ARM64, включая NVIDIA Jetson, для полевой и пограничной обработки. См. [Обзор Linux](linux/linux-overview.md).
