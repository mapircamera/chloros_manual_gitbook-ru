# Руководство по NVIDIA Jetson

Chloros на платформе NVIDIA Jetson обеспечивает многоспектральную обработку изображений на периферии — в полевых условиях, на БПЛА и в удаленных установках. Chloros 1.2.0 определяет модель Jetson при запуске и оптимизирует стратегию обработки в соответствии с обнаруженным оборудованием. **Ручная настройка не требуется.**

***

## Поддерживаемые модели Jetson

| Модель                | ОЗУ            | Стратегия обработки                                     | Рекомендуемое применение                                          |
| -------------------- | -------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| **Jetson AGX Orin**  | 32–64 ГБ общей памяти | `GPU_PARALLEL` (2 рабочих процесса)                              | Максимальная производительность, большие наборы данных                      |
| **Jetson Orin NX**   | 8–16 ГБ общей памяти  | `GPU_PARALLEL` (2 рабочих процесса, 16 ГБ) / `GPU_SINGLE` (8 ГБ)   | Основная рекомендация для применения в воздушных и полевых условиях |
| **Jetson Orin Nano** | 8 ГБ общей памяти     | `GPU_SINGLE` (1 рабочий узел, последовательный режим)                     | Пограничные вычисления начального уровня                                 |

{% hint style="info" %}
Пакет Linux для архитектуры arm64 требует **JetPack 6**, который доступен на устройствах семейства Jetson Orin. Старые модели (Nano, TX2, Xavier NX) не могут работать с JetPack 6 и не поддерживаются текущим пакетом.
{% endhint %}

***

## Требования

* **JetPack 6.x** (рекомендуется последняя версия)
* **NVIDIA CUDA** (входит в состав JetPack)
* **Платный тарифный план Chloros+** — уровень «Copper» или выше (требуется для доступа ко всем CLI/SDK; проверка осуществляется на стороне сервера)

## Установка

```bash
# Install the JetPack 6 .deb package
sudo dpkg -i chloros_1.2.0_arm64_jp6.deb
sudo apt-get install -f

# Verify installation
chloros-cli --version    # prints "Chloros CLI 1.2.0"

# Install Python SDK (optional) — the bundled wheel always matches this build
pip install --user /usr/lib/chloros/sdk/chloros_sdk-*.whl

# Run system diagnostics
chloros-cli selftest
```

Общие сведения об установке Linux, расположении файлов и устранении неполадок см. в разделе [Установка Linux](linux-installation.md).

{% hint style="info" %}
**Разместите каталог для распаковки на быстром носителе.** Скомпилированные бинарные файлы при каждом запуске самостоятельно распаковываются во временный каталог — с SD-карты это происходит крайне медленно. Chloros автоматически использует `/mnt/ssd/tmp`, если он существует; в противном случае задайте для `TMPDIR` путь на вашем NVMe (`export TMPDIR=/mnt/nvme/tmp`).
{% endhint %}

## Динамическая адаптация вычислений на Jetson

### Принцип работы

При запуске Chloros выполняет профилирование вашей системы:

1. **Определяет модель Jetson** с помощью `/proc/device-tree/model`
2. **Считывает объем доступной общей памяти GPU/CPU** (Jetson использует унифицированную память)
3. **Выбирает стратегию обработки** (`GPU_PARALLEL`, `GPU_SINGLE` или `CPU_PARALLEL`)
4. **Автоматически устанавливает количество рабочих процессов, тип конвейера и распределение памяти**Решение зависит от**общего объема общей оперативной памяти**, а не от названия модели:

* **При общем объеме оперативной памяти менее 12 ГБ**(все модели Jetson с 8 ГБ): `GPU_SINGLE` с**1 рабочим процессом — целенаправленная последовательная обработка**. Объёма памяти недостаточно для одновременной работы нескольких рабочих процессов, поэтому изображения обрабатываются по одному. На устройствах Jetson с**8 ГБ или менее** поток 3 полностью обходит пул рабочих процессов и выполняет обработку каждого изображения в рамках одного процесса.
* **12 ГБ и более**(Orin NX 16 ГБ, AGX Orin): объединённая память соответствует требованиям `GPU_PARALLEL`, но количество рабочих процессов**ограничено двумя на Jetson** — графический процессор, оперативная память рабочих процессов и контексты CUDA для каждого рабочего процесса используют один и тот же общий пул, поэтому при увеличении количества рабочих процессов возрастает риск сбоев из-за нехватки памяти.

Вы можете переопределить автоматический выбор с помощью переменной среды `CHLOROS_STRATEGY` — см. [Динамическая адаптация вычислений](../processing-architecture/dynamic-compute-adaptation.md#manual-strategy-override).

### Поведение для каждой модели

| Модель Jetson                | Стратегия       | Рабочие процессы | Выполнение                                      |
| --------------------------- | -------------- | ------- | ---------------------------------------------- |
| **Jetson Orin Nano 8 ГБ**    | `GPU_SINGLE`   | 1       | Последовательный цикл внутри процесса (`tiled_gpu` при нехватке памяти) |
| **Jetson Orin NX 8 ГБ**      | `GPU_SINGLE`   | 1       | Последовательный цикл внутри процесса                     |
| **Jetson Orin NX 16 ГБ**     | `GPU_PARALLEL` | 2       | Параллельные рабочие процессы, путь `fused_gpu`  |
| **Jetson AGX Orin 32–64 ГБ** | `GPU_PARALLEL` | 2       | Параллельные рабочие процессы, путь `fused_gpu`  |

Ключевым отличием между платформами является **объём памяти**. Jetson с 8 ГБ памяти при высокой нагрузке вынужден обрабатывать изображения по одному, используя экономящий ресурсы подход с разбиением на фрагменты, в то время как Orin с 16 ГБ и более может одновременно обрабатывать 2 изображения на GPU с помощью конвергированного конвейера с более высокой пропускной способностью.

### Бюджет GPU для каждой модели

Каждая модель Jetson также имеет аппаратный профиль, который ограничивает объём ресурсов общего пула, запрашиваемых для обработки, и масштабирует размеры пакетов:

| Модель | Максимальный бюджет GPU | Коэффициент размера пакета | Зарезервировано для системы/дисплея |
| --- | --- | --- | --- |
| **Jetson Orin Nano** | 70 % | ×0,8 | 2,0 ГБ |
| **Jetson Orin NX** | 75 % | ×1,0 | 3,0 ГБ |
| **Jetson AGX Orin** | 80 % | ×1,5 | 4,0 ГБ |

Профиль корректируется в зависимости от обнаруженного объёма ОЗУ: для устройств Jetson, сообщающих о **16 ГБ или более**, множитель размера партии увеличивается на ×1,2. Базовый размер партии до применения множителей составляет 8 изображений.

Полную справку по адаптации вычислений см. в разделе [Динамическая адаптация вычислений](../processing-architecture/dynamic-compute-adaptation.md).

## Ограничение частоты GPU для Texture Aware на Nano и Orin Nano

Дебайер Texture Aware выполняет инференцию нейронной сети на GPU, что может вызывать **предупреждения о превышении тока**на моделях Jetson с низким энергопотреблением (класс 10–15 Вт) при полной тактовой частоте GPU. Перед обработкой с помощью Texture Aware на**Jetson Nano или Orin Nano**модуль Chloros проверяет максимальную частоту GPU и ограничивает её до**510 МГц** (510000000), если текущая частота выше:

* Если CLI может записывать в узел sysfs, отвечающий за частоту графического процессора, ограничение **применяется автоматически**, и на экран выводится подтверждение.
* Если нет (требуются права root), CLI выводит точную команду `sudo` для ручного установления ограничения, ждёт некоторое время, чтобы вы могли её прочитать, а затем продолжает работу — обработка всё ещё продолжается, но могут появляться предупреждения о превышении тока.

Чтобы самостоятельно установить ограничение перед обработкой:

```bash
echo 510000000 | sudo tee /sys/devices/platform/bus@0/17000000.gpu/devfreq/17000000.gpu/max_freq
```

Модели с более высокой мощностью (Orin NX 25 Вт, AGX Orin 60 Вт) работают на полной скорости графического процессора; ограничение не применяется. Стандартный дебейер никогда не запускает ограничение ни на одной модели.

{% hint style="info" %}
**Функция «Texture Aware» на Jetson всегда обрабатывает по одному изображению за раз.** Каждому рабочему процессу потребуется собственный контекст CUDA (~1 ГБ) плюс собственная копия модели шумоподавления, чего не позволяет объединённая память — поэтому на Jetson маршрут Texture Aware привязан к одному рабочему процессу с сериализованным доступом к графическому процессору. Ожидайте, что Texture Aware будет заметно медленнее, чем Standard, на любом устройстве Jetson.
{% endhint %}

## Управление температурой

Устройства Jetson имеют ограниченный температурный запас, особенно при размещении в закрытых помещениях или на борту летательных аппаратов. Chloros отслеживает температуру SoC и автоматически регулирует размер пакетов:

| Температура         | Действие                                            |
| ------------------- | ------------------------------------------------- |
| **&lt; 70 °C**          | Нормальный режим работы — полная скорость обработки          |
| **70 °C** (Предупреждение) | Размер пакета постепенно уменьшается (с 100 % до 50 % в диапазоне от 70 °C до 80 °C) |
| **80 °C** (Критический) | Агрессивное ограничение (с 50 % до 0 % в диапазоне от 80 °C до 90 °C) |
| **90 °C** (Отключение) | Полная остановка обработки на GPU — требуется охлаждение |

{% hint style="warning" %}
**Обеспечьте надлежащую вентиляцию и отвод тепла** для непрерывной работы, особенно в закрытых полевых корпусах или бортовых системах. Термическое ограничение производительности снизит пропускную способность для защиты аппаратного обеспечения.
{% endhint %}

## Управление памятью

Устройства Jetson используют **объединённую память** — графический процессор (GPU) и центральный процессор (CPU) совместно используют одну и ту же физическую оперативную память (RAM). Указанный объём VRAM (например, ~15,3 ГБ на Orin NX с 16 ГБ ОЗУ) не является выделенной памятью графического процессора; это та же оперативная память, которую используют операционная система и все остальные процессы.

### Предупреждение о подкачке и рекомендации

Перед началом обработки на Jetson программа CLI подсчитывает количество RAW-изображений в папке входных данных (`.tif`, `.tiff`, `.raw`, `.dng` — JPG-превью не учитываются), оценивает пиковый объем памяти, необходимый для выполнения задачи, и **выдает предупреждение перед запуском**, если оперативная память + своп, вероятно, будут недостаточными. Предупреждение имеет заголовок `LOW MEMORY WARNING - Jetson Detected`, в нём отображается количество изображений, объём ОЗУ, текущий размер свопа и расчётный пиковый объём, а затем выдаются точные команды `fallocate` / `chmod` / `mkswap` / `swapon`, размер которых рассчитан для вашего проекта (никогда не меньше 8 ГБ). Программа делает паузу на несколько секунд, чтобы сообщение не затерялось в прокрутке, после чего обработка продолжается.**Оценки объёма памяти, используемые в предупреждении:**

| Режим дебайеризации | Базовый | На одно изображение |
| --- | --- | --- |
| Стандартный | ~1,5 ГБ | ~10 МБ |
| С учётом текстур | ~2,5 ГБ (модель + среда выполнения Python) | ~15 МБ |

Предупреждение срабатывает, когда расчётный пиковый объём превышает объём ОЗУ + подкачки за вычетом запаса безопасности в 1 ГБ, при этом учитывается только подкачка **с файловой поддержкой** — конфигурация, использующая только zram, всё равно будет отмечена.

Чтобы добавить подкачку вручную (пример: 8 ГБ):



<!-- SCREENSHOT-NEEDED: Terminal on a Jetson Orin (SSH session) showing the full "LOW MEMORY WARNING - Jetson Detected" block printed by `chloros-cli process` on a large folder: the image count and debayer mode line, RAM / current swap / estimated peak figures, and the fallocate/chmod/mkswap/swapon command block it recommends -->

```bash
# Check current memory and swap
free -h

# Create a swap file
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make persistent across reboots
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```### Обработка OOM (Out of Memory)

Во время обработки Chloros отслеживает состояние памяти GPU и плавно снижает производительность вместо сбоя:

1. Когда загрузка памяти GPU превышает **85%**, размеры пакетов упреждающе уменьшаются
2. Если событие нехватки памяти всё же происходит, размер пакета **уменьшается вдвое**, и уменьшается ещё вдвое при каждом последующем OOM; каждый последующий успешно обработанный пакет сдвигает это ограничение на один шаг назад
3. При длительной нагрузке конвейер переключается с `fused_gpu` на более экономичный с точки зрения памяти маршрут `tiled_gpu`, а в крайнем случае — на обработку на ЦП

## Внедрение в реальных условиях

### Рекомендации по энергопотреблению

| Модель Jetson     | Типичное энергопотребление | Примечания                   |
| ---------------- | ------------------ | ----------------------- |
| Jetson Orin Nano | 7–15 Вт              | Разъем DC barrel          |
| Jetson Orin NX   | 10–25 Вт             | Разъем DC barrel          |
| Jetson AGX Orin  | 15–60 Вт             | USB-C PD или разъем DC barrel |

Рассчитайте бюджет энергопотребления для непрерывной обработки — пиковое энергопотребление наблюдается во время выполнения потока 3 (обработка), интенсивно использующего GPU.

### Рекомендации по хранению данных

* **SSD с интерфейсом NVMe** настоятельно рекомендуется для развертываний на архитектуре arm64
* SD-карты слишком медленны для обработки данных — используйте их только в качестве загрузочного носителя
* Запланируйте объем памяти, в 2–3 раза превышающий размер исходных изображений, для обработанных данных

### Работа без монитора с помощью SSH

Chloros и CLI идеально подходят для развертывания Jetson в режиме без монитора:

```bash
# SSH into the Jetson
ssh user@jetson-hostname

# Process a dataset
chloros-cli process /data/datasets/flight001 --format "TIFF (32-bit, Percent)"

# Monitor export progress
chloros-cli export-status
```

### Постоянно работающий бэкэнд для синхронизации времени LATTICE / DAQ-E

Если ваш Jetson управляет камерами LATTICE или датчиками освещенности DAQ-E в режиме без монитора, включите бэкенд-службу systemd, чтобы главный сервер PTP работал непрерывно (модуль установлен, но по умолчанию не включен):

```bash
sudo systemctl enable --now chloros-backend.service
chloros-cli time-sync status
```

См. [Linux Установка](linux-installation.md#always-on-ptp-for-headless-hosts) для получения подробной информации, в том числе о том, как пакет обеспечивает привязку портов PTP 319/320 без прав root.

### Автоматическая обработка с помощью systemd

Создайте службу systemd для автоматической обработки:

```ini
# /etc/systemd/system/chloros-process.service
[Unit]
Description=Chloros Automated Processing
After=network.target

[Service]
Type=oneshot
User=chloros
ExecStart=/usr/bin/chloros-cli process /data/incoming --output /data/processed
StandardOutput=append:/var/log/chloros-process.log
StandardError=append:/var/log/chloros-process.log

[Install]
WantedBy=multi-user.target
```

`chloros-cli process` завершает работу с ненулевым кодом, если запуск, запросивший продукты, не записывает изображения, поэтому статус сбоя systemd имеет значение для мониторинга.

Используйте в паре с таймером systemd для обработки по расписанию:

```ini
# /etc/systemd/system/chloros-process.timer
[Unit]
Description=Run Chloros Processing Every Hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable chloros-process.timer
sudo systemctl start chloros-process.timer
```

## Примеры рабочих процессов

### Базовая обработка на Jetson

```bash
#!/bin/bash
# Process a drone flight dataset on Jetson
chloros-cli process /data/flights/flight_042 \
    --output /data/processed/flight_042 \
    --format "TIFF (32-bit, Percent)" \
    --indices NDVI NDRE GNDVI
```

### Python и SDK на Jetson

```python
from chloros_sdk import ChlorosLocal

with ChlorosLocal() as chloros:
    chloros.create_project("field_survey_042")
    chloros.import_images("/data/flights/flight_042")
    chloros.configure(
        indices=["NDVI", "NDRE", "GNDVI"],
        export_format="TIFF (32-bit, Percent)",
        reflectance_calibration=True
    )
    chloros.process(mode="parallel")

print("Processing complete!")
```

### Пакетная обработка данных нескольких полётов

```bash
#!/bin/bash
# Process all flight datasets in a directory
for flight in /data/flights/*/; do
    name=$(basename "$flight")
    echo "Processing $name..."
    chloros-cli process "$flight" \
        --output "/data/processed/$name" \
        --format "TIFF (32-bit, Percent)" \
        --indices NDVI NDRE
    echo "Completed $name"
done
```

## Рекомендуемые системы Jetson для полевого использования

Для полевого и воздушного развертывания рассмотрите следующие варианты несущих плат Jetson Orin NX 16 ГБ:

* **Воздушное/дроновое применение**: Системы с защитой от вибрации (MIL-STD), легкие (менее 300 г), с пассивным охлаждением
* **Усиленные для полевых условий**: водонепроницаемые корпуса с защитой IP67/IP69K и подключением к камерам GigE по PoE
* **Минимальные/бюджетные**: наборы для разработчиков с дополнительными корпусами

Обратитесь в [службу поддержки MAPIR](https://www.mapir.camera/community/contact) для получения конкретных рекомендаций по аппаратному обеспечению для вашего сценария развертывания.
