# Руководство по NVIDIA Jetson Система

Chloros на NVIDIA Jetson обеспечивает обработку мультиспектральных изображений на периферии — в полевых условиях, на БПЛА и в удаленных установках. Chloros 1.3.0 определяет модель Jetson при запуске и оптимизирует стратегию обработки с учетом обнаруженного оборудования. **Ручная настройка не требуется.**
{% hint style="info" %}
**Пакет Jetson версии 1.3.0 выполняет обработку на графическом процессоре (GPU) Jetson.** `chloros_1.3.0_arm64_jp6.deb` скомпилирован для JetPack 6 и использует CUDA-версию PyTorch из JetPack 6, поэтому обработка, включая алгоритм дебайеризации с учетом текстур, выполняется на графическом процессоре Orin. Пакет не содержит сам CUDA: он использует библиотеки CUDA и cuDNN, устанавливаемые JetPack 6 (`sudo apt install nvidia-jetpack` на образе, в котором их нет). Если графический процессор с поддержкой CUDA недоступен, обработка выполняется на ЦП, а Texture Aware использует стандартный дебайер.
{% endhint %}

{% endhint %}

## Требования

* **JetPack 6.x** (рекомендуется последняя версия)
* **NVIDIA CUDA и cuDNN** из JetPack 6 (`sudo apt install nvidia-jetpack`, если в вашем образе их нет)
* **Платный тарифный план Chloros+** — уровень Copper или выше (требуется для доступа ко всем средствам CLI и SDK; проверка осуществляется на стороне сервера)

## Установка

```bash
# Install the arm64 .deb package (JetPack 6) -- apt, not dpkg -i, so the
# Python SDK's requirements (python3-numpy, python3-requests) come too
sudo apt install ./chloros_1.3.0_arm64_jp6.deb

# Verify installation
chloros-cli --version    # prints "Chloros CLI 1.3.0"
python3 -c "import chloros_sdk; print(chloros_sdk.__version__)"   # the .deb installs the SDK

# Run system diagnostics
chloros-cli selftest
```

`.deb` устанавливает SDK для Python системы `python3`, соответствующий данной сборке. Только в виртуальную среду (virtualenv) необходимо установить входящий в комплект файл wheel: `pip install /usr/lib/chloros/sdk/chloros_sdk-*.whl` (полностью автономно). Подробности об установке в Linux в целом, расположении файлов и устранении неполадок см. в разделе [Установка в Linux](linux-installation.md).

{% hint style="info" %}
**Больше не требуется распаковка при запуске.** Начиная с версии 1.3.0 бэкенд и интерфейс командной строки (CLI) устанавливаются в распакованном виде в каталог `/usr/lib/chloros/`, поэтому они больше не распаковываются во временный каталог при каждом запуске. Временные файлы по-прежнему автоматически сохраняются в папке `/mnt/ssd/tmp`, если она существует; в противном случае вы можете указать в `TMPDIR` путь на вашем NVMe (`export TMPDIR=/mnt/nvme/tmp`).
{% endhint %}

## Динамическая адаптация вычислительных ресурсов на Jetson

### Принцип работы

При запуске Chloros создаёт профиль вашей системы:

1. **Определяет модель Jetson** через `/proc/device-tree/model`
2. **Считывает доступную общую память GPU/CPU** (Jetson использует унифицированную память)
3. **Запрашивает у PyTorch, можно ли использовать CUDA** — при установленных CUDA и cuDNN из JetPack 6 это возможно
4. **Автоматически выбирает стратегию обработки** (`GPU_PARALLEL`, `GPU_SINGLE` или `CPU_PARALLEL`) и количество рабочих процессов

Решение зависит от **общего объёма общей оперативной памяти**, а не от названия модели:

* **При общем объёме оперативной памяти менее 12 ГБ**(все Jetson с 8 ГБ):**1 рабочий процесс — целенаправленная последовательная обработка**. Памяти недостаточно для одновременной работы нескольких рабочих процессов, поэтому изображения обрабатываются по одному. На устройствах Jetson с**8 ГБ или меньше** поток 3 полностью обходит пул рабочих процессов и выполняет обработку каждого изображения внутри процесса. В журнале бэкэнда эта стратегия обозначена как `GPU_SINGLE`.
* **12 ГБ и более**(Orin NX 16 ГБ, AGX Orin): унифицированная память соответствует условиям для `GPU_PARALLEL`, но количество рабочих процессов**ограничено двумя на Jetson** — графический процессор, оперативная память рабочих процессов и контексты CUDA для каждого рабочего процесса используют один и тот же общий пул, поэтому при большем количестве рабочих процессов возникает риск сбоев из-за нехватки памяти.
* **Отсутствие работоспособной CUDA** (отсутствуют библиотеки CUDA из JetPack): `CPU_PARALLEL` при объёме 12 ГБ и более, ниже — по одному образу за раз.

Вы можете переопределить автоматический выбор с помощью переменной среды `CHLOROS_STRATEGY` — см. [Динамическая адаптация вычислений](../processing-architecture/dynamic-compute-adaptation.md#manual-strategy-override).

### Поведение для отдельных моделей

| Модель Jetson                | Стратегия       | Рабочие процессы | Выполнение                                      |
| --------------------------- | -------------- | ------- | ---------------------------------------------- |
| **Jetson Orin Nano 8 ГБ**    | `GPU_SINGLE`   | 1       | Последовательный цикл внутри процесса (`tiled_gpu` при нехватке памяти) |
| **Jetson Orin NX 8 ГБ**      | `GPU_SINGLE`   | 1       | Последовательный цикл внутри процесса                     |
| **Jetson Orin NX 16 ГБ**     | `GPU_PARALLEL` | 2       | Параллельные рабочие процессы, путь `fused_gpu`  |
| **Jetson AGX Orin 32–64 ГБ** | `GPU_PARALLEL` | 2       | Параллельные рабочие процессы, путь `fused_gpu`  |

Ключевым отличием между платформами является **объём памяти**. Jetson с 8 ГБ памяти при высокой нагрузке должен обрабатывать изображения по одному, используя эффективный с точки зрения памяти подход с разбиением на фрагменты, в то время как Orin с 16 ГБ и более может одновременно обрабатывать 2 изображения на GPU с помощью конвергированного конвейера с более высокой пропускной способностью.

### Бюджет GPU для каждой модели

Каждая модель Jetson также имеет аппаратный профиль, который ограничивает объем памяти, который может задействовать обработка из общего пула, и масштабирует размеры пакетов:

| Модель | Максимальный бюджет GPU | Коэффициент размера пакета | Зарезервировано для системы/дисплея |
| --- | --- | --- | --- |
| **Jetson Orin Nano** | 70 % | ×0,8 | 2,0 ГБ |
| **Jetson Orin NX** | 75 % | ×1,0 | 3,0 ГБ |
| **Jetson AGX Orin** | 80 % | ×1,5 | 4,0 ГБ |

Профиль корректируется в зависимости от обнаруженного объёма ОЗУ: для устройств Jetson, сообщающих о **16 ГБ или более**, множитель размера пакета увеличивается на ×1,2. Базовый размер пакета до применения множителей составляет 8 изображений.

Полную справочную информацию по адаптации вычислений см. в разделе [Динамическая адаптация вычислений](../processing-architecture/dynamic-compute-adaptation.md).

## Ограничение частоты GPU для Texture Aware на Nano и Orin Nano

Дебайер Texture Aware выполняет инференцию нейронной сети на GPU, что может вызывать **предупреждения о превышении тока**на моделях Jetson с низким энергопотреблением (класс 10–15 Вт) при полной тактовой частоте GPU. При передаче `--debayer texture-aware` на**Jetson Nano или Orin Nano**, CLI проверяет максимальную частоту GPU и ограничивает её до **510 МГц** (510000000), если текущая частота выше:

* Если CLI может записывать в узел sysfs, отвечающий за частоту графического процессора, ограничение **применяется автоматически**, и на экране выводится подтверждение.
* Если нет (требуются права root), CLI выводит точную команду `sudo` для ручного применения ограничения, выжидает некоторое время, чтобы вы могли её прочитать, а затем продолжает работу — обработка всё ещё выполняется, но могут появляться предупреждения о превышении тока.

Чтобы самостоятельно установить ограничение перед обработкой:

```bash
echo 510000000 | sudo tee /sys/devices/platform/bus@0/17000000.gpu/devfreq/17000000.gpu/max_freq
```

Модели с более высокой мощностью (Orin NX 25 Вт, AGX Orin 60 Вт) работают на полной скорости графического процессора; ограничение не применяется. Стандартный дебайер никогда не запускает ограничение ни на одной модели.

{% hint style="info" %}
**Техника «Texture Aware» на Jetson всегда обрабатывает по одному изображению за раз.** Каждому рабочему процессу потребуется собственный контекст CUDA (~1 ГБ) плюс собственная копия модели шумоподавителя, чего не может обеспечить унифицированная память — поэтому на Jetson маршрут Texture Aware привязан к одному рабочему процессу с сериализованным доступом к графическому процессору. Ожидайте, что Texture Aware будет заметно медленнее, чем Standard, на любом Jetson. Техника «Texture Aware» применяется к изображениям Survey3: снимки LATTICE всегда обрабатываются с помощью стандартного дебайера. При отсутствии работоспособного CUDA-графического процессора выполняется стандартный режим, и бэкенд записывает в журнал одну строку `[DEBAYER] … needs a CUDA GPU …` с объяснением причины (показано с `chloros-cli --verbose`).
{% endhint %}

## Управление тепловым режимом

Устройства Jetson имеют ограниченный тепловой запас, особенно при размещении в закрытых помещениях или на борту летательных аппаратов. Программа Chloros отслеживает температуру SoC и автоматически регулирует размеры пакетов:

| Температура         | Действие                                            |
| ------------------- | ------------------------------------------------- |
| **< 70 °C**          | Нормальный режим работы — полная скорость обработки          |
| **70 °C** (Предупреждение) | Размер пакета постепенно уменьшается (с 100 % до 50 % в диапазоне от 70 °C до 80 °C) |
| **80 °C** (Критический) | Агрессивное ограничение производительности (с 50 % до 0 % в диапазоне от 80 °C до 90 °C) |
| **90 °C** (Отключение) | Полная остановка обработки на GPU — требуется охлаждение |

{% hint style="warning" %}
**Обеспечьте надлежащую вентиляцию и отвод тепла** для непрерывной работы, особенно в закрытых полевых корпусах или бортовых системах. Термическое ограничение производительности снизит пропускную способность для защиты оборудования.
{% endhint %}

## Управление памятью

Устройства Jetson используют **объединённую память** — графический процессор и центральный процессор используют одну и ту же физическую оперативную память. Указанный объём VRAM (например, ~15,3 ГБ на Orin NX с 16 ГБ ОЗУ) не является выделенной памятью графического процессора; это та же оперативная память, которую используют операционная система и все остальные процессы.

### Предупреждение о подкачке и рекомендации

Перед началом обработки на Jetson командная строка подсчитывает количество RAW-изображений в вашей входной папке (`.tif`, `.tiff`, `.raw`, `.dng` — JPG-превью не учитываются), оценивает пиковый объем памяти, необходимый для выполнения задачи, и **выдает предупреждение перед запуском**, если объем ОЗУ + своп, вероятно, будет недостаточным. Предупреждение имеет заголовок `LOW MEMORY WARNING - Jetson Detected`, в нём отображается количество ваших изображений, объём ОЗУ, текущий объём подкачки и расчётный пиковый объём, а затем выдает точные команды `fallocate` / `chmod` / `mkswap` / `swapon`, размер которых рассчитан для вашего проекта (никогда не меньше 8 ГБ). Программа делает паузу на несколько секунд, чтобы сообщение не затерялось в ленте прокрутки, после чего обработка продолжается.**Оценки объёма памяти, используемые в предупреждении:**

| Режим дебайеризации | Базовый | На одно изображение |
| --- | --- | --- |
| Стандартный | ~1,5 ГБ | ~10 МБ |
| С учётом текстур | ~2,5 ГБ (модель + среда выполнения Python) | ~15 МБ |

Предупреждение срабатывает, когда расчётный пиковый объём превышает объём ОЗУ + подкачки за вычетом запаса безопасности в 1 ГБ, причём учитывается только подкачка **с файловым резервом** — конфигурация, использующая только zram, всё равно будет отмечена.

Чтобы добавить подкачку вручную (пример: 8 ГБ):

```bash
# Check current memory and swap
free -h

# Create a swap file
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make persistent across reboots
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Обработка OOM (Out of Memory)

Во время обработки Chloros отслеживает состояние памяти GPU и плавно снижает производительность вместо того, чтобы вылетать:

1. Когда загрузка памяти GPU превышает **85%**, размеры пакетов превентивно уменьшаются
2. Если событие нехватки памяти всё же происходит, размер пакета **уменьшается вдвое**, и уменьшается ещё вдвое при каждом последующем случае OOM; каждый последующий успешно обработанный пакет отменяет это ограничение на один шаг
3. При длительной нагрузке конвейер переключается с маршрута `fused_gpu` на более экономичный по памяти маршрут `tiled_gpu`, а в крайнем случае — на обработку на ЦП

Поскольку графический процессор использует оперативную память Jetson совместно с ним, объем оперативной памяти плюс объем подкачки по-прежнему ограничивают время выполнения — приведенное выше предупреждение о подкачке является сигналом, на который следует обратить внимание.

## Развертывание в полевых условиях

### Соображения по энергопотреблению

| Модель Jetson     | Типичное энергопотребление | Примечания                   |
| ---------------- | ------------------ | ----------------------- |
| Jetson Orin Nano | 7–15 Вт              | Разъем DC barrel          |
| Jetson Orin NX   | 10–25 Вт             | Разъем DC barrel          |
| Jetson AGX Orin  | 15–60 Вт             | USB-C PD или разъем DC barrel |

Планируйте бюджет питания с учётом длительной обработки — пиковое энергопотребление наблюдается во время выполнения потока 3 (обработка), интенсивно использующего GPU.

### Рекомендации по хранению данных

* **SSD NVMe** настоятельно рекомендуется для развёрток на базе arm64
* SD-карты слишком медленны для обработки данных — используйте их только в качестве загрузочного носителя
* Рассчитывайте, что размер обработанных данных будет в 2–3 раза превышать размер исходных изображений

### Работа в режиме без монитора через SSH


Chloros — идеальное решение для развертывания Jetson в режиме без монитора:

```bash
# SSH into the Jetson
ssh user@jetson-hostname

# Process a dataset
chloros-cli process /data/datasets/flight001 --format "TIFF (32-bit, Percent)"

# Monitor export progress
chloros-cli export-status
```

### Постоянно работающий бэкэнд для синхронизации времени LATTICE / DAQ-E

Если ваш Jetson управляет камерами LATTICE или световыми датчиками DAQ-E в режиме без монитора, включите бэкенд-службу systemd **от имени вашего пользователя**, чтобы главный сервер PTP работал непрерывно, а скрипты SDK могли найти запущенный бэкенд (устройство установлено, но по умолчанию не включено):

```bash
sudo systemctl enable --now chloros-backend@$USER.service    # $USER expands to your user name
chloros-cli time-sync status
```

После этого бэкенд будет работать от вашего имени: записываемые им данные будут вашими, и он будет использовать ваш `chloros-cli login`. См. [Установка в Linux](linux-installation.md#always-on-ptp-for-headless-hosts) для получения подробной информации, включая файл root `chloros-backend.service` и описание того, как пакет обеспечивает возможность привязки портов PTP 319/320 без прав root.

### Автоматическая обработка с помощью systemd

Создайте службу systemd для автоматической обработки:

```ini
# /etc/systemd/system/chloros-process.service
[Unit]
Description=Chloros Automated Processing
After=network.target

[Service]
Type=oneshot
User=chloros
ExecStart=/usr/bin/chloros-cli process /data/incoming --output /data/processed
StandardOutput=append:/var/log/chloros-process.log
StandardError=append:/var/log/chloros-process.log

[Install]
WantedBy=multi-user.target
```

`chloros-cli process` завершает работу с ненулевым кодом, если запуск, запросивший продукты, не записывает никаких изображений, поэтому статус сбоя systemd имеет значение для мониторинга.

Используйте вместе с таймером systemd для запланированной обработки:

```ini
# /etc/systemd/system/chloros-process.timer
[Unit]
Description=Run Chloros Processing Every Hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable chloros-process.timer
sudo systemctl start chloros-process.timer
```

## Примеры рабочих процессов

### Базовая обработка на Jetson

```bash
#!/bin/bash
# Process a drone flight dataset on Jetson
chloros-cli process /data/flights/flight_042 \
    --output /data/processed/flight_042 \
    --format "TIFF (32-bit, Percent)" \
    --indices NDVI GNDVI OSAVI
```

### PythonSDK
для Jetson

```python
from chloros_sdk import ChlorosLocal

with ChlorosLocal() as chloros:
    chloros.create_project("field_survey_042")
    chloros.import_images("/data/flights/flight_042")
    chloros.configure(
        indices=["NDVI", "GNDVI", "OSAVI"],
        export_format="TIFF (32-bit, Percent)",
        reflectance_calibration=True
    )
    chloros.process(mode="parallel")

print("Processing complete!")
```

### Пакетная обработка данных нескольких полётов

```bash
#!/bin/bash
# Process all flight datasets in a directory
for flight in /data/flights/*/; do
    name=$(basename "$flight")
    echo "Processing $name..."
    chloros-cli process "$flight" \
        --output "/data/processed/$name" \
        --format "TIFF (32-bit, Percent)" \
        --indices NDVI OSAVI
    echo "Completed $name"
done
```

## Рекомендуемые системы Jetson для полевого использования

Для полевого и бортового применения рассмотрите следующие варианты несущих плат Jetson Orin NX 16 ГБ:

* **Бортовое/дронное применение**: системы с виброустойчивостью (MIL-STD), легкие (менее 300 г), с пассивным охлаждением
* **Условия полевой эксплуатации**: водонепроницаемые корпуса с защитой IP67/IP69K и подключением к камере GigE по PoE
* **Минимальная комплектация/экономный вариант**: наборы для разработчиков с дополнительными корпусами

Обратитесь в [службу поддержки MAPIR](https://www.mapir.camera/community/contact) для получения конкретных рекомендаций по аппаратному обеспечению для вашего сценария развертывания.
